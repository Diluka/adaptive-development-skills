# Adaptive Development Workflow：自适应开发工作流

<SUBAGENT-STOP>
如果你是为边界明确的工作单元派发的子代理，跳过任务级路由，只执行派发给你的单元和主要方法。任务级拆分、范围、授权、节点转换与交付由根代理负责；仅在委派说明明确授权时，才在原单元内继续拆分，并向协调者回报结果。
</SUBAGENT-STOP>

## 职责

本技能只决定任务与工作单元、级别、当前节点及转换边界。节点包括讨论 / 调查 / 设计 / 作业 / 验证 / 评审；详细进入与退出判据见 [resources/node-routing.md](resources/node-routing.md)，术语见 [resources/terminology.md](resources/terminology.md)。

当前节点确定后，由 [execution](../execution/SKILL.md) 选择并执行具体方法、证据和机制。独立标准方法被用户直接指定时，可由该方法先核验自己的适用条件。

## 识别与拆分

先确认用户要得到的结果，以及明确要求的过程或产物。讨论 / 调查 / 作业 / 验证只是可交叉的侧重点，不是必须依次执行的流程。

用户用“调查、求证、验证”等动作表达希望消除不确定性时，先盘点同一会话已有事实及适用条件。已有证据足以回答就直接给出结论、推导和边界；仍有会改变回答或决策的未知，或用户明确要求新的观测、重新运行、独立来源或调查记录时，再建立调查单元。

- **开发任务**：最终要保留、集成或交付代码、配置、依赖、测试、脚本、技能、工作流或版本控制文档。
- **非开发任务**：只交付解释、意见、事实、根因、可行性证据或决策输入，不产生 Git 交付。

按可独立描述的目标、交付物和证据边界拆分，而不是按文件或技术层拆分。调查单元只交付证据；决定保留临时产物或落实调查结论时，把正式变更作为开发单元重新路由。

## 按选定增量分级

只按用户已选择的交付内容分级，不把未要求的行为、候选方案或通用风险补进增量。

| 级别 | 当前增量 | 路由 |
|---|---|---|
| 微小 | 目标明确、局部可逆，不改变运行行为或公共契约，不涉及依赖、权限、生成规则或外部副作用 | 直接作业并做必要检查；不落盘计划或安排最终独立评审 |
| 常规 | 边界明确的行为或配置变化，可能包含若干相关步骤，影响可控且没有重大未知 | 直接作业或按实际协调需要设计；用受影响路径验证，具体未证风险需要独立视角时再评审 |
| 复杂或高风险 | 选定增量本身包含难回退或高影响操作、正式环境、安全 / 身份 / 资金 / 敏感数据、广泛不兼容契约迁移或显著未知 | 落盘计划，保留风险相称的验证、独立评审和恢复边界 |

从最低充分级别开始，选定增量的真实影响变化时再升降级。文件数、代理数、工作树和验证数量不是级别判据。

## 编排与转换

- 目标或关键选择不清楚时讨论；明确指令或已选方案跳过讨论，再按级别进入设计或作业。
- 取证本身成为独立目标时调查；当前动作需要的直接读取或检查留在原节点。
- 验证失败或评审发现范围内问题时，返回受影响节点。
- 新事实产生独立目标时拆成新单元；只改变当前实现动作、方法或证据时留在原节点。

需求、不变量、真实调用方与已核验契约优先于实现、测试、计划和方法偏好。满足用户已选结果的局部实现细节由 Execution 直接决定；若新事实会改变用户可见行为、公共契约、架构方向、风险、范围、授权、交付结果或外部副作用，返回本技能重新编排。

## 授权与交付

开发任务默认按仓库约定完成分支、提交、推送和 MR/PR；用户明确收窄时按其限制执行。创建 MR/PR 后报告链接和当前 CI 状态，并等待最终推送提交的自动任务进入终态。

合并、发布、部署、正式环境写入、权限修改、外部消息、流量调整和其他高影响外部操作需要明确授权。调查、开发和验证不得写入正式环境数据源，并保留用户与其他任务的改动。
