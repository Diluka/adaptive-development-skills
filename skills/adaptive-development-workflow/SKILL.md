# 从请求选择工作路径

<SUBAGENT-STOP>
委派单元的边界和主要方法明确时，按该方法执行并回报事实与实际差异。任务级范围、授权与交付由协调者持有；根入口供协调者选择整体工作路径。
</SUBAGENT-STOP>

用户的一句话表达目标。结合仓库现状、真实调用方、已确认规则和当前授权还原**想得到的结果**，再根据事实与缺口选择工作路径；方法按实际需要加载，正式文档按明确需求维护。

## 下一步做什么

| 会使下一步走错的缺口 | 当前行动 |
|---|---|
| 涉及用户决定且会改变行为或验收的业务取舍 | 围绕该决定澄清；已有权威来源时直接沿用 |
| 需要核验真实调用方、根因、外部契约或可行性事实 | 取能改变下一步选择的最小证据；证据足以回答或实施时停止调查 |
| 目标、约束、接缝和授权已足够 | 直接实施、检查或回答；在真实使用路径核对结果 |

同一措辞可有不同路径：“加订单号筛选”在接口与语义已知时直接实现，语义未知时确认会改变行为的那一项。“修复上传取消后提示成功”已有症状时，沿真实取消路径定位根因并据此选择修复方式。

调查与实施属于同一已授权请求时，事实确认后直接继续实现。新事实改变用户可见行为、公共契约、架构边界、范围、授权或副作用时，暂停受影响路径并确认关键取舍；用户纠正目标时，核查并修正或撤除依赖旧假设的实现、测试与文档。

## 按实际需要组织工作

按当前增量的影响、未知、副作用、可回退性和已有证据，分别决定计划、独立评审、隔离与追加验证。每项机制都针对一个具体缺口；可核实的未知先取最小证据。

验证从真实消费或激活路径取证，执行当前仓库的强制检查；复用仍适用的证据，足以支撑声明后停止追加。测试期望独立来自需求、调用方或契约，并与待写实现保持独立。

## 按需读取

- 需要展开需求取舍时，读取 [需求讨论与收敛](../requirements-discussion/SKILL.md)。
- 涉及外部契约、删除代码、正式环境数据或评审独立性时，按需读取 [代码与契约安全](../code-and-contract-safety/SKILL.md)。
- 需要委派或用工作树并行时，按需读取 [委派与隔离](../delegation-and-isolation/SKILL.md)。
- 交付遵循用户当前任务的明确要求；未指定部分按仓库约定和 [交付分支](../finishing-a-development-branch/SKILL.md) 的默认规则处理，并保留用户和其他任务的改动。
- 文档确为交付物时，读取 [文档](../documentation/SKILL.md)。
