# 工作节点路由

Use when 需要决定工作单元进入哪个节点、何时退出，以及结果应在原节点内反馈还是触发重新编排。

本资源只描述宏观节点路由，不选择具体方法、工具、证据层级或执行机制；进入节点后的“怎么做”见 [execution](../../execution/SKILL.md)。

## 讨论

- **进入**：目标或需求边界尚不足以编排，关键歧义会实质改变方案，或执行中出现无法自行解决的授权 / 取舍。
- **退出**：相关发散分支已逐一确认，或已有可在授权范围内默认推进的推荐；输出明确边界，必要时拆分工作单元。
- 明确指令或已有方案不安排讨论节点。

## 调查

- **进入前**：区分用户希望得到的结论与明确要求的新观测、过程或产物，盘点当前上下文（包括同一会话）中的已确认事实和仍适用证据。只有代理综合后仍存在会改变回答或决策的真实未知，才把“调查、求证”等动作词路由为调查；事实直接回答问题，或通过已确认不变量足以可靠推出答案时，直接报告结论、推导和适用边界。用户明确要求重新读取 / 运行、独立来源或调查记录时，该观测或产物本身是目标，按其实际性质路由。
- **进入**：当前系统、根因、外部契约、可行性、设计取舍或重要行为在盘点后仍未知，直接作业会依赖未经证明的假设。
- **退出**：已取得足以回答原问题或支持下一项决策的可追溯事实，并明确剩余未知。
- 调查只交付证据或决策输入；需要保留实现、长期测试、契约或文档时，建立开发单元重新路由。

## 设计

- **进入**：需要落盘计划以协调、恢复上下文或控制风险，需要需求、技术设计、规格、决策记录等正式依据支撑后续作业 / 验证 / 评审，或常规工作单元的实现会建立或改变稳定概念、职责所有权、生命周期、状态权威或运行接入契约，而相关架构决定尚未收敛。
- **退出**：目标、范围、约束、工作单元、依赖和验收边界已经足以开始下游作业，且影响实现结构的架构决定已有需求、真实调用方、已核验契约或调查证据支持。保持上述架构边界的局部实现细节可以留给作业节点。
- 微小任务不安排设计节点，在作业节点内处理当前增量需要的局部决定；常规任务在上述架构决定尚未收敛或设计有其他实际收益时安排；复杂或高风险任务保留落盘计划。

## 作业

- **进入**：目标、范围、授权和依赖前置条件足以执行；尚存未知已被隔离为调查或讨论单元。
- **退出**：当前工作单元的预期产物已形成，可观察结果已就绪，且直接影响的既有伴生产物已按授权边界同步。
- 新事实只改变动作或方法时留在本节点反馈；改变目标、范围、级别或授权时返回入口。

## 验证

- **进入**：存在待证明的结果、行为、不变量或交付声明，且已有可观察对象；验证能拒绝至少一种当前合理错误。
- **退出**：最低要求是用户或需求明确提及的 happy case 得到直接证据；核心、边界敏感或高影响风险按当前级别取得额外证据，必要缺口已明确。
- 证据失败时返回受影响节点；证据揭示新的独立目标或风险面时重新拆分与分级。

## 评审

- **进入**：当前级别要求独立评审，或独立视角能覆盖定向验证未覆盖的兼容性、范围偏离、高危操作或较大改动风险。
- **退出**：范围内发现已核验并处理，或有证据说明无需修改；实质修改只使受影响的验证和评审结论失效。
- 评审者必须独立于相关实现、证据设计和差异修改；没有独立收益的简单变更不安排评审节点。

## 完成与交付转换

即将从最后一个工作节点转向完成或交付时，保持 [verification-before-completion](../../verification-before-completion/SKILL.md) 独立：它把完成声明映射到最终增量上的最新直接证据，并核对适用评审状态。完成声明成立后才进入普通 Git 交付或用户明确要求的其他已授权交付。
