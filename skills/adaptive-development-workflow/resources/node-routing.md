# 工作节点路由

Use when 需要决定工作单元进入哪个节点、何时退出，以及结果应在原节点内反馈还是触发重新编排。

本资源只描述宏观节点路由，不选择具体方法、工具、证据层级或执行机制；进入节点后的“怎么做”见 [execution](../../execution/SKILL.md)。

## 讨论

- **进入**：目标或需求边界尚不足以编排，关键歧义会实质改变方案，或执行中出现无法自行解决的授权 / 取舍。
- **退出**：影响方案的关键决定已经完成选择，目标、成功标准、纳入范围和必要约束足以路由；输出选定内容与真正门控的未决项，必要时拆分工作单元。
- 发散、深入设计或考虑更多方案只增加候选与比较。候选说明保留在讨论或专门决策材料中；影响用户可见行为、公共契约、架构边界或风险的候选完成选择后，才进入选定设计、实施计划、任务、验收、测试和评审。
- 明确指令或已选方案直接按其边界路由。

## 调查

- **进入前**：区分用户希望得到的结论与明确要求的新观测、过程或产物，盘点当前上下文（包括同一会话）中的已确认事实和仍适用证据。只有代理综合后仍存在会改变回答或决策的真实未知，才把“调查、求证”等动作词路由为调查；事实直接回答问题，或通过已确认不变量足以可靠推出答案时，直接报告结论、推导和适用边界。用户明确要求重新读取 / 运行、独立来源或调查记录时，该观测或产物本身是目标，按其实际性质路由。
- **进入**：当前系统、根因、外部契约、可行性、设计取舍或重要行为在盘点后仍未知，需要把取证作为正式工作单元。与当前单元直接相关的自发轻量探测由 Execution 在当前节点内按累计五分钟证据预算处理。
- **退出**：已取得足以回答原问题或支持下一项决策的可追溯事实，并明确剩余未知。
- 调查只交付证据或决策输入；需要保留实现、长期测试、契约或文档时，建立开发单元重新路由。

## 设计

- **进入**：影响用户可见行为、公共契约、架构边界或风险的候选已经在讨论或专门决策材料中完成选择；用户或仓库要求正式依据，任务内容复杂或高风险，需要跨单元协调、跨会话恢复或高风险控制，或者选定方向仍需展开为稳定概念、职责所有权、生命周期、状态权威或运行接入契约。
- **退出**：目标、范围、约束、工作单元、依赖和验收边界已经足以开始下游作业；每项可实施逻辑都有有效来源，影响用户可见行为、公共契约、架构边界或风险的候选已经完成选择。调查证据形成候选或决策输入；通过 Execution 统一门禁的必要技术前置可以自行进入设计。保持既定边界的局部实现细节留给作业节点。
- **直接作业**：目标、范围和验收结果明确；所有设计逻辑来源有效；产品行为、公共契约和架构方向已经完成选择；依赖就绪、执行可逆；当前单元可在一个会话上下文内持续推进。满足时直接开工，多步骤最多维护简短执行清单。
- 用户或仓库明确要求、任务内容复杂或高风险、真实需要跨单元协调、跨会话恢复或高风险控制时落盘计划；复杂或高风险任务同时保留独立评审。代理数、会话数、工作树、计划篇幅、验证数量和协作方式不参与复杂度判定；仅为提速使用子代理时沿用当前单元的简短执行清单。

## 作业

- **进入**：目标、范围、授权和依赖前置条件足以执行；每项可实施逻辑都通过上述来源与选择门禁，正式未知已被隔离为调查或讨论单元。
- **退出**：当前工作单元的预期产物已形成，可观察结果已就绪，且直接影响的既有伴生产物已按授权边界同步。
- 新事实只改变已选方案内的动作或方法时留在本节点反馈；改变目标、范围、公共契约、架构边界、风险、级别或授权时返回入口。

## 验证

- **进入**：存在待证明的结果、行为、不变量或交付声明，且已有可观察对象；验证能拒绝至少一种当前合理错误。
- **退出**：真实消费或激活路径上的直接证据至少覆盖需求明确提及的正常场景，并完成适用于当前增量的仓库强制检查。追加手段各自覆盖一个尚未证明的具体风险；证据足以支持当前声明时停止。
- 证据失败时返回受影响节点；证据揭示新的独立目标或风险面时重新拆分与分级。

## 评审

- **进入**：当前级别要求独立评审，或独立视角能覆盖定向验证未覆盖的兼容性、范围偏离、高危操作或较大改动风险。
- **退出**：范围内发现已核验并处理，或有证据说明无需修改；实质修改只使受影响的验证和评审结论失效。
- 评审者必须独立于相关实现、证据设计和差异修改；没有独立收益的简单变更不安排评审节点。

## 完成与交付转换

即将从最后一个工作节点转向交付时，保持 [verification-before-completion](../../verification-before-completion/SKILL.md) 独立：它把实现就绪声明映射到最终增量上仍适用的直接证据，并核对适用评审状态。普通 Git 交付创建 MR/PR 后立即回报链接和当前 CI 状态，再等待最终推送提交的自动流水线稳定终态。这一终态证明流水线等待已经结束；必需自动任务均成功时才支持 CI 通过和交付就绪声明，失败或取消时只支撑对应流水线结果的报告。
