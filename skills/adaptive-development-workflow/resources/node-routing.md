# 工作节点路由

Use when 需要决定工作单元进入哪个节点、何时退出，以及结果应在原节点内反馈还是触发重新编排。

本资源只描述宏观路由；节点内的方法、证据和机制由 [execution](../../execution/SKILL.md) 选择。

## 讨论

- **进入**：目标、成功标准或会实质改变方案的关键选择尚不清楚。
- **退出**：用户已选择目标、纳入范围和必要约束；真正门控的未决项保持可见。
- 明确指令或已选方案跳过讨论，再按级别进入设计或作业，不为完整列举候选而停留。

## 调查

- **进入**：仍有会改变回答或决策的事实未知，且取证本身需要成为工作单元；用户明确要求的新观测、复现或调查记录也按实际目标进入。
- **退出**：已有证据足以回答原问题或支持下一项决定，并说明适用条件和剩余未知。
- 当前动作所需的直接读取或检查留在原节点。调查结论需要形成长期实现、测试、契约或文档时，建立开发单元重新路由。

## 设计

- **进入**：选定结果仍需要明确会影响实施或验收的职责、状态、生命周期、接口或运行接入方式，或者复杂 / 高风险增量需要稳定的共享依据。
- **退出**：目标、范围、必要约束、依赖和验收边界足以作业，且影响行为、公共契约或架构方向的选择已经完成。
- **直接作业**：用户结果、范围和验收已明确，依赖就绪，剩余选择只是局部实现细节。
- 落盘计划只服务用户 / 仓库要求、跨单元协调、跨会话恢复或高风险控制。

## 作业

- **进入**：目标、范围、授权和依赖足以执行。
- **退出**：选定产物和可观察结果已经形成。
- 新事实只改变当前动作或方法时留在本节点；改变选定结果、公共契约、架构方向、风险、范围或授权时返回入口。

## 验证

- **进入**：存在待证明的结果或声明，且已有可观察对象。
- **退出**：真实消费或激活路径覆盖需求明确提及的场景，并完成仓库对当前增量要求的检查。
- 证据失败时返回受影响节点；新事实形成独立目标时重新拆分。

## 评审

- **进入**：复杂或高风险增量要求独立评审，或已识别的具体风险无法由定向验证覆盖。
- **退出**：范围内发现已核验并处理，或有证据说明无需修改。
- 评审者独立于相关实现、证据设计和差异修改；简单变更不为形式安排评审。

## 完成与交付

最后一个工作节点结束时，用 [verification-before-completion](../../verification-before-completion/SKILL.md) 核对最终增量、直接证据和适用评审。普通 Git 交付创建 MR/PR 后报告链接和当前 CI 状态，并等待最终推送提交的自动任务进入终态。
