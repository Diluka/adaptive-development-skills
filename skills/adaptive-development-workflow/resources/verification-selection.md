# 验证方式选择

Use when
处于验证节点，需要为工作单元选择验证手段：是否验证、选哪类手段、如何组合互补。

## 是否验证

按任务形状、真实调用方、风险和证据缺口，以最少能拒绝合理错误的验证决定是否验证及其手段，不按习惯或仪式。

## 手段三大类（按证据产生方式）

### 动态执行（运行产生行为证据）

- **自动化** / **手动**（手工测试）/ **调试**。
- 可再按观察视角分：
  - **黑盒**：只管外部行为（如 curl 接口）；e2e 可自动可手动。
  - **白盒**：验证内部环节（单元测试、打断点调试）。

### 静态检查（工具静态验证，不运行行为）

- build（编译）、lint、format、类型检查。
- 类型驱动设计下，build 即可验证类型系统；类型能排除的稳定不变量不另测。

### 审视核对（看，不执行）

- 直接看内容核对是否符合预期，用于文字类产物（文档、文案）。

## 手动测试的适用性看项目

- 复杂耦合高、外部引用多的项目，某些路径无法自动验证，需手动回归，甚至比自动更有效、更常见。

## 手段互补而非互斥

- 主手段覆盖不全处，用辅助手段补证据；组合证据才完整。
- 只新增判据独立且能拒绝合理错误的验证；强度以此为下限，已有证据覆盖同一风险不重复。
- 结合现有代码、真实接缝和运行成本决定具体手段；能复用真实入口就优先复用，不为人工测试增加生产开关、包装层或公共接口。

## 边界

- 本资源只负责选择验证方式；专项方法（属性 / 契约 /
  基线等）与实现方式选择见入口正文「选择开发方式」。
- 证据充分性、复用与长期收敛由
  [evidence-management](../../evidence-management/SKILL.md) 负责。
