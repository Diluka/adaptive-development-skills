# 流程级别：把当前增量归入可比较的级别

Use when 需要决定本增量要不要计划、独立评审、隔离工作树、MR/PR 与 CI 等待；级别确定后按对应行的机制集合执行，不再逐项重新论证。

本资源是全部流程机制的**唯一级别定义**。其他技能只引用级别名，不各自重述判据；改判据只改本文件。

## 判据

按当前**增量**（不是父任务、不是 PR/MR 整体）核对三项可观察事实，取最高级别：

| 判据 | 观察方式 |
|---|---|
| 不可逆 | 失败后无法用一次 `git revert`、分支重置或丢弃未提交改动复原；含正式环境或外部系统的写入、数据迁移、已发布制品 |
| 跨边界 | 改动的符号或数据被本增量之外的东西使用：改动落在对外导出、公开 API 清单、其他包或其他仓库引用的符号上，或触碰鉴权与权限、数据模型、依赖解析、并发与共享运行资源。**动手前无法核实是否存在外部调用方时，按成立处理** |
| 有未证风险 | 改动意图为“修好某个已观察的错误”，但根因未定位；或所用外部 SDK／协议／CLI 的实际安装版本行为未核验；或新行为没有可核对的权威来源（需求、调用方或既有规则），当前只能靠推断 |

三项全不成立即为 **L0**；只有第三项成立为 **L1**；第二项成立（无论第三项）为 **L2**；第一项成立为 **L3**。

预期读者是代理，判据写成可核对的观察，不写成“风险高／低”“规模大／小”。不确定时**按更高级别执行**——升级只增加少量成本，降级可能造成不可逆后果。

## 各级机制

| | L0 局部改动 | L1 待定根因或未核契约 | L2 跨边界 | L3 不可逆 |
|---|---|---|---|---|
| 计划 | 不写 | 不写，回复中列清单 | 跨单元或跨会话时写 | 写 |
| 隔离工作树 | 就地修改 | 就地修改 | 有并发写入者时创建 | 创建 |
| 独立评审 | 不启动 | 不启动 | 启动 | 启动 |
| MR/PR | 不创建 | 不创建 | 创建 | 创建 |
| 等待 CI | 不等 | 不等 | 等待 | 等待 |
| 验证 | 真实路径核对预期结果 + 仓库强制检查 | 同上，另加能拒绝该根因假设的观测 | 加公共契约与调用方证据 | 加回退路径与基线对照 |

L0 与 L1 只做本地提交并报告差异，是否推送由用户决定；需要跨人评审、跨环境部署或用户与仓库明确要求时才升到 L2 的交付动作。

## 升级与降级

调查中发现新事实时重判级别并**只补该级别新增的机制**，不从头重跑：

- 定位到根因且修复局限在已核范围 → L1 降为 L0，取消仅为根因假设保留的观测。
- 发现需触碰公共契约或数据模型 → 升为 L2，补评审与调用方证据。
- 发现写入正式环境或无法回退 → 升为 L3，并先取得用户授权。

级别只决定机制集合，**不扩大授权**。合并、发布、部署、正式环境写入、权限变更、外部消息与破坏性操作始终需要用户明确要求，不因级别为 L2／L3 而获得授权。

## 为什么固定级别

同一句需求在不同会话走不同流程时，既无法比较效果，也无法判断技能改动是否有效。固定级别让每类增量落到同一行机制，于是“是否按级别执行”成为可核对的合规指标。

合规指标不等于质量指标：级别能衡量有没有按流程走，不能衡量需求理解、契约核验与根因定位是否正确。后者需要代表任务与预先确定的评价标准单独评估。
