# 讨论节点决策规则

Use when
需求边界模糊、目的不明，或作业中遇到无法自行解决的突发情况，需要先与用户澄清、明确界限再继续。明确指令
/ 已有方案时不需要本节。

## 何时需要讨论

- **边界模糊**：需求边界都定不下来，先通过讨论明确功能界限 / 开发界限。
- **目的不明**：作为工作流起点，把还不能直接编排为流程的任务逐渐清晰、变得可编排。
- **突发插入**：作业中遇无法自行解决的突发情况，随时插入讨论（建模为子流程）。
- **明确指令 / 已有方案**：不需要讨论，直接进入设计 / 作业等对应节点。

## 怎么做

- 以头脑风暴为主展开，需要适当思维发散才能发现问题、明确需求。
- 先**发散**（提可能性、边界问题）→ 再**收敛**（明确界限、达成一致）。
- 发散有边界：只澄清会实质改变方案的关键歧义，不做无关扩展。

## 产出

- 明确功能界限 / 开发界限。
- 可能**分裂任务**：一个变多个，各自重新编排。
- 澄清关键歧义后可直接进入设计 / 实现。

方法见 [brainstorming](../../../brainstorming/SKILL.md)。
