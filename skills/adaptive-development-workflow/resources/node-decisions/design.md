# 设计节点决策规则

Use when 判断是否需要写文档、写什么类型文档，以及临时 / 正式产物放哪里。

## 时机判据 = 复杂度 + 用途

- **新业务 / 复杂**：需要设计文档——为后续验证 / 评审提供评判标准。
- **简单变更**：不写，简单验证即可保证效果，写设计是形式主义。

## 文档类型判定

| 文档类型                | 作用                                             | 何时写                           |
| ----------------------- | ------------------------------------------------ | -------------------------------- |
| **需求**                | 自然语言描述需求，偏沟通                         | 需记录 / 沟通需求时              |
| **计划 / 任务**         | 任务的执行计划（步骤、单元、顺序、验证）         | 需协调 / 恢复上下文 / 跟踪执行时 |
| **技术设计**            | 怎么实现（架构、模块、接口、数据模型）           | 实现复杂、需方案依据时           |
| **规格**                | 有明确结构的正式技术文档（项目附件，可对外交付） | 需结构化规格、正式 / 对外交付时  |
| **决策记录 / 正式文档** | 长期保存需求、设计、决策                         | 需版本控制长期保存时             |
| **交付 / 对外文档**     | 面向使用者：README、API 文档、用户指南、发布说明 | 需对外交付、用户可读时           |

- **需求 vs
  规格**：需求是自然语言描述（自由、沟通用）；规格是有明确结构的正式技术文档（可作项目附件，可对外交付）。
- 计划 / 任务就是任务的执行计划文档（一类）。
- 正式文档内部可再分：**对内**（决策 / 记录）与**对外**（交付文档、规格）。

## 临时 vs 正式、位置规则

- 临时产物放被忽略的 `.docs/`（计划在 `.docs/plans/`）；正式文档放 `docs/`。
- 文档写作与管理规则见 [documentation](../../../documentation/SKILL.md)。
