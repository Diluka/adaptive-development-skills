# 调查节点决策规则

Use when
需要研究学习、消除对当前系统、第三方契约、根因、可行性或未知行为的确定性，选择对应调查方式。

## 按问题类型选方式

| 调查问题                                           | 调查方式                                                                     |
| -------------------------------------------------- | ---------------------------------------------------------------------------- |
| 系统结构、运行路径、历史演进、架构未知             | [system-understanding](../../../system-understanding/SKILL.md)（系统理解）   |
| 第三方 SDK / 框架 / 协议 / HTTP API / CLI 契约未知 | [contract-verification](../../../contract-verification/SKILL.md)（契约核验） |
| 已有症状、因果链未知                               | [systematic-debugging](../../../systematic-debugging/SKILL.md)（系统化调试） |
| 可行性 / 依赖行为 / 性能 / 集成形态未知            | [unknown-exploration](../../../unknown-exploration/SKILL.md)（未知探索）     |

## 边界

- 调查只交付事实、根因、可行性证据或决策输入；正式变更须回到入口重新路由为开发单元。
- 探索发现稳定症状后，结束探索单元，再以系统化调试追因。
- 方式库持续积累：会陆续收录标准与实战总结的调查经验。
