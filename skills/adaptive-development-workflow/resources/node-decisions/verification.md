# 验证节点决策规则

Use when 检查某项事情是否符合预期，判断是否验证、选哪类验证手段。

## 定位

- 验证 =
  检查某项事情是否符合预期；验证手段**不限于自动化测试**，自动化测试只是其中一种手段。
- 验证 =
  有既定对照的核对（实现是否符合设计）；与评审（无固定对照的整体审视）区分。

## 手段三大类（按证据产生方式）

- **动态执行**（运行产生行为证据）：自动化 / 手动 /
  调试；可再按观察视角分**黑盒**（只管外部行为）与**白盒**（验证内部环节）。
- **静态检查**（工具静态验证，不运行行为）：build（编译）、lint、format、类型检查。
- **审视核对**（看，不执行）：直接看内容核对是否符合预期，用于文字类产物（文档、文案）。

## 是否验证 + 选哪类手段

- 是否验证：按任务形状、真实调用方、风险和证据缺口，以最少能拒绝合理错误的验证决定，不按习惯或仪式。
- 手段互补而非互斥：主手段覆盖不全处用辅助手段补证据，组合证据才完整。
- 详细判据见 [../verification-selection.md](../verification-selection.md)。

## 完成判据

- 至少需求提及的 happy case 通过即算通过；核心组件 / 边界敏感处可进一步验证。
- 即将声明完成时，用
  [verification-before-completion](../../../verification-before-completion/SKILL.md)
  核对证据。
