# 理解现有系统

## 目标

从一个具体问题出发，还原当前系统实际如何工作，交付足以支持下一项决定的事实模型。本技能不设计目标方案，也不把调查结论直接变成项目差异。

## 选择切片

| 问题 | 输出 |
|---|---|
| 仓库由什么组成、入口在哪里 | 与问题有关的模块、公共入口、装配和外部边界 |
| 某项功能如何运行 | 从真实入口到状态变化与可观察结果的纵向路径 |
| 当前状态由谁持有 | 创建、读取、修改和释放该状态的现有边界 |
| 当前行为为何如此或何时改变 | 能说明现状的关键提交、版本差异和有证据的原因 |

只研究会改变当前回答或实现选择的切片；已有事实足够时停止。

## 追踪步骤

1. 确认待回答的问题、目标分支或提交、适用配置和已知约束。
2. 从真实入口或调用方沿控制流与数据流追踪到相关状态和可观察结果。
3. 核对模块注册、依赖注入、路由、插件、生成代码、配置或约定式加载中实际决定可达性的部分。
4. 记录现有状态由谁创建、持有、修改和释放，以及当前生命周期边界。
5. 用反向调用方、代表性测试、运行产物或最小只读观测交叉核对主路径。

动态分派、反射、代码生成和部署配置可能让静态搜索漏掉调用方；只有当前问题涉及这些机制时才展开。外部契约或运行行为仍未知时，报告精确缺口，不在本技能内扩展为依赖研究或可行性实验。

## 历史

需要解释演进时，以当前可达实现为起点，使用 `git log`、`git log -S` / `-G`、`git blame` 和 `git show` 定位能说明行为、契约或所有权变化的提交。提交内容证明“改了什么”；原因只引用提交信息、关联决策或问题记录，缺少来源时标为未知。

## 结论

报告：

- 当前入口、调用路径、状态所有者和可观察结果；
- 直接支持这些事实的文件、符号、版本、测试或运行证据；
- 与当前决定有关的约束和仍未确认的事实。

事实模型形成后即结束调查。方案选择、实现、验证、评审和文档维护由对应工作单元处理。
