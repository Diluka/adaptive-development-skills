# 理解与审查现有系统

## 核心原则

从具体问题出发，建立能追溯到当前源码、装配、版本、真实调用方与运行证据的系统模型。先还原系统实际如何运作，再提出或评价目标设计；目录、惯例、偏好和抽象程度都不能代替事实。本技能只交付事实模型和决策输入，不直接把结论变成项目差异。

## 追踪当前系统

从公共导出、HTTP 或消息入口、CLI、启动流程、计划任务和后台消费者中找到真实入口，沿数据流和控制流追踪到编排、领域规则、持久化与外部边界；优先使用仓库已有语义索引或调用图，再用源码搜索补足动态路径。动态分派、反射、代码生成、约定式加载和部署配置都可能让静态调用图不完整，静态不可见不等于不可达。

需要运行时证据时，优先用最小、可逆的只读观测来源交叉核验主路径：只读日志、APM 跟踪、指标、只读数据库快照、已部署镜像和下游响应；观测不写入、修改或迁移正式环境数据源。正式环境和远程环境只做必要的只读观测，保护敏感值。

测试断言是理解当前契约与意图的入口：它们说明现有调用方如何使用系统、系统承诺什么行为。遗留行为难以从静态代码判读时，可用特征测试基线记录当前实际行为作为对照。

## 建模架构

只为影响当前决定的部分建模：稳定概念、职责与所有权、生命周期、状态边界、不变量和数据流。用模型比较备选方案，检查是否减少重复状态、隐式时序、双重所有权和穿透抽象；不要为层数、模式或统一命名而建模。

## 检查适用风险

先从真实调用、部署和状态模型判断风险是否存在，再检查对应设计。技术上可能失败本身不构成新增机制的需求；不要无条件套用分布式系统清单。重试、补偿、恢复或中间恢复状态只在已确认的闭环成立时检查：异常后仍存活并持有相关状态的主体、实际触发恢复的主体或事件、表示恢复完成的可观察结果。任一项未被需求、真实调用方或已核验运行边界确认时，只描述已确认的失败传播或生命周期终止边界，不增加恢复机制、状态或验收项。

## 研究历史演进

以当前可达实现为基线，用 `git log`、`git log -S` 或 `-G`、`git blame`、`git show`、标签、发布说明和迁移记录定位关键变化；遇到移动或重命名时跟随文件历史，只选择能说明行为、契约、所有权或数据模型变化的提交。提交内容可以证明“改了什么”；只有提交信息、关联决策或问题记录才可能解释“为什么”。原因没有直接证据时标为综合或未知。

## 形成结论

交付能直接支持决策的结论：推荐方案及其对应的事实、约束和关键不变量；主要取舍；被否决的真实备选方案及原因；对调用方、公开契约、数据、部署、运维和后续实现的实际影响；仍未确认的假设与获得下一份证据的最小动作。按证据强度标记结论：已确认事实、证据支持的综合、假设、门控行为和缺失实现，分别给出精确来源、推导关系、缺口或排查范围。

## 边界与衔接

- 关键业务选择、成功标准或互斥设计方向未定时，把会改变方案的未决项返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 处理。
- 不强制特定命名、设计模式、新抽象或通用化；当前设计不需要它们时保持简单。
- 默认只交付研究或审查结论，不自动创建设计文档或实施代码；需要长期保留时返回 Workflow 建立开发单元，再由 Execution 选择文档或实施方法。
- 本技能以理解与决策输入为目的；删除、升级等正式维护变更只复用本技能交付的调用方证据，具体开发方法由 Execution 选择。
- 任务包含正式实施时，形成足以支撑决定的结论后停止，把结论返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 建立并分级开发单元，再由 [execution](../execution/SKILL.md) 选择开发方式；本技能不继续实施，也不代替最终差异适用的 [requesting-code-review](../requesting-code-review/SKILL.md)。
