# 系统理解：还原会改变决定的事实

从用户当前问题出发找真实可达路径，不凭目录结构、惯例或测试名称推断运行行为。沿公共导出、启动、HTTP、消息、计划任务或后台消费入口追到关键状态与外部边界；语义索引和调用图帮助定位，动态导入、反射、代码生成、框架注册和部署配置仍需源码与运行证据补足。静态搜索不可见不等于没有调用方。

借鉴参考实现时，核对其输入输出、层次、顺序和错误语义，区分可复用行为与当前系统必需的适配。只为影响当前决定的职责、生命周期、状态边界和不变量建模；需要运行时事实时，用最小、只读的日志、指标、部署产物或下游响应交叉核对，保护敏感值和正式环境数据。

技术上可能失败本身不构成增加重试或恢复状态的需求。考虑恢复闭环时，先核实异常后仍存活并持有状态的主体、实际恢复触发者，以及表示恢复完成的可观察结果；任一项缺失就只描述已确认的失败传播边界。

研究历史时用当前可达实现作基线。提交内容可证明“改了什么”，原因需提交说明、关联决策或问题记录支持；缺直接依据时把原因标为推断或未知，不把时间顺序当因果。

输出足以让当前任务继续的事实、来源、适用版本与未决关键边界。只求事实的请求至此停止；同一已授权请求还要求实现时，将事实交给当前实施路径直接使用，不自动追加正式规格或重复批准。新事实若改变产品行为、契约、授权或副作用，再返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 重新选择。
