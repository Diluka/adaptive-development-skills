# 渐进式交付（Progressive Delivery）

Use when 候选版本已达到可发布状态，需要通过受控暴露和真实观测决定扩大、保持、暂停或回退。

候选版本已经具备开发期证据并达到可发布状态后，可以通过金丝雀、功能开关、流量分割、地域或用户群分批等机制控制暴露范围，再根据真实观测逐步扩大、保持、暂停或回退。观测与决策闭环是本方法核心；只有分批动作而没有判断标准，不构成渐进式交付。

## 适用前提

- 候选制品已通过与功能风险相称的开发期验证并达到可发布状态；
- 存在能够精确控制用户、请求、地域、实例或功能暴露的机制；
- 能观察用户体验、业务结果与系统健康，并有可信基线；
- 继续、暂停、终止和回退条件可在执行前定义。

缺少可观察信号、无法限制暴露范围或没有可执行回退时，先补齐能力或改用更保守的发布安排，不把直接全量发布称为渐进式交付。

## 交付循环

1. 固定候选制品、剩余风险假设、目标人群和当前环境，明确本轮最大允许爆炸半径。
2. 按入口的「交付节奏决策」选择满足风险控制所需的最小暴露机制，并落实开关 / 金丝雀的职责要求。
3. 在执行前定义阶段、群体或比例、观察窗口、基线、成功指标、护栏指标以及扩大、保持、停止和回退阈值。
4. 核对精确环境、当前状态、操作权限和恢复步骤。没有明确授权时，只完成方案和只读核验，不修改正式环境。
5. 对首个受控群体暴露，读取完整观察窗口中的实际信号；证据不足时保持当前阶段，不按预定时间自动扩大。
6. 根据阈值扩大、暂停或回退，并为每次决策记录制品、暴露范围、时间和证据。
7. 达到目标后确认最终暴露状态。临时开关、路由和旧版本清理由独立工作单元处理，继续遵守调用方证明与授权边界。

## 方法特有证据

- 精确制品与暴露范围；
- 每阶段基线与观测结果；
- 每次扩大、暂停或回退的阈值判断与负责人；
- 回退或禁用后的恢复结果，以及最终暴露状态。

## 停止与交接

缺少可信信号或达到停止阈值时保持、暂停或回退，不按预定时间自动扩大。候选制品达到目标暴露状态后，本方法完成；临时开关、路由和旧版本的清理由独立工作单元处理。正式环境改动、发布和回退始终遵守入口的授权边界。
