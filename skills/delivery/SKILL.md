# Delivery：集成、交付与受控发布

## 核心原则

交付通常由三段能力衔接：

| 能力 | 作用 |
|---|---|
| 主干开发 | 把工作拆成可独立集成的小批次，并频繁合入 |
| 持续交付 | 让各种变更在整个生命周期保持可发布 |
| 渐进式交付 | 对已验证候选版本受控暴露，并以真实观测决定扩大或回退 |

三段能力是同一交付生命周期的衔接阶段，各自闭环、可以独立建立，但都不能替代功能、契约或质量证据。

## 选择方法资源

先确定当前缺少的交付能力，只读取对应方法资源；几个能力同时成立但产物或反证边界独立时，按依赖顺序分别推进，不把三个完整循环混成一次操作。

| 当前目标 | 读取资源 |
|---|---|
| 将变化切成可独立集成的小批次，并保持主干健康 | [Trunk-Based Development](resources/trunk-based-development.md) |
| 让已集成变化持续保持可发布，并建立可追溯制品与环境提升能力 | [Continuous Delivery](resources/continuous-delivery.md) |
| 候选版本已可发布，需要按真实观测控制正式环境暴露 | [Progressive Delivery](resources/progressive-delivery.md) |

需要按顺序建立完整交付能力时，通常先主干集成，再持续交付，最后才对已验证候选版本采用渐进式交付；每一步仍由当前目标和前提决定，不把顺序当成无条件门禁。

## 交付节奏决策

三段能力共享同一组节奏决策，先在此定下，各方法段只讲做法、不重复维护：

- **发布方式选择**：发布节奏高、可自动化且风险受控时，从主干直接发布；节奏低、需人工把关或加固时，为发布切分支，验证加固后发布，完成即删除该分支，不在主干上长期保留发布分支。
- **暴露机制选择**：按风险与暴露粒度选择满足风险控制所需的最小机制——金丝雀（流量渐进）、蓝绿（整体切换、快速回退）、功能开关（功能级暴露、与发布节奏解耦）、直接全量（低风险）。低风险变更直接全量，不套用更重机制。
- **共享决策**：制品身份（候选制品稳定身份、跨环境提升不重建）、授权边界（发布 / 回退 / 正式环境改动有明确负责人与授权，未授权只停在“可发布”或只读核验）、观测回退（有健康与业务信号、可信基线和可执行回退路径）、开关 / 金丝雀职责（所有者、默认行为、依赖与清理条件）。

## 共享记录

除各方法资源要求的特有证据外，保留本次发布方式、暴露机制及其理由，候选制品与来源提交、跨环境提升身份，授权负责人，以及健康 / 业务基线和可执行回退路径。没有实际发布或正式环境授权时，准确记录停在“可发布”或只读核验的位置。

## 方法边界

- 本技能决定集成、交付与受控暴露方法内部的节奏，不决定功能工作单元的主要开发或证据方法；后者由 [execution](../execution/SKILL.md) 为各工作单元选择。
- 本技能管交付节奏决策；分支、提交、推送、MR/PR 及其自动流水线终态等待由 [finishing-a-development-branch](../finishing-a-development-branch/SKILL.md) 按普通 Git 交付默认值处理。观察并等待流水线自动 review 环境任务属于该交接流程；合并、制品发布、主动环境变更和正式环境部署属于单独授权范围。主干健康检查是节奏层检查，不重复该技能的就绪核对。
- 功能开关、金丝雀和 A/B 分流是可选机制，不是独立正确性证据，也不应为了人工测试改变产品设计。
- 不可逆数据迁移、公共契约破坏或无法按群体隔离的共享副作用不能仅靠缩小流量解决；先建立兼容迁移、状态边界与恢复方案。
- 完成声明通过 [verification-before-completion](../verification-before-completion/SKILL.md) 核对当前制品、观测、决策与最终状态，不能用开发环境或过时指标代替。
