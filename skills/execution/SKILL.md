# Execution：在工作节点上执行工作单元

## 核心原则

执行面向工作单元要达成的结果，不逐字服从已经过时的文字。计划（有的话）是可修正的工作假设和多代理共享状态；当前需求、调用方、契约和新证据优先。没有落盘计划不阻塞执行——有计划时引用计划执行，无计划时直接执行。

## 执行循环

每个工作单元在执行环节遵循同一循环：**明确要做的动作 → 执行 → 核对结果 → 反馈 / 同步 / 继续**。它适用于各工作节点的执行动作——作业节点的实现、验证节点的验证动作、评审节点的评审动作等。

1. **明确要做的动作**：完整阅读计划（有计划时）、仓库说明、工作树状态和已有进展，确认目标、范围、工作单元、主要方法、验证，以及独立评审是否适用和对应依据，并核对原任务整体授权。没有落盘计划时不以此为前置：先通过 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 判断是否需要计划，只有满足落盘条件时才使用 [documentation](../documentation/SKILL.md)，不要为微小任务补造计划。计划不产生独立于原请求的批准状态。原任务授权尚未取得，或 [documentation](../documentation/SKILL.md) 判断仍有未解决取舍、越界方案或高风险操作需要确认时，停止受影响执行；执行中新出现的逐路径确认事项只暂停受影响路径，不阻断其他已授权工作。
2. **执行**：执行下一个依赖就绪的工作单元。每个单元开始前，以最小成本确认相关文件、真实调用方、依赖契约、前置状态和授权边界仍成立。首次准备修改计划未列出的路径时，先按 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 判断它是否为本次变更直接影响的既有伴生产物；不是时，再确认保持它不变是否会阻止当前任务正确实现、验证或交付。主要问题变化时，通过 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 重新选法。
3. **核对结果并同步**：验证单元结果；有计划时同步计划。正式实现完成后，按 [documentation](../documentation/SKILL.md) 的授权边界最小同步本次变更直接影响的既有伴生产物，再验证组合结果和真实运行链路。
4. **反馈 / 继续**：执行动作的结果决定下一步——需要评审时，根代理按 [requesting-code-review](../requesting-code-review/SKILL.md) 派发、按 [receiving-code-review](../receiving-code-review/SKILL.md) 核验；实质修复只重验和复审受影响范围。用 [verification-before-completion](../verification-before-completion/SKILL.md) 核对实现、验证和适用评审证据，再报告未完成和未执行事项。

## 根据新事实修正

计划外发现先按 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 的任务范围规则分类。本次变更直接影响的既有伴生产物作为收尾同步写回计划，不归为阻塞项或任务外发现；需要新授权时保留在计划内并只暂停该同步路径。

不影响当前任务的其他问题只报告，不超出分类所需的最小证据继续调查或修改。不能因为某个问题与当前代码有关联、容易修复或已有测试，就把它加入计划。

确认问题会阻塞当前任务时，按 [documentation](../documentation/SKILL.md) 的阻塞前置条件规则发出非阻塞询问，说明默认方案，并继续不依赖它的工作。用户未及时回复且满足默认纳入条件时，更新计划并处理最小前置内容；需要明确确认时只暂停受影响路径。

其他证据与计划冲突时，停止受影响路径，并按 [documentation](../documentation/SKILL.md) 的边界更新计划：原目标、范围、业务行为、交付结果和授权不变且无新增副作用时，告知用户后继续；否则暂停并请求确认。

用户明确收窄或排除某个工作单元时，立即停止该路径，并从交付差异中移除本任务为它产生的改动。已经投入的时间、已有实现或通过的测试都不是保留理由。只移除自己为本任务产生的内容，保留用户和其他工作的改动。

协调者或单代理维护计划、关键证据、偏差和风险，其他人只回报；短局部委派走 [agent-and-parallel-dispatch](../agent-and-parallel-dispatch/SKILL.md)，持续写入、独立上下文/工作树/生命周期的单元走 [using-git-worktrees](../using-git-worktrees/SKILL.md) 并另配上下文，均不得并发改计划。

## 边界

- 计划不改变任务类型对应的交付结果：开发任务按普通 Git 交付默认值或用户限制完成分支、提交、推送和 MR/PR，非开发任务不自动产生 Git 交付。合并、发布、部署、外部消息、破坏性清理和正式环境数据写入仍遵守各自的明确要求边界。
- 保留用户的无关改动；编辑重叠文件前重新读取当前内容。
- 只读 lint/format 可按仓库覆盖必要范围；自动修复仅改本任务行，不能行级时依次扩大至最小语法单元或受影响文件，审阅并移除无关且非项目契约所需的差异，不借机批量修存量。
- 不因后续步骤依赖错误假设而继续执行冲突路径。
- 计划不为形式强制实现子代理或独立评审；为项目改动创建或检出开发分支且无另行安排时，按 [using-git-worktrees](../using-git-worktrees/SKILL.md) 绑定独立工作树。纯只读审查按同一技能判断是否可用根路径。
