# Execution：选择并执行具体做法

## 职责边界

[adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 决定任务是什么、有哪些工作单元、当前处于哪个节点以及何时转换；本技能是唯一的微观执行决策层，决定当前单元**具体怎么做**并落实执行。

执行面向工作单元要达成的结果，不逐字服从已经过时的计划。需求、不变量、真实调用方、契约和新证据优先；计划（有的话）是可修正的工作依据和共享状态。没有落盘计划不阻塞执行，有计划时引用计划，无计划时直接执行。

**快速路径**：用户已经直接指定标准方法，且不存在跨方法、证据组合或执行机制选择时，可直接加载该方法并由其核验前提，不必先读取本技能的选法资源。方法不适用，或执行中需要重选方法、证据或机制时，再返回本技能。

## 按需读取资源

只读取当前决策需要的资源，避免一次加载全部方法经验：

| 当前问题 | 资源 |
|---|---|
| 调查、开发、文档、评审、交付或执行机制怎么选 | [resources/method-selection.md](resources/method-selection.md) |
| 进入验证节点后，选什么验证手段或专项测试方法 | [resources/verification-selection.md](resources/verification-selection.md) |
| 证据是否充分、能否复用、何时失效、如何收敛 | [resources/evidence.md](resources/evidence.md) |

标准方法经本技能选中后，读取对应技能并忠实执行其核心循环。没有专项方法能增加独立反馈或证据收益时，直接实现、直接检查或直接操作是一等选择。

## 执行循环

每个工作单元遵循同一循环：**明确边界与缺口 → 选择具体做法 → 执行 → 核对结果 → 反馈、重选或转换**。

1. **明确边界与缺口**：读取仓库说明、相关计划、当前工作树和已有进展，确认工作单元、当前节点、级别、目标、权威判据、范围、授权、依赖前置和待拒绝的合理错误。计划不产生独立于原请求的批准状态。
2. **选择具体做法**：按当前主要不确定性或风险选择一个主要方法；再选择能独立拒绝合理错误的最小充分验证和必要机制。多个目标具有独立产物或反证边界时，返回工作流拆成有依赖的单元，不把多套主要方法混成一个流程。
3. **执行**：执行下一个依赖就绪的动作。使用标准方法时保留其核心闭环；直接执行时仍以真实调用方、契约和项目约定为边界。首次准备修改计划未列出的路径时，先判断它是否是本次变更直接影响的既有伴生产物；不是时，再判断保持它不变是否会阻止当前任务正确实现、验证或交付。
4. **核对结果并同步**：用所选证据核对动作结果；有计划时同步状态、关键证据和偏差。正式实现完成后，按授权边界最小同步本次变更直接影响的既有伴生产物，再核对组合结果和真实运行链路。
5. **反馈、重选或转换**：结果只改变当前动作、方法或证据组合时，在原节点内修正后继续；改变工作单元、级别、节点、范围、授权、交付结果或副作用时，返回工作流重新编排。即将声称完成时使用独立的 [verification-before-completion](../verification-before-completion/SKILL.md) 核对最终声明，而不是由本技能自我替代。

## 计划、范围与新事实

原任务授权尚未取得，或仍有会改变方案的关键歧义、越界方案、高风险 / 难回退操作时，只暂停受影响路径；其他已授权且不依赖它的工作可继续。新事实不改变目标、范围、行为、交付、授权或副作用时，更新适用计划并告知后继续；否则暂停受影响路径并请求确认。

确认某项计划外问题会阻止当前任务时，按 [documentation](../documentation/SKILL.md) 的阻塞前置条件规则说明证据、默认方案和影响，并继续不依赖它的工作。允许默认纳入且无需新授权时，等待窗口后更新计划并处理最小前置；需要明确确认时只暂停受影响路径。

不影响当前任务的问题只收集足以判断边界的最小证据并报告，不写入计划或顺手修改。

用户明确收窄或排除某个单元时，立即停止该路径，并从交付差异中移除本任务为它产生的改动。已经投入的时间、已有实现或通过的测试都不是保留理由；只移除本任务产生的内容，保留用户和其他工作的改动。

协调者或单代理维护唯一计划、关键证据、偏差和风险，其他参与者只回报。具体是否委派、并行或使用工作树按 `resources/method-selection.md` 选择；评审者保持独立，不并发修改计划。

## 执行边界

- 选择方法、工具或交付机制不扩大原任务授权；合并、发布、部署、外部消息、流量调整、破坏性清理和正式环境写入仍需对应明确授权。
- 保留用户与其他任务的改动；编辑重叠文件前重新读取当前内容。
- 只读 lint / format 可覆盖必要范围；自动修复只改本任务行，不能行级时扩大到最小语法单元或受影响文件，并移除无关差异。
- 不因后续步骤依赖错误假设而继续冲突路径，不为测试增加真实调用方不需要的生产开关、包装、回退、分支或公共接口。
- 为项目改动创建或检出开发分支且无另行安排时，使用 [using-git-worktrees](../using-git-worktrees/SKILL.md) 判断并落实隔离；纯只读工作按同一技能判断是否可留在稳定基线。
