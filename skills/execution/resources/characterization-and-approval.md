# Characterization / Golden Master / Approval

Use when 需要从真实执行记录可稳定重放的现有或复杂行为，并用可审阅基线发现行为保持型变更造成的漂移。

Characterization 描述系统当前实际行为，Golden Master 保存代表性结果，Approval Testing 负责比较、审阅和显式批准；三者都不能把观察到的现状自动宣称为正确需求。

## 开始前确认

- 能从真实入口执行代表性场景，并观察输出、状态或副作用。
- 结果能够稳定复现，或能在不改变业务语义的前提下清除无关噪声。
- 基线范围和差异足够清晰，评审者能够判断变化是否可接受。
- 敏感数据可使用非敏感代表值或安全脱敏，批准产物适合长期维护。

## 核心循环

1. **选择特征范围**：根据真实调用方、失败影响和准备修改的路径选择少量代表性场景，记录入口、环境、输入和观察结果。行为保持型工作在修改前运行当前版本；未知行为标记为“已观察”。
2. **捕获真实结果**：通过真实执行路径生成 received 结果。Golden Master 必须从执行生成，不能手写目标内容或从待实现设计复制预期结果冒充基线。
3. **稳定基线**：重复运行确认稳定。只清洗时间、随机标识、临时路径、无关顺序和敏感值等非业务差异，并保留清洗规则；清洗会掩盖待保护行为时改用更窄观察面或明确断言。
4. **审阅并批准**：比较 received 与 approved。首次建立旧行为基线时审阅实际结果并显式批准；新复杂输出先生成结果，再依据需求判断完整性。第一次缺少 approved 只说明基线尚未建立，不能证明业务缺陷。
5. **修改后比较**：在相同环境、输入和入口重跑。非预期差异返回实现定位；预期差异依据需求、真实调用方或已确认决策解释后再显式更新。不得批量接受新基线来消除失败。
6. **收敛长期保护**：随着行为被理解，把宽泛基线收窄为有业务意义的区域，必要时转为明确语义断言。保留仍能发现合理漂移的最小基线，删除噪声或已被更清晰证据完整替代的批准产物。

## 不适用

- 结果无法稳定复现，也没有安全的噪声隔离方式。
- 差异过大、不可读，或没有具备上下文的评审者。
- 目标是主观质量、概率性效果或多种合理答案；本方法不适用，返回 [baseline-and-evaluation.md](baseline-and-evaluation.md) 重选。
- 简单确定性规则已有独立判据；本方法不适用，返回 [verification-selection.md](verification-selection.md) 选择更直接证据。
- 目标是尚不存在且没有可批准输出的新行为；先从需求或规格建立目标。

## 产出与边界

记录场景、环境和输入，机器生成的 received 与 approved 或等价基线，稳定化规则、可审阅差异、修改后比较结论和每次更新依据。

基线只证明当前行为可在既定条件下复现，不自动证明它满足正确产品需求。被 Execution 选为行为保持型维护证据时，在修改前建立相称基线；证据保留、失效和收敛见 [evidence.md](evidence.md)。正式环境观测不授权数据写入或未明确要求的发布操作。
