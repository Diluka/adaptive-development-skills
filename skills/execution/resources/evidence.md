# 证据充分性、复用与收敛

Use when 需要判断工作单元的证据是否充分、复用既有测试与观测、处理测试与需求冲突、证明行为保持，或收敛最小充分长期证据组合。

本资源不是独立方法或必经门。它把结论映射到最小反证，复用仍适用的证据、只补缺口，并收敛值得长期保留的测试与观测；具体验证手段由 [verification-selection.md](verification-selection.md) 选择。

## 明确待证明结论

对每项结论说明：

- 必需结果或不变量及其权威来源；
- 真实调用方、输入结构、环境和相关依赖契约；
- 当前变化可能引入的具体错误；
- 哪个观察会推翻“实现正确、行为保持或可交付”的判断。

证据冲突时，按需求和不变量 > 真实调用方与运行行为 > 依赖和协议契约 > 实现与测试判断。测试基于不存在的调用方、错误契约或内部细节时修正或删除测试；实现违反更高优先级事实时修正实现。

## 从需求派生并记录证据

从权威需求或约束映射真实调用方可观察的结果、边界和失败风险。实现步骤只帮助找接缝，不能定义必证行为；同一风险已有需求级证据时，除非低层有独立规则、失效面或定位价值，不再追加。

对每项证据做轻量记录：声明、证据、来源、适用输入 / 环境 / 版本 / 路径、失效条件、未覆盖风险和复用 / 保留判定。记录足以定位与复核即可，不追求固定格式。

## 判断独立性与静态证据

新增测试须来自需求、真实调用方或契约，保留真实接缝、能拒绝合理错误且覆盖值得保护的风险。从待写字面量或当前实现复制的断言不独立，除非精确内容本身是外部契约；没有新增反证或定位价值时不追加。

严格配置和真实使用位置已证明的约束不重复测；记录工具链版本、配置、命令和范围。公共或复杂类型 API 有兼容风险时才保留少量 intended-valid / intended-invalid 编译用例。静态检查是证据，不是开发方式；稳定非法状态可由当前类型系统排除时，在开发单元内按 [type-driven-design.md](type-driven-design.md) 建模。外部输入仍需运行时解析。

常见风险不必另造方法：分支同步或机械冲突未改变运行语义时，审阅冲突与最终差异、确认没有冲突标记，并查看最终集成结果的 CI；风险只在一个真实环境或完整装配边界出现时，使用可重复的集成、端到端或冒烟观测。

## 复用、失效与再验证

输入、状态与时效、环境、版本、依赖、契约、实现路径和风险面未变时复用既有证据。发生变化后判断它是否触及结论依赖的边界，只使受影响结论失效并补对应缺口，未失效部分继续复用。已确认不变量足以覆盖变化维度时，可由既有事实可靠推出答案，不为表面场景差异补镜像实验。最终推送或合并结果的 CI 是组合证据；本地检查只为更早发现风险、补 CI 缺口或建立必要基线。

追加证据前，明确新观测可能推翻的结论或改变的决策，以及它补哪个适用条件缺口。不存在这种可能结果时，证据已经收敛，直接报告结论和适用边界；用户本人尚不确定不会使仍适用的证据失效。用户明确把当前读回、重新运行、独立来源或调查记录作为结果时，按该交付目标取得并报告，不把它包装成原结论仍未知。

再验证的最终声明核对由 [verification-before-completion](../../verification-before-completion/SKILL.md) 独立完成。

## 行为保持型工作

涉及业务逻辑、状态变化、公共契约或框架边界的行为保持型变更，改动前必须有能发现核心漂移的证据：列出必须保持的核心行为、真实入口和失败影响；确认既有测试或观测经过受影响路径并观察真实结果；修改前后用相同入口、环境和输入对照。只有能由已确认需求解释的差异可接受，其余差异表示行为保持尚未证明。

旧实现上的通过基线只证明当前行为能在既定条件下复现；构建、类型检查、无关测试、模拟调用次数和代码审查可以补充，但不能单独证明核心业务行为保持。无法建立测试或可比较观测时，缩小单元、先建立真实接缝或暂停对应变更。

普通行为保持维护的最小步骤见 [maintenance-operations](../../maintenance-operations/SKILL.md)；复杂输出需要可审阅基线时见 [baseline-and-evaluation.md](baseline-and-evaluation.md)。

## 选择证据层级

通常从能保留待验证行为的最低真实接缝取证；较低层会抹掉目标行为时才向上移动。不同层级覆盖不同失效面时可以并存，不能用大量低层测试冒充真实框架、传输、持久化或部署边界。

独立验证明确从顶层开始时，先从受影响真实调用方中找能覆盖目标风险的最高入口，在该入口定义可观察结果，再按失败定位补低层证据。这里的顶层是与声明相称的公共或装配边界，不自动等于跨越全部服务、数据库和外部依赖的完整 E2E 环境。

## 保持接缝真实

只替换时钟、网络、进程、随机性或不可用服务等真实边界；保留业务不变量及被验证的框架、解析、序列化和持久化真实。不得 mock 被测单元、增设生产测试钩子或以协作者次数代替可观察结果，除非该次数本身是外部副作用契约。

## 收敛最终证据组合

把新增和受影响的长期证据映射到稳定需求 / 不变量、调用方、回归风险和失败信号。保留核心契约、历史缺陷、边界或副作用保护；合并无新输入、边界或定位价值的同层重复；删除只锁定淘汰实现或无业务意义内部细节的测试。暂定 rubric、一次性探索记录和本地随机缓存不构成确定性契约；删除后重验组合。

成本高不等于可删关键保护。必要时只在隔离、可恢复环境中做临时故障注入或变异测试，不留生产钩子。

## 报告边界

报告命令或观测、输入环境、结果、直接结论和未覆盖风险。格式 / 引用检查和单次代理模拟只证明结构或样例，不外推为真实运行或普遍效果。
