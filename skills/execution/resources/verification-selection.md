# 验证方式选择

Use when 已进入验证节点，需要为当前工作单元选择验证手段或专项测试方法，并形成最小充分组合。

## 从声明和反证开始

Workflow 已决定验证节点存在及其转换边界。本资源先写清待证明声明、权威来源、真实调用方与风险边界，再问：哪个观察能够推翻“它正确、保持行为或可交付”？只选择能拒绝当前合理错误的证据。

## 三类验证手段

### 动态执行

- 自动化测试、脚本化手工测试、可重复冒烟、调试和测量。
- **黑盒**从真实调用方或公共边界观察结果；**白盒**观察内部环节。E2E 可自动也可手动，不因名称天然更充分。

### 静态检查

- build / 编译、类型检查、lint、format 和其他静态分析。
- 记录真实工具链版本、配置、命令和范围。类型系统已证明的稳定约束不再用运行时测试重复，但静态检查不能证明副作用、算法、传输、持久化、并发、时间、性能或概率质量。

### 审视核对

- 直接对照需求、规格、设计或既有事实审阅文档、文案、配置、差异和其他无需运行的产物。
- 审视可以验证确定内容，也可以参与 Approval 或人工评价；独立代码评审是另一个有独立角色要求的节点，不能用作者自查冒充。

## 按风险选择层级

| 主要风险边界 | 首选证据 |
|---|---|
| 简单确定性规则 | 最低真实接缝上的示例或参数化测试 |
| 广泛输入空间、状态机或转换不变量 | [property-based-testing](../../property-based-testing/SKILL.md) |
| 框架绑定、序列化、装饰器或中间件 | 真实框架模块或窄集成测试 |
| 通过约定、注册、扫描、反射、生成描述或运行环境间接激活 | 真实激活入口，或保留相同选择、解释和执行机制的最窄集成路径 |
| 事务或持久化映射 | 可丢弃的本地 / 测试存储集成 |
| 独立演进的服务协议兼容 | [consumer-driven-contract-testing](../../consumer-driven-contract-testing/SKILL.md)，再按业务风险补功能或集成证据 |
| 实际 SDK、框架、协议或 CLI 契约事实 | [contract-verification](../../contract-verification/SKILL.md) 的确切版本和安全探测 |
| 稳定但逐项断言成本高的旧 / 复杂输出 | [baseline-and-evaluation.md](baseline-and-evaluation.md) 中的 Characterization / Golden Master / Approval |
| 主观、多解或概率性能力 | [baseline-and-evaluation.md](baseline-and-evaluation.md) 中的 Eval-Driven Development 与重复试验 |
| 完整且接近真实使用的调用链 | 窄范围端到端或可重复冒烟 |
| 文字、说明或纯结构产物 | 审视核对；格式、链接或解析检查只补结构证据 |
| 正式发布后的剩余风险 | 只读运行观测；受控暴露节奏另由 [delivery](../../delivery/SKILL.md) 执行且不扩大授权 |

通常从能保留待验证行为的最低真实接缝开始；较低层会抹掉目标风险时才上移。明确要求自顶层独立验证时，从与当前声明相称的最高真实调用方入口开始，再按失败定位补低层证据，不自动搭建跨越所有服务和外部依赖的完整环境。

间接激活产物的选择、解释和执行路径共同构成激活契约。验证覆盖产物如何进入真实执行链；产物内容、局部调用、编译和格式分别保留为局部证据。既有 CI 实际经过相同激活路径时才覆盖该契约。

## 组合与强度

- 主手段覆盖不全处用辅助手段补证据；不同手段只有覆盖不同失效面时才并存。
- 复用输入、环境、版本、路径和风险仍相同的既有测试、观测、评审或 CI，只补受当前增量影响的缺口；详细失效与收敛规则见 [evidence.md](evidence.md)。
- 复杂耦合、外部依赖或人工判断占主导时，脚本化手工回归可能比新增脆弱自动化更直接；记录步骤、环境和结果，使其可重复审阅。
- 行为保持型变更在修改前先确认有效基线；复杂可复现输出与概率性结果分别使用不同方法，不因都需要“比较基线”而混为一种测试法。

## 防止无效验证

- 断言必须独立来自需求、真实调用方、稳定不变量或外部契约；从待写字面量、当前实现或同一配置复制的镜像断言没有独立证据价值。
- 不为测试增加真实调用方不需要的生产开关、包装层、回退、分支或公共接口；替身只隔离时钟、网络、进程、随机性等真实外部边界。
- 构建通过、mock 调用次数、无关测试和格式检查只能证明各自范围，不能冒充业务行为、框架装配、传输或正式运行证据。
- 测试与更高优先级需求、真实调用方或契约冲突时修正测试或实现，不削弱真实不变量只求绿灯。

完成手段选择后，用 [evidence.md](evidence.md) 判断组合是否充分；即将声称完成时再由 [verification-before-completion](../../verification-before-completion/SKILL.md) 在最终增量上核对声明与证据。
