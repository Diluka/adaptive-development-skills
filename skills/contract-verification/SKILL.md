# 验证既有契约

## 核心原则

以实际版本、调用方和输入输出核验运行边界。版本未知先确认；类型、示例、模拟和可信内部类型都不能证明外部契约。本技能只交付事实，不定义新契约或实施正式变更。

## 记录最小证据

| 字段 | 证据 |
|---|---|
| 使用方 | 当前生产调用位置和输入结构 |
| 提供方 | 包、服务、CLI 或框架名称 |
| 版本 | 锁文件声明版本与实际安装/部署版本分开记录 |
| 探测环境 | OS、运行时、部署目标；结论只覆盖该环境，跨环境需重测 |
| 契约 | 类型，以及运行时源码、帮助信息或传输行为 |
| 失败 | 精确错误、响应、序列化结果或状态转换 |
| 安全探测 | 本地夹具、沙箱、只读请求或可丢弃环境 |

本地类型、生成声明和领域模型只表达当前代码期望，不能证明外部 JSON、HTTP、数据库、CLI 或第三方运行时；[type-driven-design](../type-driven-design/SKILL.md) 的可信表示进入前仍须核验边界。

## 核验既有边界

从真实入口追到边界，依次核对锁定/解析版本、该版本源码/类型/生成物或 `COMMAND --help`，再做最小安全探测。锁文件声明版本与实际安装版本分开记录，不一致时以实际安装/部署版本为准，并报告差异来源（手动安装、间接依赖、平台差异等）；文档与项目版本冲突时同样以实际安装或部署产物为准。

服务于 [unknown-exploration](../unknown-exploration/SKILL.md) 时，把版本和探测证据返回探索，不擅自进入正式实现。没有外部或框架边界时，结束本调查单元并返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 重新分类。

## 契约版本迁移影响

对比目标版本与当前版本的契约差异（发布说明、changelog、类型或传输变化、破坏性变更），把迁移影响面作为可交付事实之一。本技能只交付迁移影响事实，不实施升级；升级执行归 [maintenance-operations](../maintenance-operations/SKILL.md)。

## 方法边界与衔接

本技能回答既有边界当前是什么。双方共同控制消费者与提供者，且目标是新增或演进消费者期望、契约产物、提供者验证和兼容部署决定时，使用 [consumer-driven-contract-testing](../consumer-driven-contract-testing/SKILL.md)。不要用当前行为探测代替持续契约开发。

需要把已核实契约转为正式实现、长期回归测试或契约产物时，停止调查。把确切版本、调用链、观察结果和未决边界返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md)，重新选择开发方式和证据支持；本技能不修改实现或新增正式测试。

## 安全边界

- 正式环境仅在授权下只读；脱敏捕获结果并区分访问限制与提供方失败；无调用方和契约证据不增兼容分支。

完成时报告确切版本、调用链、观察到的契约、探测结果和仍未验证的边界。
