# Contract Verification：契约验证

## 核心原则

验证真正运行的边界：确切版本、真实调用方、实际输入与可观察输出。类型、示例和模拟对象在已安装或远端契约确认前都只是线索。

## 建立契约记录卡

修改适配器前记录：

| 字段 | 证据 |
|---|---|
| 使用方 | 当前生产调用位置与输入结构 |
| 提供方 | 包、服务、CLI 或框架名称 |
| 版本 | 锁文件、已安装元数据、二进制版本或已部署镜像 |
| 契约 | 类型，加运行时源码、帮助信息或传输行为 |
| 失败 | 精确错误、响应、序列化结果或状态转换 |
| 安全探测 | 本地测试夹具、沙箱、只读请求或可丢弃环境 |

提供方版本未知时先解决版本事实，不要猜。

## 验证顺序

1. 从真实入口追踪到边界。
2. 读取项目锁定版本与实际解析的依赖树。
3. 查看该版本的已安装源码、导出类型、生成客户端或 `COMMAND --help`。
4. 用最小安全探测捕获 HTTP 交互、CLI 输出、集成冒烟测试或框架启动行为。
5. 仅当任务包含生产实现时，把稳定行为编入契约测试或集成测试。
6. 仅当实现已获授权且仍在范围内时，最小修改生产代码并重跑同一探测。

官方文档用于解释行为；若文档与项目版本冲突，以已安装产物为准。

本技能若服务于 [technical-spike](../technical-spike/SKILL.md)，在版本检查与安全探测后停止，把证据返回技术探索；除非生产实现另行进入范围，不得继续写生产测试或改生产代码。

没有外部或框架边界的确定性本地规则不使用本技能，改用 [evidence-based-testing](../evidence-based-testing/SKILL.md)。

## 安全边界

- 只有任务授权正式环境检查时才做只读正式环境请求。
- 不得为了验证假设修改正式环境数据库或服务状态。
- 捕获产物时移除凭据与敏感载荷。
- 网络失败时先区分访问限制与提供方失败。
- 没有真实调用方或依赖契约证明必须同时支持多个契约形态时，不新增兼容分支。

## 示例

排查边界序列化回归时，检查真实调用方、实际解析的提供方版本、运行时配置与传输层输入输出，并通过真实边界重现行为。直接向内部单元传入已经归一化的输入，不能证明传输和归一化过程的实际契约。

## 完成证据

报告锁定版本、已验证调用链、观察到的契约、精确探测与仍未验证的边界。选择回归覆盖时组合 [evidence-based-testing](../evidence-based-testing/SKILL.md)。

## 常见错误

- 用最新文档推断旧的已安装版本。
- 模拟掉序列化、框架启动或传输过程。
- 未确认违约方就先改应用代码。
- 把类型检查通过当成运行时兼容。
