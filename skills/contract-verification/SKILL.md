# 核验现有契约

## 目标

只核验一个会改变当前结论或实现选择的契约事实。真实调用方、当前解析版本和实际输入输出优先于记忆、通用文档和示例。

## 核验步骤

1. 写清待确认的调用、输入、输出和两个可能结论；若结果不会改变决定，直接复用现有事实。
2. 从 manifest、lockfile、运行时元数据或部署制品确认当前实际版本和入口。
3. 先读取仓库中的真实调用方、类型、测试和同类用法，确定项目实际依赖的最小契约。
4. 本地事实不足时，在当前工作区已解析的包源码或类型中查证；工作区没有安装产物时，把它记录为证据缺口。
5. 仍需运行时证明时，执行一个安全、可重复、不会写正式环境的最小探测，并保存输入、输出、版本和环境。

正式环境的只读探测也需明确授权，捕获结果按数据敏感性脱敏；本技能不执行正式环境写入。

网络文档或发布说明只补当前版本的缺口；版本不同的示例不证明现有行为。替身只能证明本地调用假设，不能证明真实 SDK、传输或服务边界。

## 输出

报告确切版本、真实调用链、已确认契约、证据来源和剩余缺口。事实足以支持当前决定后停止；正式实现、升级、长期测试或契约产物由新的开发单元处理。
