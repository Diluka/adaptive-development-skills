# Property-Based Testing：属性测试

## 核心原则

用可证伪的属性描述一类输入必须保持的关系，再由生成器探索输入空间并把失败收缩为最小反例。属性必须来自需求、领域规律或独立参考模型；随机生成大量输入本身不是属性测试，只有“不崩溃”也不能替代真实行为判据。

## 建立前提

- 被测行为具有确定性，或时间、随机性和外部状态能够受控；
- 属性能在实现之外独立说明，并能拒绝合理但错误的实现；
- 输入域能够生成，失败样例能够稳定重放并在保持前提时收缩；
- 有副作用的每次执行都能隔离、重置或安全重复。

## 标准流程

### 1. Properties / Invariants

写明属性、不变量或变形关系的来源、适用输入域和失败含义。优先使用往返关系、幂等性、守恒关系、顺序或单调关系、状态机不变量，以及与更简单参考模型的等价性；只有领域规则确实保证时才能采用这些关系。

### 2. Generators

从领域结构生成有效输入，并显式覆盖空值、边界、极端规模和有意义的组合。无效输入使用独立生成策略和对应属性。避免先生成大量域外数据再过滤；记录或分类样例分布，确认关键子域实际被探索。

### 3. Execution

设置与风险匹配的样例数量、规模范围和可重现配置，执行属性并观察分类分布。失败时保留原始输入、运行环境和重放信息；通过大量样例只能增加证据，不能证明属性覆盖了错误的输入模型。

### 4. Shrinking

沿保持领域有效性和属性前提的方向收缩失败输入，直到得到最小且仍能复现的反例。若收缩结果落到域外，修正生成或收缩策略；若反例推翻了属性本身，先修正属性，不为错误判据修改生产实现。

### 5. Regression Example

把确认后的最小反例固化为显式回归样例或等价的版本化长期输入，同时保留探索广泛空间的属性测试。不要只依赖本地缓存、临时随机种子或工具内部格式。修复后先运行回归样例，再重跑属性测试，确认局部缺陷和输入空间都已覆盖。

## 排除场景

- 预期结果只是指定字面量或少量示例，没有独立属性；
- 约束已经由可信领域类型在编译期排除，生成运行时值只会重复检查类型形状；
- 输入集合小而封闭，参数化示例能更清楚地覆盖全部风险；
- 结果主要是主观评价、概率分布或多种合理答案；
- 外部副作用昂贵、不可逆或无法隔离，生成执行会造成真实风险；
- 属性、输入域或工具可行性仍未知，此时先通过 [technical-spike](../technical-spike/SKILL.md) 获得可丢弃证据。

## 产出证据

记录属性及其来源、生成域与样例分布、执行配置、原始和最小反例、重放方式、显式回归样例，以及修复后的回归与属性执行结果。

## 相邻方法

[test-driven-development](../test-driven-development/SKILL.md) 规定用失败示例驱动明确行为的实现时序；属性测试规定如何用独立属性、生成与收缩探索广泛输入空间。广泛输入不变量是主要风险时，本技能拥有该单元，首次属性失败不另算 TDD；属性检查只作为某个 Red 的测试技术时，由 TDD 拥有实现时序，不再为同一行为执行第二套主要流程。只有示例行为与广泛输入不变量具有独立目标和失败边界时才拆成两个单元。[type-driven-design](../type-driven-design/SKILL.md) 排除类型层面的非法表示；属性测试继续验证可信运行时值上的算法、变形关系和状态机不变量，不能因为算法使用类型就改走类型建模。[characterization-testing](../characterization-testing/SKILL.md) 从真实执行记录当前行为，不能替代独立属性；整体证据组合由 [evidence-based-testing](../evidence-based-testing/SKILL.md) 收敛。
