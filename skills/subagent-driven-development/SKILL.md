# Subagent-Driven Development：受控委派开发

## 核心原则

实现委派的主要价值是显著节约根代理上下文，同时让边界明确的局部工作独立推进。实现子代理是按场景选择的执行者，不是每个任务的固定角色；开发任务的最终独立评审子代理则是完成条件。根代理始终对需求、共享计划、范围、授权、集成、最终验证和完成声明负责。

## 有意识地选择任务

当以下条件成立且委派收益高于交接成本时，优先把实现、调查或定向验证交给子代理：

- 具有一个边界明确的结果和停止条件；
- 对开发任务，已在当前计划文档中记录工作单元、主要方法、负责人和验证方式；对非开发调查，已有共享目标、边界和证据要求；
- 上下文足以推进，无需重新发现整份需求；
- 工作需要大量局部代码搜索、日志分析、依赖调查或实现细节，委派能避免根代理加载这些局部上下文；
- 读取范围或写入范围可识别；
- 根代理可以检查并集成其结果；
- 不需要替用户做产品、授权或破坏性决策。

改动很小且根代理已经完整掌握上下文、多个步骤持续修改同一文件或共享状态、关键业务决策尚未解决、子代理需要频繁询问全局问题，或交接成本高于上下文收益时，不要强行委派实现。

当至少两个候选任务可以并行时，使用 [dispatching-parallel-agents](../dispatching-parallel-agents/SKILL.md)。否则顺序委派，或由根代理保留紧密耦合的工作。

## 委派与集成

1. 根代理先判断任务类型。开发任务读取共享计划；非开发调查只提供完成当前委派所需的目标、边界和证据要求。不要为每个任务固定创建实现者、修复者和评审者完整角色链。
2. 对开发任务，根代理先在计划中记录工作单元负责人、读写范围、依赖和共享状态，并提供计划的精确路径与工作单元标识；对非开发调查，提供共享目标、边界和证据要求。两者都应说明相关证据、预期产物或报告、验证责任，并明确禁止继续派生代理。
3. 决策和共享接口由根代理持有。在执行代理自行发明跨任务契约前，先解决它提出的问题。
4. 子代理只回报新事实、产物、差异与验证结果，不并发编辑共享计划。根代理检查实际文件后更新计划状态和决策，协调重叠内容并验证集成链路。
5. 开发任务的正式实现和相关验证完成后，根代理使用 [requesting-code-review](../requesting-code-review/SKILL.md) 派发未参与实现的独立评审子代理。若实现由子代理完成，评审者必须是另一个未参与实现或修复的子代理；实现者不得评审自己的改动。
6. 根代理使用 [receiving-code-review](../receiving-code-review/SKILL.md) 核验意见。实质修复后重新验证，并由未参与该轮实现或修复的独立子代理复审最终版本。
7. 使用 [verification-before-completion](../verification-before-completion/SKILL.md) 验证最终声明。若环境无法创建独立评审子代理，只能报告实现和验证完成、独立评审尚未完成。

复杂非开发调研不强制独立评审；当范围广、证据链长或容易偏离初始目标时，可以选择独立评审代理核对目标覆盖、反证和结论准确性。这个可选评审不把调查转换为开发任务，也不建立固定角色链。

## 边界

- 只有根代理可以派发。子代理必须自行完成被分配工作，并在缺少上下文或授权时向根代理报告。
- 不要为每个任务强制实现子代理、TDD 或提交。通过 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 选择测试和实现方法；只有用户明确要求或已授权工作流包含提交时才提交。开发任务的最终独立评审不在这些可选项中。
- 不要给两个执行代理重叠的写入所有权，也不要允许它们静默修改共享接口。
- 不要让子代理各自复制计划；跨工作树时传递协调计划文件的绝对路径。
- 未经明确授权，不得委派外部写入、正式环境数据变更、推送、合并或破坏性操作。
- 当真正的问题是任务定义、计划或共享契约时，停止无意义的重复派发。

## 示例

当一个开发任务同时包含正式文档更新和高风险接口调查时，根代理可以在它们能显著节约上下文且边界独立时委派工作，同时保留接口决策。最终完整差异仍由另一个未参与实现的子代理评审，但无需为每个工作单元分别创建实现者、修复者和评审者。

## 常见错误

- 委派“完成整个功能”这类模糊结果。
- 允许子代理继续创建子代理。
- 用新的执行代理代替保存共享决策。
- 不读实际文件就接受成功摘要。
- 为很小且已完全掌握的改动强行委派实现，使交接成本超过上下文收益。
- 让实现子代理评审自己的改动，或因根代理已经自查而省略最终独立评审。
- 把开发任务的强制评审误写成所有非开发调查的固定门禁。
