# 子代理驱动开发

## 适用范围

本技能只管理同一个 Codex 任务中的短生命周期代理树，用于隔离局部上下文或获得独立判断，不建立持久的并行开发轨道。子代理可以完成短小的只读工作；根代理能够立即检查和接管结果时，也可以完成边界精确的局部修改。

需求、共享计划、范围、授权、项目写入所有权、跨单元决策、集成、最终验证和完成声明始终由根代理负责。

## 选择工作单元

委派收益高于交接成本时，优先委派符合以下条件的单元：

- 角色产出、停止条件、读写范围和验证责任明确；
- 需要落盘计划的开发任务已记录该单元；无需计划的任务和非开发调查已有清晰共享目标与证据边界；
- 无需重新理解整份需求，也不需要替用户做产品、授权或破坏性决策；
- 局部搜索、日志、依赖或实现细节会明显占用根代理上下文，或者独立判断能提供实现者自证之外的证据；
- 能在当前任务的一次短生命周期内闭环，不需要长期持有项目写入、分支、工作树或运行资源；
- 根代理能够检查并集成结果。

改动很小且根代理已掌握上下文时，由根代理直接完成。步骤会持续修改共享状态、关键产品决策尚未解决，或需要频繁处理全局问题时，也不要委派。交接成本高于收益时同样由根代理完成。

缺失成功标准会改变用户意图时，先用 [brainstorming](../brainstorming/SKILL.md) 澄清，不能让多个代理投票替用户决定。至少两个候选单元能够安全隔离，且并行吞吐或独立对照有收益时，再使用 [dispatching-parallel-agents](../dispatching-parallel-agents/SKILL.md)。

单元还会继续分解、需要独立长上下文、持续项目写入、独立工作树或运行资源，可能跨当前任务停启运行，或完成后需要恢复一个已空闲的协调任务时，就不再属于本技能的子代理粒度。通过 [using-git-worktrees](../using-git-worktrees/SKILL.md) 建立或复用独立工作树，并按当前环境能力和用户授权另行分配负责执行上下文；条件不成立时缩小单元或顺序执行。

## 分离实现与证据

实现与证据有独立产物和反证边界，且分开能减少实现者自证偏差时，可以按收益分离三个角色。这个模式既适用于判据稳定的确定性行为，也适用于已有共享目标、代表性样例或评价边界的主观、概率性结果。

1. 实现者只修改约定的生产文件，并说明设计选择；不为预想测试增加需求外行为。
2. 验证者依据计划所指向的需求、设计、真实调用方和契约，独立设计测试、样例、评价量表或反证。角色产出包含自动化测试时，只修改约定的测试与夹具，通过所选真实入口验证可观察结果，并回报规格映射、运行环境与结果。预期不能从实现细节或生产组件列表反推，也不能复制目标字面量制造镜像测试。
3. 任务级别或具体风险要求独立评审时，最终评审者读取完整差异和验证证据，检查实现与证据是否共同偏离真实目标。参与实现、验证、证据设计或相关项目差异修改的代理不得兼任。

验证者不必产出自动化测试。确定且稳定的不变量可以进入测试；模糊质量用评估或实验；能稳定复现的真实输出可以用快照或行为基线。根代理通过 [evidence-management](../evidence-management/SKILL.md) 决定证据层级和哪些产物值得长期保留。

## 局部实现与验证协作

实现与证据设计可以由不同子代理提供独立视角，但当前任务仍只有一个持久项目写入所有者。共享说明先固定目标行为、真实调用方、公共契约、评价边界、角色产出和停止条件。

1. 实现子代理只在单次短生命周期内修改精确约定的文件。完成后立即把实际差异交回根代理，不继续占有分支、工作树或运行资源。
2. 验证子代理可以并行执行只读证据设计、样例分析或稳定数据查询。需要写测试、夹具或评估产物时，由根代理串行安排写入，或者把它升级为独立工作树任务。预期结果只能来自需求、设计、真实调用方和契约，不能从未完成实现反推。
3. 两个角色都需要持续修改项目，或一方运行验证时另一方仍会改变被测状态，就通过 [dispatching-parallel-agents](../dispatching-parallel-agents/SKILL.md) 和 [using-git-worktrees](../using-git-worktrees/SKILL.md) 建立粗粒度独立工作树单元。不能把共享工作区的移动中间状态描述为并行开发证据。
4. 根代理读取实际文件、处理隐藏重叠，并在最终组合状态重新运行验证。再通过 [evidence-management](../evidence-management/SKILL.md) 收敛仍提供独特价值的长期证据；适用的最终独立评审只在实现、证据和组合验证齐备后开始。

## 委派与集成

1. 根代理说明工作单元、主要方法、相关证据、读写边界、角色产出、停止条件和验证责任，并明确禁止继续派生代理。子代理把不影响本单元实现、验证或交付的问题作为单元外发现回报，不超出分类所需的最小证据继续调查、修改或建立外部问题单；由根代理判断它是否影响整个任务。
2. 有统一计划时，提供精确路径和单元标识；没有计划的开发任务和非开发调查，提供共享目标与证据要求。
3. 跨单元决策和共享接口由根代理持有。子代理回报新事实、实际差异和验证结果；有适用计划时不并发编辑计划，也不通过修改另一角色的文件自行解决契约分歧。
4. 根代理读取实际文件、解决重叠并验证集成，不只接受成功摘要；有适用计划时同步更新，没有计划时更新共享目标和证据状态。

任务级别或具体风险要求独立评审时，通过 [requesting-code-review](../requesting-code-review/SKILL.md) 选择未参与实现、证据设计或相关项目差异修改的独立评审者；实质修复后的处理使用 [receiving-code-review](../receiving-code-review/SKILL.md)。实现委派不会自动要求或免除最终评审，仍按当前增量的证据收益决定。

## 边界

- 本技能中的根代理和子代理作用域只限当前 Codex 任务。只有当前任务的根代理可以派发；子代理缺少上下文或授权时回报根代理，不继续创建代理。粗粒度单元另行分配的负责执行上下文是新的任务根代理，不是本代理树中的嵌套子代理；[using-git-worktrees](../using-git-worktrees/SKILL.md) 只处理其工作树隔离，不创建执行上下文。
- 子代理发现技术上相关但不影响所委派单元的问题时，只回报必要证据。根代理再按整个当前任务判断是否需要处理，不能仅凭技术关联并入任务，也不能因为不影响该单元就直接排除。
- 不给执行代理重叠写入所有权，也不允许静默修改共享契约。
- 需要独立判断时，各代理基于同一已确认目标工作，在回报前不读取或迎合另一代理的结论；根代理负责比较，而不是让代理互相收敛。
- 有协调计划时，跨工作树传递其绝对路径，不复制计划；没有计划时传递共享目标、约束和证据边界。
- 最终普通 Git 交付由根代理在组合验证后串行完成；当前任务内的子代理不独立持有提交、推送或 PR/MR 交付轨道。合并、发布、部署、正式环境数据变更、权限修改和破坏性操作仍需用户明确要求，且不得通过委派扩大边界。
