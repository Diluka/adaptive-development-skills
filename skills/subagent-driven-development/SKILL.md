# Subagent-Driven Development：受控委派开发

## 核心原则

本技能只管理同一个 Codex 任务内的代理树。委派可以节省根代理的上下文，也可以分开实现与证据设计，减少实现者自证偏差。是否使用子代理看实际收益。需求、共享计划、范围、授权、跨单元决策、集成、最终验证和完成声明始终由根代理负责。

## 选择任务

委派收益高于交接成本时，优先委派满足以下条件的单元：

- 角色产出、停止条件、读写范围和验证责任明确；
- 需要落盘计划的开发任务已记录该单元；无需计划的任务和非开发调查已有清晰共享目标与证据边界；
- 无需重新理解整份需求，也不需要替用户做产品、授权或破坏性决策；
- 局部搜索、日志、依赖或实现细节会明显占用根代理上下文，或者独立判断能提供实现者自证之外的证据；
- 根代理能够检查并集成结果。

改动很小且根代理已掌握上下文，或步骤持续修改共享状态、关键产品决策未解决、需要频繁处理全局问题时，不要委派。交接成本高于收益时也由根代理完成。缺失成功标准会改变用户意图时，先用 [brainstorming](../brainstorming/SKILL.md) 澄清，不能让多个代理投票替用户决定。至少两个候选单元能够安全隔离，且并行吞吐或独立对照有收益时，再使用 [dispatching-parallel-agents](../dispatching-parallel-agents/SKILL.md)。

如果单元本身还会继续分解、需要独立长上下文或工作树、可能跨当前任务停启持续运行，或者完成后需要恢复一个已空闲的协调任务，就不再是本技能的子代理粒度。只有用户明确授权创建新 Codex 任务时，才使用 [orchestrating-multi-session-work](../orchestrating-multi-session-work/SKILL.md)；否则缩小单元或留在当前任务内执行。

## 分离实现与证据

对于主观、概率性或允许多种合理实现，但已有共享目标、代表性样例或评价边界的单元，可以按收益分离三个角色：

1. 实现者只修改约定的生产文件并说明设计选择，不为预想测试增加需求外行为。
2. 证据设计者依据需求、真实调用方和契约独立提出测试、样例、评价量表或反证；不从实现细节反推预期，也不复制目标字面量制造镜像测试。
3. 任务级别或具体风险要求独立评审时，最终评审者读取完整差异和验证证据，检查实现与证据是否共同偏离真实目标；不得由参与实现、证据设计或相关项目差异修改的代理兼任。

证据设计者不必产出自动化测试。确定且稳定的不变量可以进入测试；模糊质量用评估或实验；能稳定复现的真实输出可以用快照或行为基线。根代理通过 [evidence-based-testing](../evidence-based-testing/SKILL.md) 决定哪些证据值得长期保留。

## 委派与集成

1. 根代理说明工作单元、主要方法、相关证据、读写边界、角色产出、停止条件和验证责任，并明确禁止继续派生代理。要求子代理把不影响本单元实现、验证或交付的问题作为单元外发现回报，不超出分类所需的最小证据继续调查、修改或建立外部问题单；由根代理判断它是否影响整个任务。
2. 有统一计划时提供精确路径和单元标识；没有计划的开发任务和非开发调查提供共享目标与证据要求。
3. 跨单元决策和共享接口由根代理持有。子代理回报新事实、实际差异和验证结果；有适用计划时不并发编辑计划。
4. 根代理读取实际文件、解决重叠并验证集成，不只接受成功摘要；有适用计划时同步更新，没有计划时更新共享目标和证据状态。

任务级别或具体风险要求独立评审时，通过 [requesting-code-review](../requesting-code-review/SKILL.md) 由未参与实现、证据设计或相关项目差异修改的独立子代理评审；实质修复后的处理使用 [receiving-code-review](../receiving-code-review/SKILL.md)。实现委派不会自动要求或免除最终评审，仍按当前增量的证据收益决定。

## 边界

- 本技能中的根代理和子代理作用域只限当前 Codex 任务。只有当前任务的根代理可以派发；子代理缺少上下文或授权时回报根代理，不继续创建代理。由协调任务创建的独立工作任务是新的任务根代理，不是本代理树中的嵌套子代理。
- 子代理发现技术上相关但不影响所委派单元的问题时，只回报必要证据。根代理再按整个当前任务判断是否需要处理，不能仅凭技术关联并入任务，也不能因为不影响该单元就直接排除。
- 不给执行代理重叠写入所有权，也不允许静默修改共享契约。
- 需要独立判断时，各代理基于同一已确认目标工作，在回报前不读取或迎合另一代理的结论；根代理负责比较而不是让代理互相收敛。
- 有协调计划时跨工作树传递其绝对路径，不复制计划；没有计划时传递共享目标、约束和证据边界。
- 未经明确授权，不委派外部写入、正式环境数据变更、推送、合并或破坏性操作。
