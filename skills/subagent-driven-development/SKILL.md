# Subagent-Driven Development：受控委派开发

## 核心原则

实现委派的主要价值是显著节约根代理上下文，让边界明确的局部工作独立推进。实现子代理按场景选择；根代理始终负责需求、共享计划、范围、授权、集成、最终验证和完成声明。

## 选择任务

委派收益高于交接成本时，优先委派满足以下条件的单元：

- 结果、停止条件、读写范围和验证方式明确；
- 开发任务已在计划中记录该单元，非开发调查已有共享目标和证据边界；
- 无需重新理解整份需求，也不需要替用户做产品、授权或破坏性决策；
- 局部搜索、日志、依赖或实现细节会明显占用根代理上下文；
- 根代理能够检查并集成结果。

改动很小且根代理已掌握上下文、步骤持续修改共享状态、关键决策未解决、需要频繁询问全局问题，或交接成本更高时，不强行委派。至少两个候选单元真正独立时再使用 [dispatching-parallel-agents](../dispatching-parallel-agents/SKILL.md)。

## 委派与集成

1. 根代理说明工作单元、主要方法、相关证据、读写边界、预期结果、停止条件和验证责任，并明确禁止继续派生代理。
2. 开发任务提供统一计划的精确路径和单元标识；非开发调查提供共享目标与证据要求。
3. 跨单元决策和共享接口由根代理持有。子代理回报新事实、实际差异和验证结果，不并发编辑计划。
4. 根代理读取实际文件、更新计划、解决重叠并验证集成，不只接受成功摘要。

开发任务最终仍通过 [requesting-code-review](../requesting-code-review/SKILL.md) 由未参与实现的独立子代理评审；实质修复后的处理使用 [receiving-code-review](../receiving-code-review/SKILL.md)。实现委派可选不影响该完成条件。

## 边界

- 只有根代理可以派发；子代理缺少上下文或授权时回报根代理，不继续创建代理。
- 不给执行代理重叠写入所有权，也不允许静默修改共享契约。
- 跨工作树传递协调计划的绝对路径，不复制计划。
- 未经明确授权，不委派外部写入、正式环境数据变更、推送、合并或破坏性操作。
