# 完成前核验

## 规则

完成声明必须由仍覆盖最终增量的直接证据支撑。输入、环境、版本、调用路径和风险面未变的证据可以复用；证据足够后停止追加。

本技能不重新选择验证方法，也不发起新的产品设计。它只把准备声明的结果与已有证据逐项对应，并补当前声明缺少的最小检查。

## 常见映射

| 声明 | 直接证据 |
|---|---|
| 行为已实现或修复 | 真实消费或激活路径上的当前预期行为；修复还需已有失败或根因证据 |
| 重构保持行为 | 风险对应的前后测试或相同输入与环境下的结果对照 |
| 测试、构建或类型检查通过 | 精确命令的最新退出状态与有效输出 |
| 外部集成可用 | 确切版本及契约或集成探测 |
| CI 结束或通过 | 最终推送提交对应的自动任务终态；“通过”要求必需任务成功 |
| 差异干净 | Git 状态、完整差异和未跟踪文件审阅 |
| 调查完成 | 原始目标、结论、直接证据、适用边界和剩余未知 |

无法安全重现旧失败时，复用已有失败或根因证据，并用当前真实路径验证后收窄声明。

## 核验步骤

1. 列出准备作出的完成声明和最终实际增量。
2. 为每项声明找到仍适用的直接证据。
3. 先确认需求明确提及的真实路径和仓库强制检查，再补一个能拒绝当前具体缺口的检查。
4. 读取退出码与有效输出，区分本次回归和已知基线失败。
5. 核对当前任务级别已经要求的独立评审状态。

技能、提示规则或概率性结果的结构检查只能证明格式有效；代表性场景属于评估，应说明环境、样例和剩余不确定性。

报告精确命令或观测、结果及其支持的声明。失败、超时或部分覆盖时明确缺口，不把未证明内容描述为完成。
