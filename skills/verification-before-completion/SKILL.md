# 完成前核验

## 基本规则

每项完成声明都要有仍覆盖最终增量的直接证据支撑。“最新”指输入、环境、版本、调用路径和风险面仍与声明相符，并不要求在当前轮次重新运行。验证范围与风险相称；证据足以支持当前声明后立即停止追加。

验证方式选择（过程选手段）与完成声明核对（收尾核证据）是两件事：前者属于 [execution](../execution/SKILL.md) 的微观决策（见 `resources/verification-selection.md`）；本技能保持独立，只管完成声明和节点转换前的最终核对。验证通过的最低判据与工作流一致：真实消费或激活路径上的直接证据至少覆盖需求明确提及的正常场景，并完成适用于当前增量的仓库强制检查。

## 映射声明与证据

| 声明 | 直接证据 |
|---|---|
| 行为已修复 | 修复前失败或根因证据，加真实接缝上的当前预期行为 |
| 重构保持行为 | 按风险选用或组合重构前后的同一核心测试、相同环境与输入下的可重复冒烟观测和结果对照 |
| 可复现输出保持稳定 | 同一真实执行路径生成的最小快照或行为基线，加对业务差异的审阅 |
| 主观或概率性结果改善 | 预先定义的代表性样例与评价标准，加重复或独立评估结果、已知波动和剩余不确定性 |
| 测试通过 | 指定测试命令的最新输出 |
| 构建或类型检查通过 | 精确项目命令的最新输出 |
| 类型约束成立 | 当前严格编译或静态检查，加公共或复杂类型 API 必要的正反编译契约；另列类型系统无法证明的运行时风险 |
| 外部集成可用 | 确切版本，加契约或集成探测 |
| 分支或合并结果的 CI 已结束 | 最终推送提交或合并结果对应的全部自动任务进入成功、失败或取消终态；手动可选任务不阻塞，流水线内自动 review 环境任务属于自动任务。声称 CI 通过时，必需自动任务均为成功状态 |
| 软件持续保持可发布 | 最终集成结果的 CI、可追溯制品、同一制品的环境提升记录和当前恢复准备 |
| 渐进发布已完成或安全 | 精确制品与配置、各暴露阶段的实时观测、阈值决策、最终状态和实际回退结果或当前回退能力 |
| 清理安全 | 调用方、导出和加载分析，加保留路径检查 |
| 生产事故已解决 | 当前部署和改动后的日志、指标或只读状态 |
| 差异干净 | Git 状态、差异检查和对已暂存、未暂存、未跟踪内容的审查 |
| 功能收尾已对齐 | 本次变更直接影响的既有伴生产物，加对最小同步内容的审阅 |
| 开发任务已完成 | 当前增量的直接验证，以及任务级别或具体风险要求时适用的独立评审 |
| 调查已完成 | 原始目标、结论、直接证据、未决项和临时产物清理证明 |

无法安全重现旧失败时，用已有的失败或根因证据，加当前真实链路验证，并收窄声明。不得为了证明修复而还原旧代码、破坏工作状态或修改正式环境数据。

## 运行检查

1. 明确当前完成声明、实际增量和可能失效的既有证据。
2. 审阅复用判定，复用输入、环境、版本、调用路径和风险面仍相同的测试、评审、观测或 CI。
3. 先确认真实消费或激活路径上的正常场景证据与适用仓库强制检查，再运行覆盖证据缺口的定向检查。
4. 从计划、变更路径及其已知引用中，核对本次变更直接影响的既有维护文档、示例或说明，并审阅最小同步；不做全仓库资料清扫，也不修复本次变更未触及的历史问题。
5. 主动追加的类型检查、构建、更多测试、完整 CI 或独立评审能拒绝一个已指明且尚未证明的风险时，再扩大检查；风险越高越应保留独立评审。
6. 阅读退出码和有效输出，区分本次回归与已确认的基线失败。

测试只是证据之一，证明不了被跳过的框架、传输、包或部署边界。验证完成声明时，不要写正式环境数据。

先按 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 判断独立评审是否适用；适用时，再按 [requesting-code-review](../requesting-code-review/SKILL.md) 核对受影响最终差异。

证据失效与再验证规则见 [execution](../execution/SKILL.md) 的 `resources/evidence.md`；判定失效后重新核对受影响范围。缺少必要证据时收窄声明；证据充分时完成核验。非开发调查没有统一评审门禁，复杂调研只在实际选择了独立检查时报告该证据。

## 启发式结果

技能、提示规则或代理工作流属于启发式结果时，格式、引用和静态检查只能证明结构有效。代表性场景和子代理观察属于评估；子代理可能同时受已安装技能、系统规则和会话上下文影响，不能把单次模拟描述为隔离行为测试。

明确评估限制，把安装后的真实任务表现和后续具体反馈作为实践验证，并据此继续迭代。

测试本身与需求冲突时按 [execution](../execution/SKILL.md) 的 `resources/evidence.md` 处理，不要削弱真实不变量来追求绿灯。

## 报告

说明命令或观测、运行时间、结果及其支撑的结论。检查失败、超时、无法运行或只覆盖部分声明时，明确缺口，不把未完成工作描述为完成。
