# 基于证据定位根因

## 核心原则

从真实失败边界取证；只有比其他候选更能解释症状、调用链、环境和反证的假设才是根因。到第一个错误状态或契约违例即结束调查，不实施修复。

可用最小、可逆、可丢弃的插桩，但不改不变量或泄密；部署、外部状态和正式环境仍须授权。决定保留即作为正式增量返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md)。

## 确认症状

记录以下症状边界：

- 实际与预期行为、时间范围、环境和受影响标识符。
- 部署提交或镜像、配置与依赖版本，以及证据的新旧和可复现性。
- 已知未受影响范围，并区分应用失败、错误测试假设、监控假象、网络限制和过时部署。

## 追踪真实路径

从真实入口沿数据流和控制流追踪到失败。优先使用仓库语义索引或调用图，再用源码搜索和运行时证据补充。

| 症状 | 有效证据 |
|---|---|
| 只在正式环境出现 | 日志、APM 跟踪、当前部署、只读 DB 状态和下游响应 |
| 失败测试 | 需求、真实调用方、夹具假设、依赖契约和改动代码 |
| 间歇性任务 | 任务载荷、重试、进程异常、幂等状态和时序 |
| 近期回归 | 部署或提交边界、`git log`、`git blame`、依赖和配置改动 |
| 性能回归 | 跟踪片段、剖析、查询计划、指标和代表性负载 |

调查期间不得写正式环境数据源。只查询必要数据，并避免暴露敏感值。

## 检验原因假设

1. 列出由证据支持的候选原因，并按解释能力排序。
2. 选择能区分首要候选的最小安全观测；必要时使用可逆插桩。
3. 用结果更新候选，直到因果链到达第一个错误状态或契约违例。

本地复现只有在保留真实失败边界时才有价值，不是使用现有生产证据推理的前置条件。

## 交付根因证据与转换

报告症状边界、因果链/首错或契约违例、决定性证据、影响、反证、未知和建议修复层；不修改实现或测试。

若还需修复，带被违反的需求/契约、修改层和可复用区分性观测回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md)；后续单元负责正式回归与变更后验证。外部边界不明则拆 [contract-verification](../contract-verification/SKILL.md)。重新运行区分性观测并检查受影响链路；证据只覆盖一种失败模式时收窄结论。
