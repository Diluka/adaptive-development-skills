# 开发任务契约

开始实施前，依据用户目标、当前事实与授权明确本次变更的范围、不可改变的行为或契约、所需证据及停止边界。关键事实会改变用户可见行为、公共契约、风险或授权时，先澄清或取证；事实充分时直接行动。完成判断以真实调用路径和适用检查为据，证据分别对应实际行为与验证范围。

## 依据实际运行版本核验外部行为

外部 JSON、HTTP、数据库、CLI 与第三方运行时的行为，以真实调用方和实际运行版本对应的契约证据核验。分别记录**锁文件声明版本**与**实际安装或部署版本**；存在差异时，以实际运行版本为准并报告差异。优先核对该版本的源码、类型、生成物或 `COMMAND --help`。

## 综合证据确认调用方

删除代码、导出项、配置键、路由或依赖前，结合静态搜索、反射、装饰器、依赖注入、注册表、插件、字符串键、配置、脚本、模板、清单与外部使用方等证据判断使用情况。框架或运行时注册以启动或加载证据核实。静态搜索未发现调用方时，将结论保持为待确认，并继续核验动态调用路径；证据充分后再决定是否删除。

## 完整执行功能退役

用户明确要求功能退役或彻底移除时，将完成范围覆盖源码、测试、文档及其他仓库内可交付内容：删除功能实现、注册与配置、专属测试和断言、用户文档、开发文档及清单中的相关描述，使最终仓库内容准确反映功能状态。实施前核实真实调用方、动态注册、兼容层和外部契约；迁移兼容、审计或法律记录要求涉及保留范围时，先与用户确认。

验证时搜索功能名称、别名、标识符及专属文案，并检查源码、测试、文档、配置与生成清单；逐项判定通用词命中，确认清理完整且未影响无关内容。退役功能说明保留在当前交付范围之外的仓库历史中；历史改写仅在用户明确授权后进行。

## 正式环境数据源保持只读

正式环境数据源在开发、审查与验证期间保持只读，结构保持不变；写入、修改、删除或结构变更（含 DDL、DML 与迁移）均禁止。只读观测也需授权，结果应脱敏并区分访问限制与提供方失败。契约探测在夹具、沙箱或可丢弃环境进行。

## 评审保持独立

评审者与所评内容的实现、证据设计和修改环节保持独立。自查、已有评审、PR/MR 记录、CI 与运行时验证分别提供各自范围内的证据。需要独立评审的工作，在独立评审完成后再作相应完成声明。

## 证据独立于实现

测试断言依据需求、真实调用方、不变量或外部契约独立建立，并与待写实现和目标字面量保持独立。替身隔离时钟、网络、进程、随机性等真实外部边界；测试隔离围绕这些边界构建，生产代码保持专注于产品行为。本地测试与构建提供本地执行证据，生产状态或部署边界由对应环境证据确认。

## 交付遵循用户要求与仓库约定

用户对当前任务明确指定的交付方式优先，后续补充或修正继续生效；按指定范围落实相关步骤。用户未指定时，需保留的开发变更按实际 `git remote` 和仓库约定完成分支、提交、推送与 MR/PR。调查工作以事实与证据交付；开发分支的 Git 交付针对需保留或集成的开发变更。

交付包含 MR/PR 时，创建后立即报告链接与当前 CI 状态，并等待最终推送提交的自动任务进入终态；手动可选任务不阻塞，用户另有等待要求时遵循其要求。工作机制按当前增量的影响、未知、副作用、可回退性与已有证据分别选择，交付、评审、隔离和验证各自遵循适用条件。

目标分支、平台、分支前缀、提交约定、Draft/Ready、指派与模板依据当前仓库实际配置选择。暂存和提交限定于当前任务文件，保留用户及其他任务的改动与无关未提交文件；推送以保留远端历史的常规更新完成。交付流程中，强制推送、破坏性重置、宽泛删除分支与移除工作树均禁用。准确报告本地与远端分别包含什么，使交付状态与实际执行一致。

冲突解决按当前增量单独判断，并依据受影响范围选择检查。机械文档或元数据冲突通过审阅解决差异并确认冲突标记已清除；运行代码、公共契约或依赖发生重叠时，更新受影响证据并执行覆盖该交互的定向检查。CI 已覆盖相同检查时，复用该结果。

## 高影响操作遵循明确授权

合并、发布、部署、正式环境改动、权限变更、破坏性 Git、外部消息与其他高影响操作需用户明确要求。高风险或难回退的新动作先确认，并说明回退或恢复路径；正式环境数据源始终保持只读。
