# Using Git Worktrees：默认隔离开发

## 核心原则

开发任务默认在任务专属关联工作树中实施，让根工作区保持稳定基线并支持其他需求并行进行。只有用户明确要求直接在根工作区操作时才例外；启动目录恰好是根工作区不代表用户作出了该要求，干净、低风险或没有冲突也不是跳过隔离的理由。

用户没有明确要求根工作区，且当前已经位于与本任务对应的关联工作树时，直接继续而不重复创建。纯回答和只读调查等非开发任务不默认创建工作树；只有具体 Git、版本、文件或并发风险需要隔离，或者用户与仓库明确要求时才创建。

## 判断执行位置

开发任务正式实现前先确认：

1. 用户是否明确要求直接在根工作区操作；是则记录该例外并遵循要求。
2. 当前是否已经是与本任务对应的关联工作树；是则继续使用。
3. 其他情况从经核实的基点创建任务分支和关联工作树，不占用或切换根工作区。

高风险历史操作、大型迁移、冲突解决、不同分支或依赖的并行工作、目标文件与现有改动重叠，以及验证另一个分支或版本，会进一步加强隔离需要，但不再是开发任务创建工作树的前提。

工作树分别持有工作目录、索引和检出状态，但仍通过公共 Git 目录共享分支与远端引用、对象库、仓库配置与钩子、`refs/stash` 和工作树注册信息。Git 公共状态以及端口、进程、数据库、外部服务等运行时资源仍需单独协调，不因文件隔离而视为可以并发修改。

## 创建前检查

```bash
git rev-parse --show-toplevel
git rev-parse --git-dir
git rev-parse --git-common-dir
git rev-parse --show-superproject-working-tree
git rev-parse --verify HEAD
git rev-list --all --max-count=1
git branch --show-current
git status --short
git worktree list --porcelain
```

Git 目录与公共目录不同时，当前工作区通常已是关联工作树。结合分支、状态、计划和任务目标判断它是否属于当前任务；不要复用其他任务的工作树。需要创建新工作树时，不得把目标放在当前关联工作树目录内，并用 `git worktree list --porcelain` 确认目标分支未在其他位置检出。

`git rev-parse --verify HEAD` 失败只表示当前工作树的 `HEAD` 无法解析，不证明仓库没有提交。先核实任务目标分支或提交，并用 `git rev-list --all --max-count=1` 检查现有引用是否仍有提交；存在可用任务基点时从该基点创建工作树。只有确认没有可用提交基点后，才通过已安装 Git 的帮助检查 `--orphan`；支持且任务不依赖根工作区中的未跟踪内容时，使用 `git worktree add --orphan -b <new-branch> <path>` 创建未出生分支的关联工作树。不支持或任务依赖这些内容时说明限制并等待用户决定，不为创建工作树自动生成提交、复制其他任务内容或静默降级为在根工作区开发。

确认任务基点和目标分支，不从当前目录或硬编码分支名猜测。根工作区中的未提交改动不会进入新工作树；任务依赖这些改动时停止创建并说明依赖，不复制、暂存或提交其他任务的内容。

## 选择位置并创建

优先遵循仓库说明。主工作树可使用 `<repo>/.worktrees/<name>`；从关联工作树发起时，优先使用仓库指定的同级目录或根据 `git worktree list --porcelain` 解析主工作树位置，不把新工作树嵌套在现有任务工作树内。

在承载 `.worktrees/` 的工作树根目录确认忽略规则：

```bash
git check-ignore -q --no-index .worktrees/
```

未被忽略时，只有仓库配置属于当前范围才添加精确规则，不静默提交。优先使用执行环境的原生工作树能力；否则以明确分支和解析后的路径运行 `git worktree add`，不从未检查变量或宽泛路径推导目标。

任何工作树创建或创建后验证失败都停止并报告确切限制，等待用户决定；不得改用根工作区继续实施，也不得通过强制检出、删除其他工作树或修改其他任务状态来绕过失败。

## 创建后

1. 确认路径、分支或分离 HEAD 状态及干净状态。
2. 阅读新工作区的仓库说明。
3. 在任务工作树中创建或读取唯一计划；计划由其他协调位置维护时传递其绝对路径，不复制计划。
4. 只执行任务需要且已授权的准备。不要自动安装依赖、运行全量测试、提交、拉取、推送、合并或删除其他工作树。
5. 条件具备时运行能区分新回归与基线失败的最小检查；缺依赖时报告限制。

报告任务工作树路径和分支。进入后只在该工作树中实施和检查本任务，不把其他工作树的并发改动纳入本任务差异。集成与移除交给 [finishing-a-development-branch](../finishing-a-development-branch/SKILL.md) 或用户明确请求；删除前确认没有会丢失的未提交工作。
