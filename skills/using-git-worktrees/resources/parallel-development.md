# 工作树并行开发的实际隔离边界

Use when 多个持续写入单元已决定并行，需判断独立工作树之外还共享什么；派发、回报与组合验证由 [代理与并行编排](../../agent-and-parallel-dispatch/SKILL.md) 负责。

每个并发写入单元有自己的负责执行上下文、工作树与文件所有权。工作树分别隔离目录、索引和检出状态，**不会**隔离 Git 公共目录中的 refs、远端引用、仓库配置、钩子和 `refs/stash`，也不会隔离逻辑文件、锁文件、生成规则、迁移序列、共享接口、端口、进程、数据库或外部服务。

为每项单元分配不重叠的文件与运行资源；隔离不可证明时缩小单元、改只读或顺序执行。共享契约先确定再并行，尚需另一方的结论或中间产物时按真实依赖顺序安排。独立工作树只解决部分文件状态冲突，不能代替执行上下文独立性或最终组合验证。

协调者在所有写入者停止后，检查实际差异与共享状态，串行解决同仓库冲突并在组合状态验证、交付。若需要进程崩溃恢复、持久消息、租约或无人值守重试保证，应使用有相应契约的外部控制器；普通任务消息不能冒充这些能力。
