# 正式文档维护方法

正式项目文档记录需要长期维护的项目事实。只有用户要求保留，或项目规范要求维护时，才创建。准备纳入版本控制的文档属于开发任务，按主技能正文的
Git 交付边界定级与交付；位置规则见主技能正文（用户指定 > 项目规范 > 正式
`docs/`）。不要把正式文档放进忽略目录，也不要提交临时过程记录。决定长期保留调查草稿时，先按准备保留的实际增量转换并定级，再整理进正式目录。

## 选择最小充分形态

先写出目标读者要完成的任务、最需要回答的问题，以及文档需要长期保持权威的范围。按读者问题或稳定主题组织提纲，再选择能承载它们的最小形态；沿用项目已有约定，单篇能清晰回答时不扩成套装，主题形成独立阅读路径或维护边界时拆分并交叉引用。

把篇幅视为软性信息预算：每一节应回答读者问题、支撑判断或提供必要行动。只增加背景却不改变理解的内容应压缩、链接下沉或删除；不用机械字数、固定章节数或占位内容衡量完整性，没有项目或读者约束时也不自行设定目标篇幅。

## 选择内容

| 文档类型        | 按用途与适用性说明的核心内容                                                                                                                                                                                       |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Issue / 工作项  | 用当前态说明问题或目标、选定设计或要求、纳入范围、依赖、验收和真正未决事项；相邻路线会实质影响理解或执行时，只写其与当前决策标准冲突的原因                                      |
| 需求文档        | 目标、范围、可观察结果、验收标准、约束和未决问题；需要以可演进规格贯通需求、设计、任务和实现时，规格链由 [spec-driven-development](../../spec-driven-development/SKILL.md) 拥有，本方法不重复维护需求条目 |
| 设计文档        | 当前事实、选定方案、组件或数据流、关键契约、权衡、风险和回退                                                                                                                                                      |
| 接口文档        | 使用方与提供方、输入输出、错误语义、鉴权、版本和兼容性约束                                                                                                                                                        |
| 规格文档        | 需求到实现的规格链（随演进同步维护），内容与归属见 [spec-driven-development](../../spec-driven-development/SKILL.md)                                                                                              |
| 决策记录（ADR） | 背景说明待解决问题，决策与后果只描述当前路线；真实备选影响了选择，且其原因对理解或审计当前决策有价值时，在理由或取舍中记录一次关键差异和未选理由，不展开为平行设计；进入版本控制后经历提出、接受 / 拒绝、弃用等生命周期，弃用记录仍保留供追溯 |
| 决策型简报      | 待读者决定的事项、当前结论或建议、影响与取舍、支持证据及其不确定性、行动项和开放问题；只在需要决策或推动行动时使用此结构                                                                                           |
| 实施或迁移文档  | 实际工作单元、依赖和验证；涉及发布、迁移、难回退操作或已识别剩余风险时，再记录对应安排                                                                                                                                                                        |
| 交付对外文档    | 面向外部读者（用户、客户、发布说明、API 使用者）：目标读者、可观察行为、变更与兼容性影响、升级或使用方式                                                                                                          |
| README / Wiki   | 项目知识入口与长期知识库；形态选择、组织和维护方法见 [wiki.md](wiki.md)                                                                                                                                            |

范围由目标、穷尽的纳入项、影响和约束在一个权威位置正向闭合。用户列出的排除对象已经由该范围完整承载时，省略这些对象的名称；确有未被纳入项表达且会改变实施、验收、授权或契约 / 兼容性判断的边界时，补充其具体影响。其他章节引用这一定义，不重复列出排除项。

只创建需要的文档。内容跨类型时，根据项目现有形式和维护成本决定合并或拆分，不生成固定套装或占位文件。

把正式文档作为面向目标读者的交付产物，而不是素材归档。起草前先把来源区分为最终状态与形成过程；正文只提炼读者理解、执行或审计当前结论、选定设计、要求和后续行动所需的信息，探索、讨论、调研流水和逐项排除等形成过程留在本地临时材料。过程本身是理解结论或审计决策所必需的信息时，才把相关事实、权衡或理由改写成当前说明，不搬运原始记录。

## 组织决策型内容

需要读者作出选择、理解影响或安排后续行动时，让结论或待决事项、影响与取舍、证据和行动项能够被快速定位；证据不足时明确缺口和取得结论所需的信息。说明、教程、参考和叙事型文档按读者阅读顺序展开，不要求结论优先，也不机械加入执行摘要或建议章节。

## 来源与证据

1. 从当前代码、已有文档、真实调用方、依赖契约和其他原始来源收集事实，记录足以判断其出处、日期、版本和适用范围的信息。
2. 优先使用与当前问题最接近、权威且仍适用的来源；保留理解演进所需的历史材料，但不让旧摘要覆盖新证据。
3. 区分已确认事实与综合判断；证据缺口、来源矛盾或已过期信息真实存在且影响读者判断时，就近写明适用范围。冲突无法裁决时写明各自范围，不制造无证据的统一结论。
4. 关键主张、数据和直接引文就近引用，并按项目规范链接原始来源；相关陈述可以共享引用，不逐句机械堆叠。来源时效影响结论时明确标记。

## 编写与维护

1. 明确读者、用途和长期保存范围，只澄清会实质改变内容或结构的歧义。
2. 按读者问题或主题提纲写作，保持标题能够说明该节解决什么问题；保留 API、命令、路径、字段和符号的精确写法。
3. 优先修订已有权威内容；同一事实的完整解释只维护一次，其他位置保留必要摘要并交叉引用。
4. 实现或新证据改变需求、设计、接口、摘要或导航时，同步修订受影响内容；当前正文表达当前最佳理解，演进历史按需交给 ADR、变更记录或 Wiki 日志。
5. 确认路径未被忽略，验证读者问题、事实、引用和链接；任务级别或具体风险要求时，再让未参与编写的独立子代理评审最终差异。
6. 按主技能的否定标记检查逐句审阅，给每个保留项标明其信息角色；其余内容正向改写或删除。

## 文档原则

- **当前型文档表达项目当前状态**：只有读者确需追溯时才通过 ADR、规格链、变更记录或 Wiki 日志保留演进，不在正文并列维护互相冲突的多套现状。
- **决策信息服务于当前路线**：决策、实施和后果只描述当前路线。淘汰路线仅在未选原因能帮助理解或复核当前决策时，于理由或取舍中出现一次，内容止于路线名称及其与决策标准冲突的原因；缺少原因或重复出现的淘汰路线陈述直接删除。
- 不得写入凭据、个人信息、正式环境敏感数据或安全绕过细节。
- 不得虚构接口、日期、负责人、状态或验收结果，也不要复制可由代码或生成器可靠产生的大段内容。

## 完成检查

- 提纲覆盖读者必须回答的问题，章节和篇幅符合最小充分原则。
- 结论、影响、证据和行动项只在适用的决策材料中齐备；真实存在的未知、矛盾和过期范围没有被写成确定事实。
- 范围由一个权威位置的纳入项和必要约束闭合，其他章节没有重复排除清单；决策、实施和后果以当前路线为主体，同一淘汰路线最多在理由或取舍中出现一次且包含复核价值；每项内容都提供事实、决定、原因或行动信息，空栏目已省略。
- 关键主张可追溯，引用与来源时效有效；同一解释没有形成竞争性副本。
- 受新事实影响的权威正文、摘要、导航和链接已经同步，文档仍描述当前状态。
