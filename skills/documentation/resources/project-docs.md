# 正式项目文档：维护当前权威事实

Use when 用户或项目规范要求长期保留需求、设计、接口、决策、项目状态或交付说明。选择已有权威位置和最小充分形态；普通功能请求不因未附规格就先创建一套文档。

| 读者的问题 | 适用内容 |
|---|---|
| 要解决什么、什么算完成 | 需求 / Issue：目标、当前事实、范围、可观察行为与验收；已有正式规格被选为实施依据且需要持续追溯时，才由 [execution](../../execution/SKILL.md) 选择规格驱动开发（Spec-Driven Development） |
| 系统会如何实现或被调用 | 设计 / 接口：选定方案、关键组件或数据流、使用方与提供方、输入输出、错误、鉴权和兼容边界 |
| 为什么选择当前路线 | 决策记录 / 简报：待决事项、影响、取舍与证据；被淘汰方案只有其未选原因有助于复核决定时出现一次 |
| 跨任务怎样继续 | 持续项目执行状态：当前阶段与证据时点、下一合法单元、进入门槛、已核验交付层级和安全停止点 |
| 外部使用方需要知道什么 | 发布说明 / 使用文档：可观察变化、兼容影响、升级或使用方式 |
| 项目入口怎样找到事实 | README / Wiki：具体组织与维护见 [wiki.md](wiki.md) |

按读者问题与稳定主题组织，优先修订现有内容，不把调查过程原样搬成正式正文；当前路线、实际范围与确有影响的未决项是主体。面向行动的决策简报可结论优先，说明与参考文档按读者的使用顺序组织，不强制同一模板。真实安全限制、负向行为和证据缺口保留准确措辞。

## 来源与维护

- 从当前代码、真实调用方、外部契约、已有文档与原始来源取证，标注影响结论的版本、日期、环境和适用范围；区分已确认事实、综合判断与仍无法裁决的冲突。关键主张和引用就近链接来源。
- 一个事实只在一个权威位置完整解释，其他摘要和导航链接到它。新证据改变当前理解时，同步本次变化直接影响的正文、摘要、交叉引用和链接；历史确有追溯价值时交给决策记录或变更记录。
- 长期目标跨多个独立任务、发布或环境推进且后续必须恢复决策时，维护一个状态入口；当前任务仍用临时计划或简短执行清单。每次进入新任务前重新核验随时间变化的 Git、CI、部署与环境事实。
- 不写凭据、个人信息、正式环境敏感数据或安全绕过细节，不虚构接口、负责人、状态或验收结果。结构与链接检查只证明对应结构，事实结论仍要对照来源。

完成时从读者任务核对答案、来源、时效、互相矛盾的权威副本和因本次变化失真的导航；没有新信息的章节与过程记录可以省略。
