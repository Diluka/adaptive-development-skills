# README 与 Wiki 知识维护方法

README 与 Wiki 都是正式项目知识的组织形态。项目根 README 是面向项目读者的精简入口，而不是必须承载全部知识的单文件边界；多页 Wiki 用于长期、互相链接、随新证据持续演进的项目知识。一次性说明、单一主题或已有一篇权威文档即可清晰承载时，不为形式建立 Wiki。

## 从 README 到多页 Wiki

项目根 README 至少让目标读者快速理解：项目是什么、为谁解决什么问题、为何或何时使用、如何开始、关键能力与边界，以及到深入权威文档的入口。它维护当前摘要和导航；“入口”是职责，不是单文件限制。

单个入口仍可清晰、易扫读时保持精简 README，并把实现细节、专题说明或完整参考链接到已有权威文档。出现多个稳定主题、独立阅读路径或维护边界时，把详情拆为互链页面或演进为多页 Wiki；README 继续作为项目总览和导航，不能因承担入口职责而持续堆长。

Wiki 目录自己的 `README.md` 只说明该知识库的范围、目标读者、来源边界、导航方式和维护约定；它不替代项目根 README 的项目介绍、最短上手、能力边界和全局导航职责。

## 三层知识边界

- **原始来源**：代码、契约、原始文档、研究材料和其他证据保留自身出处、日期、版本与适用范围，承担事实核验和追溯。
- **当前解释层**：README 或 Wiki 组织跨来源的当前最佳理解，区分事实与综合判断；实际存在且影响读者判断的争议、未知和已过期范围就近标明，不替代原始来源。
- **维护规则**：项目约定目录、命名、引用、索引、修订和健康检查方式；稳定模式形成后再调整，不把临时习惯写成固定仪式。

## 初始化或适配结构

先阅读现有 README、文档目录、命名、链接和项目说明，识别已有权威内容与读者路径；现有结构能够承载新知识时沿用并修订，不另建竞争性 Wiki。

首次建立持久多页 Wiki 时，只创建当前规模需要的导航和维护面。以下是可选的最小结构，不是固定目录契约：

```text
wiki/
├── README.md
├── index.md
├── log.md
└── topics/
```

- 已有导航足够时不创建 `index.md`；需要独立的内容总览时，索引只保存入口、短摘要和必要元数据。
- 只有来源摄取、查询沉淀和修订需要可追溯时间线时才创建 `log.md`；普通 README 不因此增加维护日志。
- 主题页或目录只在稳定知识边界和独立阅读路径形成后创建，不预造空分类。
- 路径、文件名和工具服从项目现有约定与真实规模，不强制使用 `wiki/`。

## 持续维护

### 摄取来源

1. 记录来源标题、出处、日期、版本和适用范围，区分原始事实与既有解释。
2. 提取与当前读者问题相关的事实、概念、关系、约束和结论，判断它是新增、强化、修正还是否定现有知识。
3. 修订最接近的权威位置；一个来源可以影响多个页面，一个页面也可以综合多个来源。
4. 同一事实的完整解释只维护一次，其他页面保留必要摘要并交叉引用。
5. 同步受影响的 README 摘要、索引和链接；仅在项目已采用日志或本次变化确需追溯时记录修订。

### 沉淀问题

先从当前 README、导航和相关权威页面建立知识范围，再回到需要核实的原始来源。回答区分事实与推断；具有长期复用价值的新综合写回最接近的权威位置，只有形成稳定主题、机制、阅读路径或维护边界时才新建页面。

### 修订、冲突与过期内容

新证据改变旧结论时，让权威正文表达当前最佳理解，并同步受影响的摘要、交叉引用和导航。比较来源的时间、版本、适用范围和权威性；无法裁决时保留冲突及所缺证据，不用无证据结论掩盖差异。

历史只有在理解决策或演进确有价值时才由原始版本、ADR、变更记录或适用的 Wiki 日志承担。已过期结论不继续冒充当前正文，也不为每次来源机械创建孤立摘要。

## 权威性、链接与去重

- 每个稳定主题保留一个权威解释位置；小规模时可以是 README 中的章节，不机械要求一个主题一个文件。
- 页面间链接表达依赖、上下位、演进、冲突、相似或证据关系；重复完整说明改为必要摘要加权威链接。
- 新知识优先融入现有页面；页面过重、读者路径分叉或维护边界独立时拆分，并从入口和相关页面补链接。
- 重命名、合并或删除页面前先更新入站链接和导航；索引描述当前结构，日志只记录变化，不成为事实权威。

## 健康检查

按本次变化和知识库真实风险检查：

- 被新证据推翻但仍在使用的结论、过期摘要和冲突命名；
- 同一主题的重复权威内容、缺少来源的关键主张和明显证据缺口；
- 失效链接、没有入口或入站链接的孤立页面，以及未同步的索引；
- 边界混乱、重复、过重或需要合并拆分的页面，特别是持续增长而未下沉详情的 README。

直接修订真实权威内容、导航和适用的维护记录，不另建迅速过期的平行问题清单。普通文件搜索和链接检查足够时保持简单；只有规模导致检索或关系检查明显失效时，再引入全文索引、结构化查询或图谱工具。

## 完成检查

- 项目根 README 仍是精简、可扫读的项目入口；需要独立阅读或维护的详情已拆到权威文档并能从入口到达。
- 新内容可从现有导航或相关页面找到；受影响的权威正文、摘要、交叉引用和入站链接已经同步。
- 关键事实可追溯到仍适用的原始来源；综合判断与事实清楚区分，实际存在的冲突、未知和过期范围已就近标明。
- 没有明显的重复权威内容、失效链接、孤立页面或因本次变化产生的未同步索引。
- `index.md`、`log.md` 或主题目录只在项目已采用或真实维护需要存在时更新，不为完成检查机械创建。
