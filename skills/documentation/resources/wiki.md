# README 与 Wiki：选择知识形态

Use when 项目入口已经难以让读者找到权威答案，或多个稳定主题需要各自维护；单个问题与单篇权威文档已足够时修订现有入口。

根 README 帮助读者判断项目是什么、如何开始，以及到哪儿查深入资料。项目现有 README 与文档结构能承载新内容时先更新它们；多个主题有独立阅读路径或维护周期时，再建立相互链接的页面或 Wiki，README 继续承担总览和导航。Wiki 自己的入口说明范围与导航，不复制项目上手正文。

## 取证并修订

1. 从当前入口、导航和相关权威页面找读者的问题，再回到代码、契约或原始材料核实。记录影响结论的来源、版本、日期与适用范围；区分原始事实、当前解释和无法裁决的争议。
2. 在最接近问题的权威位置更新完整解释，其他页面只保留必要摘要与链接；同步因本次变化失真的 README、索引及入站链接。历史按实际审计需要放在版本历史、决策记录或现有日志中，不为每次修改新建摘要。
3. 页面过重、读者路径分叉或维护边界独立时拆分并补导航；来源改变结论时让当前正文反映新事实，保留仍影响判断的未知与过期范围。

`index.md`、`log.md`、专题目录只是项目已有或实际需要时的可选组织方式，不是创建 Wiki 的必备文件。普通搜索和链接检查已经能让读者找到答案时，不引入索引服务或图谱工具。

完成时从项目入口走到权威答案，检查关键事实来源、失效链接、孤立页面和受本次变化影响的摘要；只修订实际失真的部分。
