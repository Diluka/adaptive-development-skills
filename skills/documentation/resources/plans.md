# 计划写作方法

计划只在降低协调、恢复或风险成本时落盘。需求、契约和新证据优先；用户或项目要求正式计划时遵循，首次需要时建立；短小任务不为形式补造计划。

决定保留调查产物时，停止扩展临时代码。准备保留的增量需要计划时，明确哪些内容保留、重写或删除。一开始就要求调查并实现时，调查只是适用计划中的一个工作单元。

计划的创建、更新、状态同步和处理评审意见都属于原任务，不递归产生新任务或新计划。位置规则见主技能正文（默认
`.docs/plans/YYYY-MM-DD-<task-slug>.md`）；长期保留时由正式文档方法（`project-docs.md`）整理进正式目录，临时过程记录不直接提交。

## 写出足够内容

按任务需要选择以下内容：

- 目标与预期结果；
- 任务范围；
- 主要步骤、依赖与状态；
- 验证方式；
- 风险、回退和仍需确认的事项。

任务范围优先列出纳入项、必要约束和最小同步；只有在用户明确否决相关方案，或相邻方案可能被合理误解为范围内且会改变实施、验收、授权或契约/兼容性判断时，才记录具体排除边界。

单元必须追溯到原始目标、明确需求、必要前置条件或既有伴生产物的最小同步，并保留调用方、环境、版本和行为范围。失真的伴生产物列入收尾，不扩展到新资料、无关章节或历史问题；计划不能为任务外问题取得授权。

计划只记录足以解释行动与判断的证据，不扩写流程。为定向行为测试记录独立判据来源和具体回归风险；选择快照时，记录真实生成路径、稳定范围和差异审阅方式；评估模糊结果时，记录共享目标、样例或评价边界。

采用多代理协作时，再补充各角色的产出、读写范围、依赖和回报目标。把实现与验证拆成并行单元时，记录双方共同读取的需求或规格、验证所经真实入口、各自文件与运行资源和组合验证。验证工作不从预计实现步骤反推测试清单。

复杂或高风险任务再补充关键事实与假设、决策点、风险、回退、新增副作用、分工、交付安排和仍需取得的授权。可以标注待探索范围，但不得编造文件、接口、行号或依赖行为。

## 决定是否等待确认

原请求已授权目标、范围和交付，无关键歧义，风险受控且操作已授权时，告知计划位置后执行。除下节阻塞前置条件外，偏离已授权语义、范围或交付，关键歧义，高风险/难回退，正式环境或非普通
Git 外写，权限扩大或新增副作用时先说明并确认。计划本身不扩大用户授权。

## 处理阻塞前置条件

必要前置条件先非阻塞询问其证据、最小边界、风险和默认方案，同时继续无依赖工作。未回复时，仅当方案受需求、调用方或契约约束，不改目标和交付、可逆、授权内，且不含取舍、高风险/难回退、正式环境、非普通
Git 外写、权限扩大或重大副作用，才纳入计划；否则只暂停该路径。

## 对齐与修正

多上下文时记录负责人、会话角色、读写范围、依赖、共享状态、进展、待决事项和回报目标。由一个协调者维护唯一计划，执行者只读相关段或快照并回报。使用多个工作树时，跨树传路径前确认可访问。

执行中新事实影响计划时：

- 目标、范围、业务行为、交付结果和授权不变，且没有新增副作用：更新计划，告知用户后继续；
- 新事实表明既有伴生产物会因本次变更失真：把最小同步补入收尾工作；仍满足直接执行条件时继续，否则请求确认并只暂停该同步路径，不按任务外发现处理；
- 新事实是阻塞当前任务的必要前置条件：按上节进行非阻塞询问，并在符合默认纳入条件且用户未及时回复时更新计划后继续；
- 改变上述任一边界或需要新授权：记录拟议调整，暂停相关实现并请求确认。

计划外问题先排除受影响伴生产物；其余仅在阻塞当前任务时按上节处理，否则只报告。
