# 计划写作方法

计划在用户或仓库明确要求、任务内容复杂或高风险，或者实际需要跨单元协调、跨会话恢复或高风险控制时落盘；落盘与否及级别由
[adaptive-development-workflow](../../adaptive-development-workflow/SKILL.md)
判断。满足其直接作业判据时立即开工，多步骤最多维护简短执行清单。需求、契约和新证据优先；用户或项目要求正式计划时遵循，升级首次满足条件才建；纯调查不需开发计划，也不为已完成的微小任务补造仪式。代理数、会话数、工作树、计划篇幅和验证数量不改变任务级别；仅为提速使用子代理时沿用当前单元的简短执行清单。

决定保留调查产物时，停止扩展临时代码。准备保留的增量需要计划时，明确哪些内容保留、重写或删除。一开始就要求调查并实现时，调查只是适用计划中的一个工作单元。

计划的创建、更新、状态同步和处理评审意见都属于原任务，不递归产生新任务或新计划。位置规则见主技能正文（默认
`.docs/plans/YYYY-MM-DD-<task-slug>.md`）；长期保留时由正式文档方法（`project-docs.md`）整理进正式目录，临时过程记录不直接提交。

计划只记录已经完成选择的内容。可实施逻辑追溯到明确需求、真实调用方、已核验契约、已观察问题，或通过 Execution 统一门禁的必要技术前置；候选及其比较由讨论或专门决策材料承载，完成选择后进入工作单元、验收、测试和评审安排。实施计划的内容边界止于已选择的当前路线；产品行为、公共契约和架构方向均在进入计划前完成选择。

## 写出足够内容

计划至少包含：

- 目标与预期结果；
- 纳入范围、必要约束和最小同步；
- 工作单元及各自的主要开发方法；
- 实际采用的验证方式。

独立评审适用、被明确要求，或省略评审的决定本身需要审计时，再记录所覆盖的风险、依据和安排。

任务范围在本节作为唯一权威定义，由穷尽的授权编辑集合、必要约束和最小同步闭合。用户列出的排除路径已经由该集合完整承载时，省略这些路径的名称；确有未被集合表达且会改变实施、验收、授权或契约 / 兼容性判断的边界时，补充其具体影响。后续工作单元、验证和完成标准引用本节，或用“实际变更集合属于授权集合”核对结果。

单元必须追溯到原始目标、明确需求、已选择的设计、通过 Execution 门禁的必要技术前置或既有伴生产物的最小同步，并保留调用方、环境、版本和行为范围。失真的伴生产物列入收尾，不扩展到新资料、无关章节或历史问题；计划不能为任务外问题取得授权。

计划只记录足以解释主要方法的证据，不扩写流程。风险、测试、调查和评审项分别追溯到明确需求、真实调用方、已核验契约、已观察问题或必要技术前置；通用可能性只在已有直接事实使其成为当前合理风险时进入计划。为定向行为测试记录独立判据来源和具体回归风险；选择快照时，记录真实生成路径、稳定范围和差异审阅方式；评估模糊结果时，记录共享目标、样例或评价边界。直接实现不需要为了形式完整制造测试。

采用多代理协作时，再补充各角色的产出与独立读写范围。把实现与验证拆成并行单元时，还要记录双方共同读取的需求或规格条目、已确认行为与契约、验证所经真实入口及可观察结果、各自文件与运行资源、独立性依据和组合验证。验证工作不从生产组件或预计实现步骤反推测试清单。

复杂或高风险任务按实际风险补充依赖顺序、关键事实、具体风险、回退边界、分工、评审深度和交付安排；真实存在且影响后续决定时，再记录假设、决策点、新增副作用和仍需取得的授权。常规任务以直接验证依据收敛即可。可以标注待探索范围，但不得编造文件、接口、行号或依赖行为；空栏目直接省略。

完成初稿后按主技能的否定标记检查逐句审阅。用户原话中的排除要求已经由授权集合完整承载时，省略对应对象名称；执行约束、工作单元、验证、完成标准和交付说明引用授权集合或核对实际集合。纯粹表示某路径、方法、阶段或风险未被采用的句子直接删除。

用户以否定形式表达普通范围和操作时，先提取正向意图；最终计划只留下对应的授权集合、现有形态、权威位置、保全契约或适用栏目。正向主句已经完整承载信息时，句子在主句处结束。常见转换：

- 路径边界：授权编辑集合为指定路径；
- 形态保持：沿用现有文档形态；
- 临时协调：执行清单存放在临时计划中；
- 权威去重：后续章节引用唯一权威说明；
- 约束保全：保留安全、授权和真实行为契约；
- 内容保全：成熟方法保留完整核心循环；
- 元数据职责：元数据只描述触发条件；
- 状态保全：保留用户和其他任务的既有改动；
- 按需组织：只生成适用栏目；
- 范围核对：实际变更集合属于授权集合；
- 评审收敛：影响交付的评审发现均已有处理结论与证据。

定稿后只扫描最终计划正文：普通范围、过程和路线排除的否定标记计数为零；保留的每个否定标记都能对应必要红线、真实负向契约、证据缺口或一处有因决策记录。扫描发现普通否定标记时，按上表转换并重新扫描。

## 决定是否等待确认

原请求已授权目标、范围和交付，无关键歧义，风险受控且操作已授权时，告知计划位置后执行。除下节阻塞前置条件外，偏离已授权语义、范围或交付，关键歧义，高风险/难回退，正式环境或非普通
Git 外写，权限扩大或新增副作用时先说明并确认。计划不改变
[adaptive-development-workflow](../../adaptive-development-workflow/SKILL.md)
的交付和高影响操作边界。

## 记录必要技术前置

Execution 已按直接必要性、原目标专属性、既定契约 / 架构 / 授权 / 风险、同组验收以及 `100` 行 / `3` 文件阈值确认可自行继续时，把该前置及其证据加入适用工作单元。执行中确认将超过任一阈值时，记录新增事实、暂停点和拟议拆分；拆分选择明确后恢复对应路径，其他依赖就绪的工作继续维护。

## 对齐与修正

多上下文时记录负责人、会话角色、读写范围、依赖、共享状态、进展、待决事项、直接上级回报目标，以及是否存在“无需回复”的任务管理权移交；临时会话（侧边会话）的关系按用户安排记录。单任务由根代理、多任务由协调任务维护唯一计划，执行者只读相关段或快照并按派发协议回报。工作树边界由
[using-git-worktrees](../../using-git-worktrees/SKILL.md)
判断；跨树传绝对路径前确认可访问。

执行中新事实影响计划时：

- 新事实只修正已选方案内的实现细节，且目标、范围、业务行为、公共契约、架构边界、风险、交付结果、授权和副作用保持一致：更新计划，告知用户后继续；
- 新事实表明既有伴生产物会因本次变更失真：把最小同步补入收尾工作；仍满足直接执行条件时继续，否则请求确认并只暂停该同步路径，不按任务外发现处理；
- 新事实是阻塞当前任务的必要技术前置：通过 Execution 门禁时更新计划后继续；达到拆分边界时记录新增事实和暂停点；
- 改变上述任一边界或需要新授权：记录拟议调整，暂停相关实现并请求确认。

计划外问题先排除受影响伴生产物；其余仅在阻塞当前任务时按上节处理，否则只报告。
