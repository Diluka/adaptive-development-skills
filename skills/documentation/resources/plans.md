# 临时计划：只承载已选工作

Use when 用户或仓库明确要求计划，或当前工作确需跨单元协调、难回退操作与跨会话恢复；事实已充分、可直接实施时使用简短执行清单即可。

计划不是把一句话需求变成规格的步骤，也不替用户决定业务行为或公共契约。起草前确认目标、已知调用方和契约、授权范围，以及哪种未知会改变方案；关键产品选择先澄清，技术未知先按最小证据调查。没有关键缺口时按已选路线执行，不为方法的前置形式补造产物。

记录足以支撑协作和复核的内容：

- 目标结果、已授权范围与需要保持的行为；
- 已选工作单元、真实依赖和负责人（适用时）；
- 能从真实入口观察的完成信号，以及本仓库强制检查；
- 实际存在的风险、未决决定、回退边界或额外授权（适用时）。

先检查项目现有计划位置；默认使用被 Git 忽略的 `.docs/plans/YYYY-MM-DD-<task-slug>.md`。只有一个版本承担当前协调状态，委派执行者读取相关单元或不可变快照，不并发改全局计划。长期目标确需在当前任务结束后恢复时，把已核验状态与下一合法工作单元整理到 [正式项目文档](project-docs.md)；临时草稿不自动变成版本控制产物。

新事实只影响选定路线的实现细节时更新相应步骤并继续；会改变用户可见行为、契约、范围、授权或副作用时暂停受影响路径，说明缺少的决定后再继续。计划不是二次批准，用户已授权且边界清楚时不重复询问。期末核对实际变更与授权范围、当前证据及剩余未决事项；保留安全限制和真实负向契约的准确原话，不对否定词做配额或机械改写。
