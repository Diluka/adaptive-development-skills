# 计划写作方法

计划只在降低协调、恢复或风险成本时落盘；落盘与否及级别由
[adaptive-development-workflow](../../adaptive-development-workflow/SKILL.md)
判断。需求、契约和新证据优先；用户或项目要求正式计划时遵循，升级首次满足条件才建；纯调查不需开发计划，也不为已完成的微小任务补造仪式。

决定保留调查产物时，停止扩展临时代码。准备保留的增量需要计划时，明确哪些内容保留、重写或删除。一开始就要求调查并实现时，调查只是适用计划中的一个工作单元。

计划的创建、更新、状态同步和处理评审意见都属于原任务，不递归产生新任务或新计划。位置规则见主技能正文（默认
`.docs/plans/YYYY-MM-DD-<task-slug>.md`）；长期保留时由正式文档方法（`project-docs.md`）整理进正式目录，临时过程记录不直接提交。

## 写出足够内容

计划至少包含：

- 目标与预期结果；
- 纳入范围、必要约束和最小同步；
- 工作单元及各自的主要开发方法；
- 实际采用的验证方式。

独立评审适用、被明确要求，或省略评审的决定本身需要审计时，再记录所覆盖的风险、依据和安排。

任务范围在本节作为唯一权威定义，由穷尽的授权编辑集合、必要约束和最小同步闭合。用户列出的排除路径已经由该集合完整承载时，省略这些路径的名称；确有未被集合表达且会改变实施、验收、授权或契约 / 兼容性判断的边界时，补充其具体影响。后续工作单元、验证和完成标准引用本节，或用“实际变更集合属于授权集合”核对结果，不重复列出排除项。

单元必须追溯到原始目标、明确需求、必要前置条件或既有伴生产物的最小同步，并保留调用方、环境、版本和行为范围。失真的伴生产物列入收尾，不扩展到新资料、无关章节或历史问题；计划不能为任务外问题取得授权。

计划只记录足以解释主要方法的证据，不扩写流程。为定向行为测试记录独立判据来源和具体回归风险；选择快照时，记录真实生成路径、稳定范围和差异审阅方式；评估模糊结果时，记录共享目标、样例或评价边界。直接实现不需要为了形式完整制造测试。

采用多代理协作时，再补充各角色的产出与独立读写范围。把实现与验证拆成并行单元时，还要记录双方共同读取的需求或规格条目、已确认行为与契约、验证所经真实入口及可观察结果、各自文件与运行资源、独立性依据和组合验证。验证工作不从生产组件或预计实现步骤反推测试清单。

复杂或高风险任务按实际风险补充依赖顺序、关键事实、具体风险、回退边界、分工、评审深度和交付安排；真实存在且影响后续决定时，再记录假设、决策点、新增副作用和仍需取得的授权。常规任务以直接验证依据收敛即可。可以标注待探索范围，但不得编造文件、接口、行号或依赖行为；空栏目直接省略。

完成初稿后按主技能的否定标记检查逐句审阅。用户原话中的排除要求已经由授权集合完整承载时，省略对应对象名称；执行约束、工作单元、验证、完成标准和交付说明引用授权集合或核对实际集合。纯粹表示某路径、方法、阶段或风险未被采用的句子直接删除。

用户以否定形式表达普通范围和操作时，先提取正向意图；最终计划只留下对应的授权集合、现有形态、权威位置、保全契约或适用栏目。同一句已有对应的正向陈述后，省略排除对象及其名称。常见转换：

- 路径边界：授权编辑集合为指定路径；
- 形态保持：沿用现有文档形态；
- 临时协调：执行清单存放在临时计划中；
- 权威去重：后续章节引用唯一权威说明；
- 约束保全：保留安全、授权和真实行为契约；
- 按需组织：只生成适用栏目；
- 范围核对：实际变更集合属于授权集合。

## 决定是否等待确认

原请求已授权目标、范围和交付，无关键歧义，风险受控且操作已授权时，告知计划位置后执行。除下节阻塞前置条件外，偏离已授权语义、范围或交付，关键歧义，高风险/难回退，正式环境或非普通
Git 外写，权限扩大或新增副作用时先说明并确认。计划不改变
[adaptive-development-workflow](../../adaptive-development-workflow/SKILL.md)
的交付和高影响操作边界。

## 处理阻塞前置条件

必要前置条件先非阻塞询问其证据、最小边界、风险和默认方案，同时继续无依赖工作。未回复时，仅当方案受需求、调用方或契约约束，不改目标和交付、可逆、授权内，且不含取舍、高风险/难回退、正式环境、非普通
Git 外写、权限扩大或重大副作用，才纳入计划；否则只暂停该路径。

## 对齐与修正

多上下文时记录负责人、会话角色、读写范围、依赖、共享状态、进展、待决事项、直接上级回报目标，以及是否存在“无需回复”的任务管理权移交；临时会话（侧边会话）的关系按用户安排记录。单任务由根代理、多任务由协调任务维护唯一计划，执行者只读相关段或快照并按派发协议回报。工作树边界由
[using-git-worktrees](../../using-git-worktrees/SKILL.md)
判断；跨树传绝对路径前确认可访问。

执行中新事实影响计划时：

- 目标、范围、业务行为、交付结果和授权不变，且没有新增副作用：更新计划，告知用户后继续；
- 新事实表明既有伴生产物会因本次变更失真：把最小同步补入收尾工作；仍满足直接执行条件时继续，否则请求确认并只暂停该同步路径，不按任务外发现处理；
- 新事实是阻塞当前任务的必要前置条件：按上节进行非阻塞询问，并在符合默认纳入条件且用户未及时回复时更新计划后继续；
- 改变上述任一边界或需要新授权：记录拟议调整，暂停相关实现并请求确认。

计划外问题先排除受影响伴生产物；其余仅在阻塞当前任务时按上节处理，否则只报告。
