# Documentation：按读者问题维护文档

写文档是为了让读者完成决定、使用、协作或恢复任务，不是给一句话开发请求补齐形式规格。用户或项目明确要求长期保留时维护正式文档；跨单元协调、难以回退或跨会话恢复确有收益时使用临时计划。需求、真实调用方、契约与新证据优先于已有文字，文档不凭空产生授权或批准状态。

| 当前需要 | 选择的形态 |
|---|---|
| 协调已选工作的步骤和证据 | 按需读取 [临时计划](resources/plans.md)，任务结束后可丢弃 |
| 长期共享需求、设计、接口、决策或项目进度 | 按需读取 [正式文档](resources/project-docs.md)，修订已有权威位置 |
| 项目入口或多个长期知识主题 | 按需读取 [README / Wiki](resources/wiki.md)，单篇已够用时不建立知识库 |

先确认读者要回答的问题与事实来源，选择最小充分的正文。一个稳定事实只在一个权威位置完整解释；其他地方只给必要摘要和链接。决策材料可说明真正影响选定路线的备选及理由，真实负向行为、安全与权限限制照实写，不以固定栏目、否定词数量或字数代替内容准确性。关键事实、版本、时效、冲突和仍未知的范围保持可追溯；不虚构接口、日期、状态或验收结果，也不写凭据及正式环境敏感信息。

用户指定位置优先，其次项目现有规范；默认正式资料放在 `docs/`，临时计划放在被忽略的 `.docs/plans/`。正式文档准备纳入版本控制时遵循开发任务的交付边界；临时草稿与调查记录不因写了文件就自动提交。若决定长期保留临时成果，按实际内容核对授权、证据和最小同步后再整理到正式位置。

完成时核对读者问题是否能从入口找到权威答案、引用和链接是否仍适用、当前变化是否使已有伴生说明失真；结构或格式检查不能代替事实核验。
