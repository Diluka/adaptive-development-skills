# 文档

写文档是为了让读者完成决定、使用、协作或恢复任务，**不是给一句话开发请求补齐形式规格**。用户或项目明确要求长期保留时才维护正式文档。需求、真实调用方、契约与新证据优先于已有文字。

- 用户指定位置优先，其次项目现有规范。一个稳定事实只在**一个权威位置**完整解释，其他地方只给摘要与链接；优先修订已有权威位置，不新建职责重叠的文件。
- 从当前代码、真实调用方、外部契约与原始来源取证，标注影响结论的版本与适用范围，区分已确认事实、综合判断与仍无法裁决的冲突。
- 真实负向行为、安全与权限限制照实写；不虚构接口、日期、状态或验收结果，不写凭据及正式环境敏感信息。
- 临时草稿与调查记录**不因写了文件就自动提交**；决定长期保留时核对授权与证据后再整理到正式位置。

完成时核对读者能否从入口找到答案、引用与链接是否仍适用、本次变化是否使既有说明失真。格式与链接检查不能代替事实核验。
