# 管理证据

## 职责

把结论映射到最小反证，复用仍适用的证据、只补缺口，并收敛值得长期保留的测试和观测。本技能只管充分性、复用和收敛，不竞争主要方法或成为必经门；测试方式由 [choosing-tests](../choosing-tests/SKILL.md)、专项方法闭环由各自技能负责。

## 明确待证明结论

对每项待证明结论，说明：

- 必需结果或不变量及其权威来源；
- 真实调用方、输入结构、环境和相关依赖契约；
- 当前变化可能引入的具体错误；
- 哪个观察会推翻“实现正确、行为保持或可交付”的判断。

证据冲突时，按需求和不变量 > 真实调用方与运行行为 > 依赖和协议契约 > 实现与测试判断。测试基于不存在的调用方、错误契约或内部细节时，修正或删除测试；实现违反更高优先级事实时，修正实现。

## 从需求派生证据

从权威需求/约束映射真实调用方可观察的结果、边界和失败风险；记录来源、真实入口、待拒绝错误和独特失败信号。实现步骤只帮助找接缝，不能定义必证行为；同一风险已有需求级证据时，除非低层有独立规则、失效面或定位价值，不再追加。

## 选择证据与方法

| 待证明结论或风险形状 | 首选证据或方法 |
|---|---|
| 确定性行为有独立稳定判据和具体回归风险 | 最低真实接缝上的定向行为测试 |
| 稳定不变量能由类型系统显著排除非法表示，且类型建模本身有独立收益 | [type-driven-design](../type-driven-design/SKILL.md)，静态检查证明类型约束，运行时证据只覆盖剩余风险 |
| 广泛输入空间有独立属性、不变量、变形关系或参考模型 | [property-based-testing](../property-based-testing/SKILL.md) |
| 可协作的消费者与提供者需要持续证明版本兼容 | [consumer-driven-contract-testing](../consumer-driven-contract-testing/SKILL.md) |
| 旧行为/稳定输出的可审阅比较，或概率、主观输出的代表任务与重复评估 | [baseline-and-eval-testing](../baseline-and-eval-testing/SKILL.md) |
| 已知业务行为需要跨角色示例和可执行验收规格 | [behavior-driven-development](../behavior-driven-development/SKILL.md) |
| 已指定的声明式数据、映射、提示词或文案，没有改变解释逻辑 | 直接实现、差异审阅并复用现有检查；有真实缺口时验证使用方行为，不复制目标字面量 |
| 分支同步或机械冲突未改变运行语义 | 审阅冲突与最终差异、确认无冲突标记，并查看最终集成结果的 CI |
| 单个真实环境或完整装配边界风险 | 可重复的集成、端到端或冒烟观测 |

第三方边界未知时拆 [contract-verification](../contract-verification/SKILL.md)，症状根因未知时用 [systematic-debugging](../systematic-debugging/SKILL.md)；调查只交付事实，正式变更回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 重新选法。

## 判断证据是否独立

新增测试须来自需求、真实调用方或契约，保留真实接缝、能拒绝合理错误且覆盖值得长期保护的风险；从待写字面量或当前实现复制的断言不独立，除非精确内容本身是外部契约。没有新增反证或定位价值时不追加。

## 使用静态证据

严格配置和真实使用位置已证明的约束不重复测；记录工具链版本、配置、命令和范围。公共或复杂类型 API 有兼容风险时才保留少量 intended-valid / intended-invalid 编译用例。

静态检查是证据，不是开发方式。稳定不变量需主动类型建模时用 [type-driven-design](../type-driven-design/SKILL.md)；普通字段或字面量直接实现并运行既有静态检查。外部输入先运行时解析；类型不能证明副作用、算法、并发、时间、性能或概率质量，仍须取相应运行时证据。

## 复用既有证据

记录证据适用的输入、环境、版本、路径和风险；条件未变则复用，仅使受影响结论失效。最终推送或合并结果的 CI 是组合证据；本地检查只为更早发现风险、补 CI 缺口或建立必要基线，且必须能拒绝合理错误。

## 行为保持型工作

涉及业务逻辑、状态变化、公共契约或框架边界的行为保持型重构，在改动前必须有能发现核心行为漂移的证据：

1. 列出必须保持的核心行为、真实入口和失败影响。
2. 运行并复用经过受影响路径、断言可观察结果的已有测试或观测。
3. 仍有缺口时，按结果形状选择最小定向测试、[baseline-and-eval-testing](../baseline-and-eval-testing/SKILL.md) 或可重复冒烟；在旧实现上确认基线。
4. 修改后以相同入口、环境和输入再次运行并比较。
5. 只有能由已确认需求解释的差异才可接受；其余差异表示行为保持尚未证明。

旧实现上的通过基线只证明当前行为能在既定条件下复现。构建、类型检查、无关测试、模拟调用次数和代码审查可以补充，但不能单独证明核心业务行为保持。无法建立测试或可比较观测时，缩小单元、先建立真实接缝或暂停对应重构。

## 选择证据层级

| 风险边界 | 首选证据 |
|---|---|
| 纯确定性规则 | 最低真实接缝上的示例测试或属性测试 |
| 框架绑定、序列化、装饰器或中间件 | 真实框架模块或集成测试 |
| SQL、事务或持久化映射 | 可丢弃的本地或测试数据库集成 |
| 稳定但逐项断言成本高的输出 | 特征/批准基线中的最小可审阅范围 |
| 完整且接近生产的调用链 | 窄范围端到端测试或可重复冒烟 |
| 正式环境发布后的剩余风险 | 只读生产观测；需要受控暴露时使用 [delivery](../delivery/SKILL.md) |

通常从能保留待验证行为的最低真实接缝取证；只有较低层接缝会抹掉待验证行为时才向上移动。不同层级若覆盖不同失效面可以并存，不能用大量低层测试冒充真实框架、传输、持久化或部署边界。

独立验证明确安排“从顶层链路开始”时，先从受影响的真实调用方中找出能覆盖目标风险的最高入口，并在该入口定义可观察结果，再按失败定位需要补充更低层证据。这里的顶层是与当前结论相称的公共或装配边界，不自动等于跨越全部服务、数据库和外部依赖的完整端到端环境。最高入口没有独特失败信号、会引入无关不稳定性，或较低真实接缝已经能推翻同一结论时，保留较低层证据即可。

## 保持接缝真实

只替换时钟、网络、进程、随机性或不可用服务等真实边界；保留业务不变量及被验证的框架、解析、序列化和持久化真实。不得 mock 被测单元、增设生产测试钩子或以协作者次数代替可观察结果，除非该次数本身是外部副作用契约。

## 收敛最终证据组合

把新增和受影响的长期证据映射到稳定需求/不变量、调用方、回归风险和失败信号。保留核心契约、历史缺陷、边界或副作用保护；合并无新输入、边界或定位价值的同层重复；删除只锁定淘汰实现或无业务意义内部细节的测试。暂定 rubric、一次性探索记录和本地随机缓存不成确定性契约；删除后重验组合。成本高不等于可删关键保护；必要时仅在隔离、可恢复环境中做临时故障注入或变异测试，不留生产钩子。

## 报告证据边界

报告命令或观测、输入环境、结果、直接结论和未覆盖风险。格式/引用检查和单次代理模拟只证明结构或样例，不外推为真实运行或普遍效果。
