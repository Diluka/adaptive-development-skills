# Caller-Driven Cleanup：基于调用方的清理

## 核心原则

删除安全性来自调用方与加载影响面证明，不来自为了失败测试发明新行为。删除最小但完整的单元，并验证剩余系统。

## 映射删除影响面

从待删除符号、文件、包、路由、任务或配置键开始，检查：

- 静态导入、导出、再导出、别名与生成入口；
- 依赖注入标记、装饰器、反射、注册表与插件加载；
- 动态导入、字符串键、配置、脚本、任务、迁移与模板；
- 清单文件、锁文件、对等依赖、构建配置与发布文件；
- 表示真实受支持用法的测试或文档，而不是历史内部细节；
- 可疑路径是否仍服务旧调用方的仓库历史。

若仓库提供语义索引或调用图能力，先用它定位符号与调用方，再用源码搜索、依赖检查和运行时证据补足动态影响面。

## 分类引用

| 引用 | 操作 |
|---|---|
| 活跃生产调用方 | 删除前保留或迁移 |
| 存在外部使用方的公共 API | 先建立兼容或发布边界 |
| 框架或运行时注册 | 在启动或加载证据否定前视为仍在使用 |
| 测试真实契约的测试 | 与迁移后的调用方一起更新 |
| 仅测试已删除内部实现的测试 | 与实现一起删除 |
| 过时文档、测试夹具、快照或锁文件条目 | 作为同一完整单元删除 |

未知动态使用不是死代码证明。用配置、只读遥测、历史或明确发布假设解决，并保持正式环境证据范围窄且不泄露敏感值。

若无法排除公共 API 的外部使用方，应停在证据缺口。可能的发布边界不等于获准执行破坏性发布、移除兼容代码或改变外部状态。

## 删除与验证

1. 记录活跃调用图与预期保留行为。
2. 删除只属于无效路径的实现、导出、注册、测试、文档与依赖条目。
3. 使用包管理器的正常移除和解析流程，不要只手改锁文件。
4. 按需运行类型检查、构建或启动、保留调用方的定向测试与公共导出检查。
5. 审查差异中的孤立兼容分支与无关改动。

除非已验证调用方需要迁移窗口，不得添加包装层、回退分支、弃用别名或生产代码选项。

## 示例

删除适配器前同时追踪静态引用与运行时注册。若只有过时内部测试引用它，而当前生产调用方已经使用替代实现，则一起删除适配器和对应测试，再验证保留的调用链与构建；不要为了测试重新创建适配器。

## 常见错误

- 只搜源码导入，遗漏运行时注册。
- 保留唯一目的为维护已删除内部实现的测试。
- 删除仍是必需对等依赖或 CLI 二进制来源的直接依赖。
- 为假想使用方添加兼容代码。
- 未检查已发布导出范围就宣称清理安全。
