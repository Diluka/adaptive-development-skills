# 交付分支

## 交付范围由可逆性决定

- **跨边界或不可逆的增量**：按仓库约定创建或使用分支、提交、推送，并根据 `git remote` 的实际远端在 GitLab 创建 MR 或在 GitHub 创建 PR；创建后立即报告链接与当前 CI 状态，再等待该提交的全部自动任务进入终态。
- **都不成立的增量**：只暂存范围内文件、本地提交并报告差异；不推送、不创建 MR、不等 CI，除非用户要求。

用户明确限制本地 / 提交 / 推送 / PR 时逐项遵守，并准确报告本地与远端分别包含什么，**不声称未执行的内容已经交付**。

## 不硬编码

目标分支、平台、分支前缀、提交约定、Draft/Ready、指派与模板都以**当前仓库的实际配置**为准，不从硬编码名称或任一远端猜测，不把其他仓库的习惯泛化过来。

## 保留

只暂存和提交当前任务文件，保留用户及其他任务的改动与无关未提交文件。不使用强制推送，不执行破坏性重置、宽泛删除分支或移除工作树。措辞重要时先预览 MR/PR 标题、正文与目标分支。

## 授权边界

合并、创建版本发布、发布制品、主动环境变更、正式环境部署、正式环境写入、权限修改与破坏性 Git 操作需用户明确要求。交付完成不等于合并、发布或部署。

## 冲突

把冲突解决作为当前增量单独判断，不继承整个分支或 MR/PR 的复杂度：机械文档或元数据冲突只需审阅解决差异、确认没有冲突标记，不重跑原功能的完整回归；运行代码、公共契约或依赖发生重叠时，只让相关证据失效并运行覆盖该交互的定向检查。CI 已覆盖相同检查时不重复本地执行。
