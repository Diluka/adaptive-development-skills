# 交付分支

## 先确认交付约定

用户对当前任务明确指定的交付方式优先于仓库与本技能的默认规则，后续补充或修正继续生效；只调整涉及的步骤，不重复索取已有授权。未指定的部分沿用仓库约定；仓库也无约定时，需保留的开发变更默认完成分支、提交、推送与 MR/PR。只交付事实的调查不产生 Git 交付。

交付前核对实际差异与适用的验证、CI 和评审证据；复用仍适用的结果，只补失效或缺失的部分。

交付包含 MR/PR 时，根据实际 `git remote` 创建，立即报告链接与当前 CI 状态，并等待最终推送提交的全部自动任务进入终态；手动可选任务不阻塞。用户另有等待要求时遵循其要求。交付步骤不决定是否需要评审、隔离或追加检查。

准确报告本地与远端分别包含什么，**不声称未执行的内容已经交付**。

## 不硬编码

目标分支、平台、分支前缀、提交约定、Draft/Ready、指派与模板都以**当前仓库的实际配置**为准，不从硬编码名称或任一远端猜测，不把其他仓库的习惯泛化过来。

## 保留

只暂存和提交当前任务文件，保留用户及其他任务的改动与无关未提交文件。不使用强制推送，不执行破坏性重置、宽泛删除分支或移除工作树。措辞重要时先预览 MR/PR 标题、正文与目标分支。

## 授权边界

交付完成不等于合并、发布或部署；高影响操作与正式环境禁写遵循 [代码与契约安全](../code-and-contract-safety/SKILL.md)，交付约定不扩大授权。

## 冲突

把冲突解决作为当前增量单独判断，不继承整个分支或 MR/PR 的复杂度：机械文档或元数据冲突只需审阅解决差异、确认没有冲突标记，不重跑原功能的完整回归；运行代码、公共契约或依赖发生重叠时，只让相关证据失效并运行覆盖该交互的定向检查。CI 已覆盖相同检查时不重复本地执行。
