# 交付分支

## 确认交付约定

用户对当前任务明确指定的交付方式优先于仓库与本技能的默认规则，后续补充或修正继续生效；按指定范围落实相关步骤。用户未指定的部分沿用仓库约定；仓库也无约定时，需保留的开发变更默认完成分支、提交、推送与 MR/PR。只交付事实的调查以事实与证据作为交付物；Git 交付用于需保留或集成的开发变更。

交付前核对实际差异与适用的验证、CI 和评审证据；复用仍适用的结果，只补失效或缺失的部分。

交付包含 MR/PR 时，根据实际 `git remote` 创建，立即报告链接与当前 CI 状态，并等待最终推送提交的全部自动任务进入终态；手动可选任务无需等待，流水线内自动 review 环境任务纳入等待范围。用户另有等待要求时遵循该要求。交付步骤与评审、隔离及追加检查分别判断。

准确报告本地与远端分别包含的内容，使交付状态与实际执行一致。

## 依照仓库配置

目标分支、平台、分支前缀、提交约定、Draft/Ready、指派与模板均依据**当前仓库的实际配置**选择。

## 保留工作状态

暂存和提交范围限定为当前任务文件，用户及其他任务的改动和无关未提交文件保持原状。推送使用保留远端历史的常规更新，改动通过新提交交付；强制推送始终禁用。交付过程保留现有工作树与分支状态，破坏性重置、宽泛删除分支和移除工作树均排除在交付操作之外。措辞重要时先预览 MR/PR 标题、正文与目标分支。

## 授权边界

合并、创建版本发布、发布制品、主动环境变更、正式环境部署、正式环境写入、权限修改与其他高影响 Git 操作需用户明确要求。执行交付流程时，强制推送、破坏性重置、宽泛删除分支与移除工作树均禁用。交付流程完成后，按授权范围报告交付状态。

## 处理冲突

把冲突解决作为当前增量单独判断，并依据受影响范围选择检查。机械文档或元数据冲突通过审阅解决差异并确认冲突标记已清除；运行代码、公共契约或依赖发生重叠时，更新受影响证据并执行覆盖该交互的定向检查。CI 已覆盖相同检查时，复用该结果。
