# 受控探索未知

## 核心原则

用可丢弃的试验与会话回答未知，不提前编写正式实现，也不在同一工作单元内实现修复。技术探索（technical spike）回答明确的可行性、性能或集成未知；探索性测试（exploratory testing）考察可运行系统的行为和风险。两者都只交付结论与证据。

只在盘点当前上下文（包括同一会话）已有结论、证据、支持的推导和适用条件后仍有真实未知时开始探索。用户本人未知或使用“调查、求证”等动作词不等于代理仍未知；已有事实直接回答问题，或通过已确认不变量足以可靠推出答案时直接报告。用户明确要求新的实验、探索会话或记录时，把该过程或产物作为目标，并保持约定的范围与停止条件。

本方法也可承载 Execution 在当前节点发起的自发轻量探测：使用隔离、可丢弃 demo，并继承同一证据问题累计五分钟的预算。用户原请求、既定计划或 Workflow 建立的正式调查单元使用任务约定的时间盒。

## 定义与运行试验（Technical Spike）

开始前写清：一个决策问题；最小且有代表性的输入和环境；成功、失败和无法判断时各会观察到什么；时间或范围边界，以及禁止的副作用和原型的丢弃方式。

先检查确切的已安装依赖或现有运行时证据；适用条件未变且已有证据能回答决策问题时，记录结论并结束。仍有真实未知时，再运行最小命令、请求或独立程序；每次探测只改变一个变量，用对照或基线隔离非目标因素。只增加回答问题所需的观测，不加入生产架构、通用选项、穷尽测试或无关打磨；追加探测前说明哪种结果仍可能改变结论或决策，不存在这种结果时立即结束。试验结束后按可行、不可行或无法判断记录证据、阻碍和缺失证据；只有决策问题仍无法回答时才记录下一个最便宜的试验。

临时产物不得覆盖、清理或混入用户已有改动，也不得把临时依赖、锁文件、配置、生成产物或插桩留在最终差异中。使用非敏感代表性数据；正式环境写入、远端修改或额外权限必须取得精确授权，否则报告证据缺口。

## 探索会话（Exploratory Testing）

开始前记录：可观察的产品、版本、环境、入口和代表性数据；Charter（使命、关注风险、待回答问题和明确排除范围）；判断可接受与可疑行为的依据；与问题规模相称的时间盒、记录方式和停止条件；禁止的副作用、数据安全边界和所需授权。

用现有说明、运行状态和已有检查建立足以开始的产品模型，选择第一个高价值探测；在会话中同步学习、设计测试、执行和解释结果，根据新信息调整输入、状态、顺序、交互和观测面。把已有脚本、自动化检查和工具当作探测手段，不把它们当成限制探索范围的唯一清单。追踪与 Charter 相关的新线索；范围外发现只记录必要证据，不静默扩大调查。区分直接观察、证据支持的推断和待确认问题；异常出现时，记录环境、前置状态、操作、输出和副作用，争取获得最小可复现条件。

探索不是随意点击。测试者必须能解释当前选择与 Charter、产品模型或新证据的关系；发现数量、执行步数和通过率都不能代替学习价值。

到达时间盒或停止条件时结束会话，即使仍有未知。**获得稳定症状或最小可复现条件即结束探索**：保留复现证据，不在探索内自行诊断；根因成为新目标或需要新单元时返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md)，工作单元边界不变时返回 [execution](../execution/SKILL.md) 重选方法。不要为了制造“完成”结论而补写未经观察的结果。会话记录至少包含 Charter、环境与版本、实际覆盖的风险区域、重要操作、观察结果、可复现问题、未确认线索和剩余未知。会话后复盘实际执行了什么、发生了什么、学到了什么，以及哪些风险得到支持或削弱；复盘只确认调查结果，不授权实现、部署或外部状态修改。

## 交付与边界

交付问题或 Charter、适用环境、覆盖说明、关键观察或试验证据、复现证据、剩余未知、结论限制和建议的下一个最小工作单元。是否需要独立检查以及如何执行，由 [execution](../execution/SKILL.md) 根据证据收益选择。

调查单元不进入正式实现。探索可以提出修复建议，但不能把建议、猜测或一次观察描述成已验证实现。调查结束时清理或隔离临时产物，确认没有把探索代码混入项目差异，并检查工作区没有遗留准备交付的差异。需要正式修改产品，或把探索结论固化为版本控制的正式内容时，返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 建立、拆分和定级开发单元，再由 Execution 选法。
