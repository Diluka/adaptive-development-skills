# 代理团队协作协议

Use when 已选择代理团队，需要创建持续成员、维护共享任务状态并组织多轮沟通与交接。团队特有规则由本资源承载；通用委派要素、权限边界、角色独立性与组合验证见 [主技能](../SKILL.md)。

## 创建团队

- 先核验当前环境的成员创建、身份寻址、任务分配、消息投递、等待、停止与恢复能力，以及上下文、权限、模型和思考强度的配置或继承规则；按实际支持的能力组织协作。团队能力不可用时，可拆成独立任务的部分由协调者委派子代理并串行集成，准确说明实际协作形态。
- 保留一个任务级协调者，成员承担明确产物和验收边界。成员通信与自行认领任务不转移需求、范围、授权、共享契约、集成或最终结论的控制权；成员不得擅自扩展同级工作或绕过权限限制，局部编排按主技能的授权边界执行。
- 从当前可独立推进的产物划分成员职责，结合交接成本、资源与验证成本确定人数；成员可以顺序承担多个任务。角色名称只作定位，实际工作由任务契约限定。
- 沿用主技能的委派要素，补充成员身份、依赖就绪条件、认领方式与直接上级回报目标。派发说明自包含；有共同计划时给精确定位，按实际继承能力补齐任务事实，历史快照不当作实时同步。

## 任务所有权与就绪

- 用一份共享任务账本记录目标、验收、负责人、依赖、写入与运行资源范围、执行状态、产物和证据定位；它承载分工状态，任务级计划与跨单元决定仍由协调者维护。
- 认领前读取最新任务与依赖状态，通过当前环境支持的原子认领或协调者串行分配确立唯一执行者。更新冲突时重读并核对所有权、实际进展和依赖，再更新；同一任务已有执行者或状态不明时先对账。
- 就绪、已领取、正在执行、自报完成和协调者验收是不同事实；成员是否正在执行一轮工作又是另一维状态。后继任务实际开工前，所需输入须经协调者核验且已经可见，账本自动解锁不代替这项核对。

## 写入与交接

- 成员关系、任务领取和写入范围声明都不提供文件锁或运行资源隔离。按主技能的并行独立性检查分配互不冲突的写入面；持续并发写入按 [粗粒度并行协议](parallel-dispatch.md) 分配独立工作树与负责执行上下文。
- 接口、契约或范围分歧交协调者决定后再继续受影响路径；成员不通过修改另一成员的文件解决分歧。跨角色沟通传递事实和所需决定，不以转述其他成员的同意冒充用户授权。
- 打断当前轮次、取消任务和结束成员分别核验实际效果。交接或重试前确认旧执行者已停止写入，对账实际产物与外部副作用，再移交所有权和剩余工作；超时或缺少回报不授权重复执行。

## 通信与等待

- 向需要该信息的成员定向发送新事实、契约变化、阻塞与交接请求；只有共同输入或边界变化才同步所有受影响成员。较大结果通过产物定位与必要摘要交接，保留原始证据。
- 消息已投递不代表已处理；按投递结果和当前通信契约核对，确认已投递的消息不重复发送。成员空闲不代表任务完成，任务就绪也不保证成员已经开始执行。
- 等待前核对必需任务的所有权、就绪输入与成员执行状态；需要继续工作的成员尚未执行时，按当前环境支持的方式派发或恢复工作。确认有执行者能产生进展后再等待；等待通知后重读任务和成员状态，无进展时检查阻塞、投递或执行失败，而不是宣告完成。
- 协调者监看真实进展并纠偏，仍保留成员的写入所有权；需要接管时先完成安全交接。需要独立判断的任务按主技能保持共同输入与结论隔离，团队讨论和相互质询不替代独立评审。

## 回收与收尾

- 成员在完成、失败、取消或无法自行解除阻塞时向直接上级回报实际产物、证据与剩余事项。回报义务与管理权移交例外沿用 [粗粒度并行协议](parallel-dispatch.md)；任务状态缺失或滞后时由协调者核验实际进展后对账。
- 协调者收齐必需任务的终态回报，核验真实产物后接收结果；按主技能在所有写入停止后的组合状态验证，再串行交付。成员成功摘要、消息通知和账本完成标记各自只证明其对应状态。
- 当前目标完成后，按环境实际支持的结束方式回收本次成员与已获授权的临时运行资源。需要跨会话继续时保留目标、任务所有权、事实、产物和证据定位；恢复后重新核验成员与项目状态，不假定成员或未完成任务自动恢复。崩溃恢复与无人值守重试需要具备相应契约的外部控制能力，边界见 [工作树并行开发](../../using-git-worktrees/resources/parallel-development.md)。
