# 并行派发协议

粗粒度并行（独立会话 + 工作树）的派发、回收与串行集成按本协议执行。

## 并行独立性检查清单

对每一对候选单元逐项核对；任一不确定即缩小任务、改只读、用隔离工作树或顺序执行：

- [ ] **信息**：都能基于同一已确认目标和当前事实开始，不等待对方决策或发现；需要独立对照时回报前不读取对方结论。
- [ ] **写入**：不共享文件、生成产物、分支操作、数据库、外部资源、端口或进程状态。
- [ ] **契约**：共享接口与评价边界已固定，不会各自发明或修改。
- [ ] **顺序**：任一先完成都不会使另一项失效。
- [ ] **集成**：协调者能在明确边界上组合并验证结果。

测试或评估要等实现完成后才能取得稳定输入时，不伪装成并行单元，改顺序协作。

## 派发

- 先定义负责人、角色产出、读写范围、预期结果、证据和验证，再派发。
- 通过 [using-git-worktrees](../../using-git-worktrees/SKILL.md)
  建立或复用独立工作树，并按当前环境能力与用户授权另行分配负责执行上下文；新建执行会话以用户授权为前提。
- 只有一方或双方均为短小只读、无持久写入所有权的局部协作时，才在当前任务内使用子代理（见
  [subagent-protocol.md](subagent-protocol.md)）。
- 两种方式都只保留一个任务级协调者；执行者不得擅自创建或转派同级工作单元。获授局部编排权时，只能在原单元边界内派发更小的执行单元。
- 有落盘计划时，执行者读取同一计划或其不可变单元快照；没有计划的开发任务和非开发调查，共享同一目标与证据边界，不因多个执行上下文或工作树协作而转换任务类型或自动升级流程。

## 回收与串行集成

- 协调者检查执行者返回的实际文件和证据，排查隐藏重叠，再运行组合验证；不只接受成功摘要。
- 所有写入停止后在组合状态重跑验证；测试准备、生成产物、端口、进程或外部资源不能隔离时取消并行。
- 适用时同步计划，并按任务级别或具体风险决定最终独立评审；非开发调查统一汇总结论。
- 不并行编辑同一文件、锁文件、生成产物、迁移序列或共享外部状态；只读调查只有在数据源稳定且查询无写入时才能并行。
- 症状可能共享根因时先用
  [systematic-debugging](../../systematic-debugging/SKILL.md)，不要授权多个代理同时试修。
- 目标就是独立对照时，协调者必须预先固定共同输入、评价边界和回报格式，并在结果返回前保持判断隔离。
