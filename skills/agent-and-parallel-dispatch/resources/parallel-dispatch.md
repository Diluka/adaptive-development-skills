# 粗粒度并行：派发与回收

Use when 独立会话与工作树承担持续写入，且 [主技能](../SKILL.md) 的信息、写入、契约、顺序与集成独立性检查已通过；缺少独立性时缩小范围、改只读或顺序执行。

派发前固定目标和完成判据、已知事实、依赖、写入与运行资源所有权、验证责任、会话角色和直接上级回报目标。每个持续写入单元分配独立工作树与负责执行上下文；小块只读协作可按 [子代理协议](subagent-protocol.md) 在当前任务内完成。派发不转移任务级范围、授权、集成或交付权；局部再委派须明确授权。同一单元已有尝试仍在运行或状态不明时不重复派发；超时或丢回报先核对旧执行者，确认已停止且重派不会重复外部副作用后才重新派发。

收到任务的工作会话在完成、失败、取消或无法自行解除阻塞时向直接上级报告终态、实际产物、证据和剩余事项。只有上级明确声明“任务管理权已移交且无需回复”才取消该回报义务；临时侧边会话按用户安排。协调者检查真实文件与证据后再接收结果，不把执行者的成功摘要当组合验证。

所有写入停止后，协调者排查隐藏重叠，在最终组合状态验证并串行处理冲突与 Git 交付。文件、锁文件、迁移序列、生成物或运行资源无法隔离时取消并行；症状可能共享根因时先调查根因，不让多个执行者同时试修。需要独立对照时预先固定共同输入和评价边界，在回报前保持结论隔离。
