# 子代理委派协议

当前任务内短小单元的子代理委派按本协议执行。只有当前任务的根代理可以派发；子代理不得继续派生代理。

## 委派说明要素

根代理派发时固定以下要素，让子代理无需重新理解整份需求：

- 工作单元与主要方法（含相关证据）；
- 共享目标，或有统一计划时的精确路径与单元标识；
- 读写边界（哪些文件可写、哪些只读）；
- 角色产出（交付什么：实际差异、验证结果、证据、报告）；
- 停止条件（何时视为完成）；
- 验证责任（由谁、如何验证可观察结果）；
- 禁止继续派生代理，以及单元外发现的回报方式。

## 角色产出与停止条件

- **实现子代理**只修改约定的生产文件并说明设计选择；完成后立即把实际差异交回协调者，不继续占有分支、工作树或运行资源。
- **验证子代理**可并行执行只读证据设计、样例分析或稳定数据查询；需要写测试、夹具或评估产物时，由协调者串行安排写入，或升级为独立工作树任务。预期只能来自需求、设计、真实调用方和契约，不能从未完成实现反推。
- 停止条件达到（角色产出完成且可观察结果已回报）即结束该子代理，不扩展范围。

## 回报格式

子代理回报新事实、实际差异和验证结果：

- 实际完成的改动（文件与差异），不只给成功摘要；
- 验证方式、运行环境与可观察结果；
- 单元外发现（见下）；
- 计划外的新事实或偏差。

## 单元外发现最小回报

子代理发现技术上相关但不影响本单元实现、验证或交付的问题时，只回报必要证据（定位与最小说明），不继续调查、修改或建立外部问题单；由协调者判断它是否影响整个任务——不能仅凭技术关联并入任务，也不能因为不影响本单元就直接排除。

## 禁止派生与集成

- 子代理缺少上下文或授权时回报协调者，不继续创建代理。
- 多个子代理不得各自维护计划副本，也不得并发编辑计划或通过修改另一角色文件自行解决契约分歧。
- 跨单元决策和共享接口由协调者持有；协调者读取实际文件、解决隐藏重叠，并在所有写入停止后的组合状态重跑验证。
- 需要独立判断时，各代理基于同一已确认目标工作，回报前不读取或迎合另一代理结论；协调者负责比较，不让代理互相收敛。
- 最终普通 Git 交付由协调者在组合验证后串行完成；子代理不独立持有提交、推送或
  PR/MR 交付轨道。
