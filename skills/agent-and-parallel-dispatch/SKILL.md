# 代理与并行编排

本技能管理执行形态分配、并行独立性判断、实现与验证双轨，以及派发与集成；只负责「怎么做」，不承担流程编排。

## 选择执行形态

按边界与收益选择执行形态：

| 形态 | 适用 |
|---|---|
| 根代理直接做 | 改动很小且根代理已掌握上下文；交接成本高于收益；步骤会持续修改共享状态、关键产品决策未解决，或需频繁处理全局问题 |
| 当前任务内子代理委派 | 短小、只读或根代理能立即检查接管的边界局部修改；委派能节约主代理上下文或提供独立判断 |
| 独立会话 + 工作树粗粒度并行 | 单元需持续写入、独立长上下文、工作树或可恢复生命周期；经 [using-git-worktrees](../using-git-worktrees/SKILL.md) 隔离并另配负责执行上下文 |
| 顺序执行 | 单元间存在信息、写入、契约、顺序或集成依赖，无法安全隔离 |

委派与并行的动机是**保护主代理上下文**（局部搜索、日志、依赖或实现细节明显占用上下文时）和**防止多次上下文压缩后指挥跑偏**（独立判断能提供实现者自证之外的证据）。并行收益来自缩短等待时间，或在不互相锚定下形成独立实现或证据；收益低于交接与协调成本时不委派、不并行。工作数量多不代表适合派发；缺失成功标准会改变用户意图时先澄清，不能让多个代理投票替用户决定。任务内委派细节见 [resources/subagent-protocol.md](resources/subagent-protocol.md)。

## 判断并行独立性

对每一对候选单元检查五要素；任一答案不确定时缩小任务、把一方改成只读、使用隔离工作树，或顺序执行：

1. **信息**：都能基于同一已确认目标和当前事实开始，不等待对方决策或发现；需要独立对照时，回报前不读取对方结论。
2. **写入**：不共享文件、生成产物、分支操作、数据库、外部资源、端口或进程状态。
3. **契约**：共享接口与评价边界已经固定，不会各自发明或修改。
4. **顺序**：任一先完成都不会使另一项失效。
5. **集成**：协调者能在明确边界上组合并验证结果。

测试或评估要等实现完成后才能取得稳定输入时，不伪装成并行单元，改顺序协作。检查清单与派发/回收/串行集成规则见 [resources/parallel-dispatch.md](resources/parallel-dispatch.md)。

## 分离实现与验证

实现与证据有独立产物和反证边界，且分开能减少实现者自证偏差时分离角色：

- **实现者**：只修改约定的生产文件并说明设计选择；不为预想测试增加需求外行为。
- **验证者**：依据需求、设计、真实调用方和契约独立设计测试、样例、评价量表或反证。预期只能来自共同输入，不能从实现者中间代码或结论反推，也不能复制目标字面量制造镜像测试。角色产出含自动化测试时，只修改约定的测试与夹具，通过所选真实入口验证可观察结果，并回报规格映射、运行环境与结果。
- **评审者**：必须独立于实现、验证与证据设计；读取完整差异和验证证据，检查实现与证据是否共同偏离真实目标。

实现/验证分离按规模决定：小规模可在同一代理内完成（节省上下文成本），大规模使用独立验证者——权衡子代理上下文理解成本与并行节省时间，选最合适。**评审分离是必须**，不随规模放宽。验证者不必产出自动化测试：确定且稳定的不变量进测试，模糊质量用评估或实验，能稳定复现的真实输出用快照或行为基线。

## 派发与集成

- 协调者（根代理）持有需求、范围、授权、项目写入所有权、跨单元决策、集成和最终验证；执行者只回报新事实、实际差异和验证结果，不并发改计划，也不通过修改另一角色文件自行解决契约分歧。
- 委派说明固定工作单元、主要方法、相关证据、读写边界、角色产出、停止条件和验证责任，并明确是否授予局部编排权及其边界；该权限不随委派自动转移。有统一计划时提供精确路径和单元标识。
- 协调者读取实际文件、排查隐藏重叠，在所有写入停止后的组合状态重跑验证；不只接受成功摘要。适用时同步计划，按任务级别或具体风险决定最终独立评审。
- 最终普通 Git 交付由协调者在组合验证后串行完成；执行者不独立持有提交、推送或 PR/MR 交付轨道。合并、发布、部署、正式环境数据变更、权限修改和破坏性操作仍需用户明确要求，不得通过委派扩大边界。

## 边界

- 任务级派发由根代理控制；子代理不得擅自新增或转派同级工作单元，也不得启动计划、评审、交付等任务级流程。委派说明明确授予局部编排权时，子代理可以在当前单元的范围、授权和资源边界内派发更小的执行单元，并负责回收结果；缺少上下文或授权时回报协调者。粗粒度单元另配的负责执行上下文是新任务根代理，不是嵌套子代理。
- 不并行编辑同一文件、锁文件、生成产物、迁移序列或共享外部状态；只读调查只有在数据源稳定且查询无写入时才能并行。
- 症状可能共享根因时，停止并把共享根因风险交给 Execution 重选调查方法；因果链未确定前，不授权多个代理同时试修。
- 需要独立判断时，各代理基于同一已确认目标工作，回报前不读取或迎合对方结论；协调者负责比较，不让代理互相收敛。
