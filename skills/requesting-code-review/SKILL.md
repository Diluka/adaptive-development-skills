# 发起独立评审

## 适用前提

是否需要独立评审由工作流按复杂度和风险决定，完整判据见 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 的 `resources/node-routing.md`；这里只保留方法内触发条件：

- 复杂或高风险开发任务需要最终独立评审；
- 常规任务存在定向验证覆盖不到的具体风险；
- 复杂非开发调研存在偏航、遗漏反证或结论错误风险时，可选独立检查。

适用时，独立评审用于降低实现者自证偏差；评审者不能参与本任务的实现、证据设计或相关差异修改。提供完整证据包和事实约束，但不暗示结论。本技能只讲如何发起评审；何时编排下一步（返工、重评审、收尾）由入口负责。

## 决定评审深度

评审深度由复杂度和风险决定：常规验证缺口用聚焦受影响差异的独立评审；跨模块契约、依赖迁移、身份、资金、数据或并发等扩大深度并在有独立收益时增加专项评审者。具体执行层和机制选择见 [execution](../execution/SKILL.md) 的 `resources/method-selection.md`。

评审最终准备交付的受影响完整差异，不必逐个评审工作单元或临时调查产物。已有独立评审覆盖相同最终差异、事实和风险面时直接复用；PR/MR 存在评审记录不等于已经覆盖，先检查实际评审范围，不因交付阶段变化重复派发。

## 选择评审执行层

短小、只读且不需要独立长期生命周期的评审，可以由当前 Codex 任务内的独立子代理完成。评审本身是粗粒度独立工作单元，或开发已经采用多个独立工作树时，通过 [using-git-worktrees](../using-git-worktrees/SKILL.md) 为未参与实现的评审者提供干净工作树；不要复用实现者上下文。工作树提供文件隔离，执行上下文提供评审所有权，两者都必须独立。

## 准备证据包

先确认是否已有初始提交：

```bash
git rev-parse --verify HEAD
```

已有 `HEAD` 时，寻找实际分支基点，并覆盖全部提交与未提交工作：

```bash
git merge-base HEAD <target-branch>
git log --oneline <base>..HEAD
git diff --find-renames -U10 <base>..HEAD
git status --short --untracked-files=all
git diff
git diff --cached
```

没有 `HEAD` 时，跳过基点和日志，以 `git diff --cached --find-renames -U10`、`git diff` 和完整状态构造相对空树的证据包。

证据包至少包含：

- 原始需求和不变量，以及工作单元到原始需求的对应关系；
- 适用计划的路径与状态、精确差异范围、真实调用方和依赖契约；
- 本次变更直接影响的已知既有伴生产物，以及其同步授权或暂停状态；
- 最新验证、已知基线失败和未决假设。

评审者必须读取正式实现和验证完成后的受影响完整实际差异，不只读摘要。

普通 `git diff` 不包含未跟踪文件。根据完整状态逐个纳入对应文件；需要生成差异时，只对文件运行 `git diff --no-index -- /dev/null <path>`。不要传目录或为审查自动暂存，也不要用 `HEAD~1` 作为基点而漏掉更早的改动。

## 请求无偏评审

要求评审者在独立上下文中读取需求、适用计划或共享目标与约束、完整差异和验证证据。按严重性报告带文件和行号的意见，并检查正确性、回归、安全、数据边界、验证缺口和任务范围。

分别核对范围归属与操作授权。本次变更直接影响的既有伴生产物，最小同步属于原任务，不算范围扩散；已经执行的同步仍须在现有授权内，且没有待确认的业务取舍、风险或新增副作用。否则报告未经授权的改动；未执行时，确认只暂停该同步路径。

对于其他改动，如果保持相关原有代码不变仍能完成原始任务且没有明确授权，就把它报告为范围扩散，即使它修复了真实问题。

评审者原则上只读且不得继续派生代理。只有根代理可以派发；不要暗示预期结论、预先判定疑点无害或用叙述代替实际差异。

使用 [receiving-code-review](../receiving-code-review/SKILL.md) 核验意见。评审失效与否按实质修改判断：只有改变既有结论或风险面的实质修改才使对应评审失效，此时重新验证受影响范围，并在任务级别仍要求时由未参与该轮实现或修复的独立评审者复审；节点转换仍按 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 判断。

环境无法提供符合上节独立性要求的评审者时，只能阻止本来就要求独立评审的任务声明完成；评审与处理意见都不递归创建新任务。

## 复杂非开发调研

选择独立检查时，提供原始目标、范围、关键问题、证据、反证、结论、未决项和临时产物清理证明。要求检查是否偏离目标或遗漏替代解释。它不需要开发计划或 Git 差异，也不把调查转换为开发任务。
