# Requesting Code Review：请求独立评审

## 核心原则

先按 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 判断当前增量是否适用独立评审。适用时，独立评审用于降低实现者自证偏差；评审者不能参与本任务的实现、证据设计或相关差异修改。提供完整证据包和事实约束，但不暗示结论。

复杂的非开发调研不强制评审。只有独立检查能降低偏航、遗漏反证或结论错误的风险时才使用。

## 决定深度

| 改动 | 评审方式 |
|---|---|
| 常规任务存在验证缺口或重要取舍 | 一个聚焦受影响差异、回归和证据缺口的独立评审 |
| 跨模块契约、依赖迁移、身份、资金、数据或并发 | 扩大深度，必要时增加专项评审者 |
| 破坏性 Git、数据库模式、正式环境或安全边界 | 深度评审；实际操作另行取得明确授权 |

评审最终准备交付的受影响完整差异，不必逐个评审工作单元或临时调查产物。已有独立评审覆盖相同最终差异、事实和风险面时直接复用；PR/MR 存在评审记录本身不等于已经覆盖，先检查实际评审范围，不因交付阶段变化重复派发。

## 准备证据包

先检查是否已有初始提交：

```bash
git rev-parse --verify HEAD
```

已有 `HEAD` 时，寻找实际分支基点并覆盖全部提交与未提交工作：

```bash
git merge-base HEAD <target-branch>
git log --oneline <base>..HEAD
git diff --find-renames -U10 <base>..HEAD
git status --short --untracked-files=all
git diff
git diff --cached
```

没有 `HEAD` 时跳过基点和日志，以 `git diff --cached --find-renames -U10`、`git diff` 和完整状态构造相对空树的证据包。

证据包包含原始需求和不变量、工作单元到原始需求的对应关系、适用计划的路径与状态、精确差异范围、真实调用方和依赖契约、本次变更直接影响的已知既有伴生产物及其同步授权或暂停状态、最新验证、已知基线失败以及未决假设。评审者必须读取正式实现和验证完成后的受影响完整实际差异，不只读摘要。

普通 `git diff` 不包含未跟踪文件。根据完整状态逐个纳入对应文件；需要生成差异时，只对文件运行 `git diff --no-index -- /dev/null <path>`。不要传目录或为审查自动暂存，也不要用 `HEAD~1` 作为基点而漏掉更早的改动。

## 请求无偏评审

要求评审者在独立上下文中读取需求、适用计划或共享目标与约束、完整差异和验证证据，按严重性报告带文件和行号的意见，并检查正确性、回归、安全、数据边界、验证缺口和任务范围。分别核对范围归属与操作授权：本次变更直接影响的既有伴生产物最小同步属于原任务，不算范围扩散；已经执行的同步仍须在现有授权内且没有待确认的业务取舍、风险或新增副作用，否则报告未经授权的改动，未执行时确认只暂停该同步路径。对于其他改动，如果保持相关原有代码不变仍能完成原始任务且没有明确授权，就把它报告为范围扩散，即使它修复了真实问题。

评审者原则上只读且不得继续派生代理。只有根代理可以派发；不要暗示预期结论、预先判定疑点无害或用叙述代替实际差异。

使用 [receiving-code-review](../receiving-code-review/SKILL.md) 核验意见。只有改变既有结论或风险面的实质修改才使对应评审失效；重新验证受影响范围，并在任务级别仍要求时由未参与该轮实现或修复的独立子代理复审。机械格式修正、保持双方既有语义的文档冲突解决或不影响评审结论的基点移动，不自动触发完整复审。环境无法创建评审子代理时，只能阻止本来就要求独立评审的任务声明完成；评审与处理意见都不递归创建新任务。

## 复杂非开发调研

选择独立检查时，提供原始目标、范围、关键问题、证据、反证、结论、未决项和临时产物清理证明，要求检查是否偏离目标或遗漏替代解释。它不需要开发计划或 Git 差异，也不把调查转换为开发任务。
