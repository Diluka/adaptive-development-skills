# 安全维护变更

## 基本规则

维护变更的安全性来自调用方、加载影响面与依赖解析证明，不来自臆造需求，也不来自为测试保留已经没有调用方的路径。删除最小但完整的单元，并验证剩余系统。

本技能只处理行为保持或仅依赖解析变化的维护变更。一旦需要破坏性变更、正式修复、新增契约或长期测试，停止并返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 重新拆分和定级，再由 [execution](../execution/SKILL.md) 选择后续方法。维护清理只做与目标直接相关的删除、解除引用和最小修复；发现的可重构机会只记录为后续事项，不顺手执行。

## 行为保持基线

行为保持型变更（删死代码、升级依赖）先在旧实现 / 旧解析上建立可运行基线：记录待保持的核心行为、真实入口和失败影响；改动前运行经过受影响路径的既有测试或可重复冒烟确认基线；改动后以相同入口、相同环境、相同输入重跑并与基线对照。只有能由已确认需求解释的差异可接受；其余差异表示行为保持尚未证明。

证据充分性与行为保持边界见 [execution](../execution/SKILL.md) 的 `resources/evidence.md`；复杂输出的基线取证与批准见其 `resources/baseline-and-evaluation.md`。

## 按调用方清理死代码与无效路径

从待删除的符号、文件、包、路由、任务或配置键开始，检查调用方和加载影响面：静态导入、导出、再导出、别名和生成入口；依赖注入、装饰器、反射、注册表、插件和动态导入；字符串键、配置、脚本、任务、迁移和模板；清单、锁文件、对等依赖、构建配置和发布文件；表示真实支持用法的测试、文档和仓库历史。

仓库提供语义索引或调用图时，先用它定位符号与调用方，再用源码搜索、依赖检查和运行时证据补足动态影响面。本技能以删除或升级为目的定位调用方；通用定位机械做法见 [system-understanding](../system-understanding/SKILL.md)。

活跃生产调用方在删除前保留或迁移；存在外部使用方的公共 API 先建立兼容或发布边界；框架或运行时注册在启动或加载证据否定前视为仍在使用；测试真实契约的测试随迁移后的调用方更新，只覆盖已删除内部实现的测试随实现删除；过时文档、夹具、快照或锁文件条目作为同一完整单元删除。未知动态使用不是死代码证明。无法排除公共 API 外部使用方时，停在证据缺口；可能存在发布边界不等于已获准执行破坏性发布或改变外部状态。

## 删除与验证

1. 记录活跃调用图和预期保留行为。
2. 删除只属于无效路径的实现、导出、注册、测试、文档和依赖条目。
3. 使用包管理器的正常移除和解析流程，不只手改锁文件。
4. 按影响运行类型检查、构建或启动、保留调用方的定向测试和公共导出检查。
5. 审查差异中的孤立兼容分支与无关改动。

除非已验证调用方需要迁移窗口，不得添加包装层、回退分支、弃用别名或生产代码选项。

## 依赖升级

修改项目实际解析的依赖图。在使用通用建议前，先尊重项目锁定的包管理器、运行时和工作区边界。添加新包、升级运行时或编译器可能引入新行为或新的传递依赖：仍属行为保持则按『行为保持基线』执行，可能改变行为则返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 重新定级，再由 [execution](../execution/SKILL.md) 选择方法。

先读取仓库说明、清单、锁文件和已安装环境，确认包管理器、引擎、运行时和工具链锁定。再确认直接、传递、可选和对等依赖关系，覆盖或解析规则及其原因，真实导入、二进制、构建插件和运行时调用方，以及注册源、完整性元数据、生命周期脚本、原生构建钩子和新增信任边界。使用当前项目包管理器的依赖图、`why` 或 `explain` 能力证明归属；命令以项目安装版本的 `--help` 为准。

升级时阅读确切起止版本的发布说明和迁移指南，检查对等依赖、引擎、锁文件兼容性和已发布包内容；优先正常解析，只有已验证且无法正常解决的传递冲突才添加覆盖规则并记录移除条件。影响大、难回退的依赖或迁移变更，先运行包管理器的干跑 / 预览（`--dry-run`、`plan` 等，以项目安装版本 `--help` 为准）确认解析结果再执行。只修改该单元必需的清单、导入、配置和锁文件条目，再用 Execution 为该边界选定的契约证据和验证手段核对变化，按影响运行定向构建、类型检查、测试或运行时冒烟。删除依赖的安全性先按清理流程证明，再更新清单和解析结果。

## 安全边界

- 不把宽泛的 `audit fix`、`--force` 或类似修改当作升级策略。
- 不把维护变更顺手扩大为切换包管理器、重写无关锁文件区段或升级运行时、工具链。
- 依赖解析和安装脚本只在隔离的开发或 CI 环境执行，不在正式环境主机执行。
- 执行前审查新增或变化的生命周期脚本与原生脚本；需要未授权凭据、主机权限、注册源信任或工具链时停止。
- 区分既有失败与本次回归，并保留工具正常生成的来源和完整性元数据。
- 删除或升级后验证剩余系统，手段见『删除与验证』与『依赖升级』。
