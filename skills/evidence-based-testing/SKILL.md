# Evidence-Based Testing：基于证据选择测试

## 职责

把待证明结论映射到能推翻它的最小充分证据。先复用仍覆盖当前输入、环境、版本、调用路径和风险面的证据，只补真实缺口；完成后收敛长期保留的测试和观测，不追求测试数量、覆盖率数字或流程齐全。

本技能是证据策略支持，不是与开发方式竞争的主要方法。属性测试、消费者驱动契约测试、特征测试和评估驱动开发各自拥有独立标准流程；选中后进入对应技能，不在这里重写其步骤。选择测试方式（端到端、单元、TDD、属性、契约等）由 [choosing-tests](../choosing-tests/SKILL.md) 负责，本技能聚焦证据充分性判断、复用与长期收敛。

## 明确待证明结论

对每项结论记录：

- 必需结果或不变量及其权威来源；
- 真实调用方、输入结构、环境和相关依赖契约；
- 当前变化可能引入的具体错误；
- 哪个观察会推翻“实现正确、行为保持或可交付”的判断。

证据冲突时按需求和不变量 > 真实调用方与运行行为 > 依赖和协议契约 > 实现与测试判断。测试基于不存在的调用方、错误契约或内部细节时修正或删除测试；实现违反更高优先级事实时修正实现。

## 从需求派生证据

先把权威需求、规格或设计约束映射为真实调用方能够观察的结果、边界和失败风险，再决定是否需要测试以及测试层级。不要从生产目录、组件树、类、函数或当前实现步骤反向枚举测试；这些结构只能帮助找到接缝，不能定义必须证明的行为。

为每份准备新增或复用的证据记录其需求或不变量来源、真实入口、可观察结果、要拒绝的合理错误和独特失败信号。需求级证据已经覆盖同一风险时，不为底层实现细节重复增加测试；只有稳定低层规则、不同失效面或显著定位价值形成新的证据边界时，才补相应低层检查。

## 选择证据与方法

| 结论或风险形状 | 首选证据或方法 |
|---|---|
| 确定性行为有独立稳定判据和具体回归风险 | 最低真实接缝上的定向行为测试 |
| 稳定不变量能由类型系统显著排除非法表示，且类型建模本身有独立收益 | [type-driven-design](../type-driven-design/SKILL.md)，静态检查证明类型约束，运行时证据只覆盖剩余风险 |
| 广泛输入空间有独立属性、不变量、变形关系或参考模型 | [property-based-testing](../property-based-testing/SKILL.md) |
| 可协作的消费者与提供者需要持续证明版本兼容 | [consumer-driven-contract-testing](../consumer-driven-contract-testing/SKILL.md) |
| 真实旧行为或复杂稳定输出需要可审阅的前后比较 | [characterization-testing](../characterization-testing/SKILL.md) |
| AI、Agent 或其他概率性、主观输出需要代表任务和重复评估 | [eval-driven-development](../eval-driven-development/SKILL.md) |
| 已知业务行为需要跨角色示例和可执行验收规格 | [behavior-driven-development](../behavior-driven-development/SKILL.md) |
| 已指定的声明式数据、映射、提示词或文案，没有改变解释逻辑 | 直接实现、差异审阅并复用现有检查；有真实缺口时验证使用方行为，不复制目标字面量 |
| 分支同步或机械冲突未改变运行语义 | 审阅冲突与最终差异、确认无冲突标记，并查看最终集成结果的 CI |
| 单个真实环境或完整装配边界风险 | 可重复的集成、端到端或冒烟观测 |

如果第三方边界当前是什么尚不确定，先把该未知拆为 [contract-verification](../contract-verification/SKILL.md) 调查单元；若已有症状但根因未知，先用 [systematic-debugging](../systematic-debugging/SKILL.md)。调查只交付事实，正式变更返回 [adaptive-development-workflow](../adaptive-development-workflow/SKILL.md) 重新选开发方式。

## 判断证据是否独立

新增测试前确认判据独立来自需求、真实调用方或契约，接缝保留真实行为，检查能够拒绝至少一种合理错误实现，并对应值得长期保护的具体回归风险。相对既有证据没有新增反证或定位价值时，不再增加测试。

测试只能从待写入字面量或当前实现反向复制时，不构成独立判据。精确内容本身属于协议、安全、合规或其他外部契约时，可以在真实生成或消费边界保留必要断言。

## 使用静态证据

编译器或静态分析器已经在当前严格配置和真实使用位置证明的约束，不再用运行时测试重复证明。记录工具链版本、配置、执行命令和受检范围；只在公共或复杂类型 API 的兼容风险值得长期保护时，保留少量 intended-valid / intended-invalid 编译用例或等价类型契约检查。

静态检查是一类证据，不是独立的通用开发方式。需要主动用类型表达稳定不变量时进入 [type-driven-design](../type-driven-design/SKILL.md)；普通字段、显然类型标注或指定字面内容直接实现并运行项目既有静态检查。

类型不能证明解析前的外部 JSON、HTTP、数据库或用户输入，也不能替代真实副作用、数值算法、并发、时间、性能和概率性质量证据。不可信边界先做运行时解析或校验，转换为可信领域类型后才复用静态保证；对类型系统无法表达的失败面继续选择运行时测试、契约、观测或评估。

## 复用既有证据

为测试、评审、观测和 CI 记录其适用输入、环境、版本、调用路径和风险面。当前变化没有影响这些条件时直接复用；只让受影响结论失效，不因为新提交、基点移动或交付阶段变化而重跑全部检查。

最终推送提交或合并结果上的 CI 是组合状态的一等证据。本地检查仅在能更早发现当前风险、覆盖 CI 缺口或提供必要基线时增加。任何新增检查都要能说明它拒绝的合理错误，否则跳过。

## 行为保持型工作

涉及业务逻辑、状态变化、公共契约或框架边界的行为保持型重构，在改动前必须有能发现核心行为漂移的证据：

1. 列出必须保持的核心行为、真实入口和失败影响。
2. 运行并复用经过受影响路径、断言可观察结果的已有测试或观测。
3. 仍有缺口时，按结果形状选择最小定向测试、[characterization-testing](../characterization-testing/SKILL.md) 或可重复冒烟；在旧实现上确认基线。
4. 修改后以相同入口、环境和输入再次运行并比较。
5. 只有能由已确认需求解释的差异才可接受；其余差异表示行为保持尚未证明。

旧实现上的通过基线只证明当前行为能够在既定条件下复现。构建、类型检查、无关测试、模拟调用次数和代码审查可以补充，但不能单独证明核心业务行为保持。无法建立测试或可比较观测时，缩小单元、先建立真实接缝或暂停对应重构。

## 选择证据层级

| 风险边界 | 首选证据 |
|---|---|
| 纯确定性规则 | 最低真实接缝上的示例测试或属性测试 |
| 框架绑定、序列化、装饰器或中间件 | 真实框架模块或集成测试 |
| SQL、事务或持久化映射 | 可丢弃的本地或测试数据库集成 |
| 稳定但逐项断言成本高的输出 | 特征/批准基线中的最小可审阅范围 |
| 完整且接近生产的调用链 | 窄范围端到端测试或可重复冒烟 |
| 正式环境发布后的剩余风险 | 只读生产观测；需要受控暴露时使用 [progressive-delivery](../progressive-delivery/SKILL.md) |

只有较低层接缝会抹掉待验证行为时才向上移动。不同层级若覆盖不同失效面可以并存，不能用大量低层测试冒充真实框架、传输、持久化或部署边界。

把独立验证安排为“从顶层链路开始”时，先从受影响的真实调用方中找出能够覆盖目标风险的最高入口，并在该入口定义可观察结果，再按失败定位需要补充更低层证据。这里的顶层是与当前结论相称的公共或装配边界，不自动等于跨越全部服务、数据库和外部依赖的完整端到端环境。最高入口没有独特失败信号、会引入无关不稳定性，或较低真实接缝已经能推翻同一结论时，保留较低层证据即可。

## 保持接缝真实

测试替身只用于时钟、网络、进程、随机性或不可用外部系统等真实边界。业务不变量与待验证的框架、解析、序列化和持久化行为保持真实。

不要模拟被测单元本身，不要为了人工测试增加生产开关、包装层、回退、分支或公共方法，也不要用内部协作者调用次数替代可观察结果。真实外部边界的调用次数本身构成副作用契约时，可以在该边界验证。

## 收敛最终证据组合

完成实现后，把每份新增和受影响的长期证据映射到稳定需求或不变量、真实调用方、具体回归风险及独特失败信号：

- 保留约束核心契约、历史缺陷、边界、错误路径、状态变化或副作用的证据。
- 合并只重复同一风险且没有新增输入、边界或定位价值的同层检查。
- 删除只约束淘汰实现、私有结构、过时接缝、普通字面量或无业务意义协作次数的测试。
- 暂定 rubric、一次性探索记录和本地随机缓存不自动成为长期确定性契约。
- 删除或合并后重跑受影响验证，并审查剩余组合能否拒绝对应错误实现。

测试在开发阶段曾暴露有用问题，不等于必须永久保留；昂贵或易失测试也不能仅因维护不便删除关键保护。必要时在隔离、可恢复环境中使用临时故障注入或变异测试检查证据有效性，不得为此保留生产测试钩子。

## 报告证据边界

说明证据命令或观测、输入与环境、结果、它直接支持的结论以及未覆盖风险。格式校验、静态引用检查和单次代理模拟只能证明对应结构或样例，不得外推为真实运行行为或普遍方法效果。
