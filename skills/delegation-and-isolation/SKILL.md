# 委派与隔离

## 选择适用的隔离边界

工作树为 **Git 状态与文件**提供隔离。是否采用工作树由并发写入者数量与失败时当前工作区的安全回退能力共同决定；改动规模和风险提供评估背景，会话安排另行选择。

用户或仓库未指定位置且确需隔离时，默认放在根工作树下的 `<repo>/.worktrees/<name>`。根路径已检出当前任务的开发分支时，先核对工作状态；未提交改动归属待厘清时，报告并等待处理决定，归属确认后按授权安排迁移并保留原有文件状态。创建失败时报告准确错误，并保留现有工作树、分支与仓库状态。

## 明确工作树共享的资源

每个工作树拥有独立的工作目录、索引与检出状态；分支与远端引用、对象库、仓库配置与钩子、`refs/stash` 及工作树注册信息由仓库共享。端口、进程、数据库、外部服务等运行资源采用单独的协调安排。

## 判断能否并行

对每一对候选单元核对：信息（决策可独立进行）、写入（文件、生成物、迁移序列与运行资源相互隔离）、契约（共享接口已固定）、顺序（先后完成均维持另一单元的有效性）、集成（协调者能组合并验证）。条件尚未确认时，缩小范围、将一方设为只读、分配独立工作树，或顺序执行。测试依赖实现完成后的稳定输入时，采用顺序协作。

## 委派与回报

- 委派说明交代目标、读写边界、所需产出与验证责任；共享契约、停止条件或局部编排权影响执行时一并明确。
- 被委派者回报新事实、**实际差异**与验证结果，并简述成功情况；单元外发现提供定位与最小说明，由协调者决定是否扩大范围。
- 协调者在所有写入停止后的**组合状态**读取实际差异，复用仍覆盖相同输入、环境、版本和路径的证据，只补组合后失效或缺失的证据。
- 实现与评审由不同执行者承担。需要独立判断时，各执行者回报前分别形成结论，再由协调者比较。

## 边界

症状可能共享根因时，先定位根因，再安排实施。协调者在组合验证后完成最终 Git 交付，执行者按委派范围回报工作结果。合并、发布、部署、正式环境写入与权限修改仍需明确授权。
