# Dispatching Parallel Agents：安全并行派发

## 核心原则

只有任务真正独立且并行收益高于协调成本时才并行。工作数量多不代表适合派发；即使独立，也可以顺序执行或由根代理完成。并行不改变开发任务判定。

## 证明独立性

对每一对候选单元检查：

1. **信息：** 都能基于当前事实开始，不等待对方决策或发现；
2. **写入：** 不共享文件、生成产物、分支操作、数据库、外部资源、端口或进程状态；
3. **契约：** 不会各自发明或修改共享接口；
4. **顺序：** 任一先完成都不会使另一项失效；
5. **集成：** 根代理能在明确边界上组合并验证结果。

任一答案不确定时，缩小任务、把一方改成只读，或顺序执行。

## 派发与集成

使用 [subagent-driven-development](../subagent-driven-development/SKILL.md) 定义负责人、读写范围、预期结果、证据、验证和禁止嵌套派发。开发任务中的代理读取同一计划；非开发调查共享同一目标与证据边界，不因多代理协作而转换为开发任务。

根代理检查代理返回的实际文件和证据，排查隐藏重叠，再运行组合验证。开发任务同步计划并完成最终独立评审；非开发调查统一汇总结论。

## 边界

- 不并行编辑同一文件、锁文件、生成产物、迁移序列或共享外部状态。
- 只读调查只有在数据源稳定且查询无写入时才能并行。
- 症状可能共享根因时先用 [systematic-debugging](../systematic-debugging/SKILL.md)，不要授权多个代理同时试修。
- 多个代理不得各自维护计划副本，也不得重复同一调查，除非目标就是独立对照。
