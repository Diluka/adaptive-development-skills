# 技能包设计

> 状态：**v4**。本文是技能包目标状态的权威说明；历史重构记录留在 `.docs/plans/`。

## 目的

用户通常只给一句话需求，而不是一份现成规格。这套技能的价值是让代理基于当前事实与授权，稳定选择**下一步最有信息或交付价值的动作**：直接做、澄清、取证，还是先做可丢弃试验。

成功意味着少绕路、少返工，交付符合真实需求与契约。工作路径由**已知事实与缺口**改变，而不是由“加、修、调查”等动词决定：同一句“加上退款申请”，已有退款规则和接口时可以直接实现，资格或权限规则没有来源时应先澄清。

## 收录标准

**只收录模型容易判断错、且判断错了代价大的内容。** 判据是“这条能不能防住一个真实会犯的错误”，不是“重不重要”：

- 保留：静态搜索查不到调用方不等于死代码；外部行为以实际安装或部署版本为准；正式环境数据源禁写；评审者不得自审；断言不能来自待写实现；交付与授权边界按可逆性决定。
- 不收录：通用开发方法论（怎么追调用方、怎么写测试、怎么做 spike、怎么读迁移指南、怎么组织 README），以及公开标准方法的教程式复述。这些由模型已有能力承担。

目录完整不是存在理由；一条能被模型稳定做对的规则，写进来就是噪音。

## 从请求选择下一步

1. 识别用户要得到事实、决定，还是项目产物；以当前仓库、调用方、既有约束和授权判断已经知道什么。简短请求不自动要求正式规格、计划或新测试。
2. 找出当前最可能使下一步走错的缺口。缺用户拥有的业务取舍时只问会改变行为或验收的那一项；缺可核查的版本、调用方或症状时做最小只读调查；缺口已由现有证据覆盖时直接回答或实施。
3. 取证从能拒绝当前合理错误的最短路径开始；事实足以回答或实施时停止调查，不为直接行动补规格或仪式。
4. 核对真实消费或激活路径上的结果与仓库强制检查；足以支持当前声明即停。

调查是取证方式，不是绕开已授权实现的终点：同一请求既要求调查又要求修复时，调查结果直接支持当前授权范围内的实施；出现新的用户可见行为、公共契约、架构边界、授权或副作用时暂停受影响路径并确认关键取舍。

## 交付范围按可逆性决定

| 事实 | 交付动作 |
|---|---|
| 不可逆（无法用一次 revert 或分支重置复原，含正式环境写入、数据迁移、已发布制品） | 先取得授权，记录回退路径 |
| 跨边界（公共契约、对外接口、鉴权、数据模型、依赖解析、并发或共享运行资源） | 独立评审 + 推送 + MR/PR + 等待 CI 终态 |
| 都不成立 | 就地实现，本地提交并报告差异；不创建 MR、不等 CI |

不确定时按更高一档处理。级别只决定机制集合，**不扩大授权**：合并、发布、部署、权限修改、外部消息、流量调整与其他高影响操作始终需要用户明确要求。开发、调查与验证不得写入正式环境数据源。保留用户和其他任务的改动。

## 不可失的边界

- 需求、已确认不变量、真实调用方和已核验契约优先于实现、测试及预设流程；缺少事实不能用代理推测补成产品规则。
- 动态导入、反射、注册、配置或外部调用可能让静态引用搜索漏报；死代码删除和兼容性判断需要对应证据。锁文件声明与实际安装或部署版本冲突时，以实际运行边界为准并报告差异。
- 独立评审者不能参与所评内容的实现、证据设计或修改。测试期望不从待写实现复制；替身只隔离真实外部边界。
- 技能包自足：技能不依赖仓库外的用户配置或机器专属文件。

## 验收场景

用相同的短请求和固定事实输入核对首个实质动作、待问的关键决定与停止信号；改变事实后路径必须随之改变：

- “给订单页加按订单号筛选”：匹配语义已确认且接口支持时直接实现并验证；多商户订单号重复、匹配范围无权威规则时先询问；匹配规则已定但接口行为未知时先核验接口。三者都不先编规格。
- “修复取消上传却提示成功”：已可稳定复现时先观察取消路径并追踪错误状态；修复后验证取消不提示成功且正常上传仍成功，不用延迟或大重构猜根因。
- “升级支付 SDK”：部署实际用 1.x 而锁文件是 2.x 时，先核验运行调用方与版本差异，不只改声明版本，不在正式环境执行交易探测。
- 交付分级对照：“改一处文案错别字”三项判据都不成立，就地修改并本地提交，不建工作树、不评审、不创建 MR；“给现有接口加一个可选参数”触碰公共契约，需要独立评审与 MR。

事实翻转对照、重复运行和真实安装后的反馈才能评估效果。上述样例是验收输入，不宣称单次模拟证明生产使用效果。

## 技能分工

- `adaptive-development-workflow`：常规开发的唯一根入口，默认直接执行或委派子代理，从请求选择下一步并按可逆性决定交付动作。
- [`requirements-discussion`](../skills/requirements-discussion/SKILL.md)：按需收敛需求与关键取舍，形成共识与未决点后交回现有流程，不默认产出规格文档。
- `code-and-contract-safety`：外部契约、死代码判定、正式环境禁写、评审独立性与证据独立性。
- [`delegation-and-isolation`](../skills/delegation-and-isolation/SKILL.md)：子代理委派、并行独立性判断与工作树隔离边界。
- [`development-team-composition`](../skills/development-team-composition/SKILL.md)：用户明确要求代理团队协作且运行时许可时的显式开团入口，覆盖组建到协作。团队职责、协作与工作区策略只由本技能、同目录协议和入口元数据承载，其他技能不介绍或引用团队入口；共用技能中的子代理职责只在该团队上下文由入口侧适配，不要求下游反向适配。它可引用通用质量与授权机制，但不以子代理委派技能作为团队策略权威。
- `finishing-a-development-branch`：提交、推送、MR/PR 与 CI 等待的交付边界。
- `documentation`：文档确为交付物时按读者问题维护。

## 已知限制

流程级别产出的是**合规指标**（有没有按级别执行），不等于**质量指标**（需求理解、契约核验、根因定位是否正确）。后者需要代表任务与预先确定的评价标准单独评估，本仓库尚未建立该评估集。静态结构检查不证明代理行为改进。
